# TMS 프로젝트 불균형 데이터 해결 방안 검토
## 1. 검토 결과 및 최종 권장 방향

TMS 프로젝트는 정상 데이터에 비해 이상 데이터의 비율이 매우 낮은 불균형 데이터 문제를 가지고 있습니다.

현재 데이터 기준으로 이상 데이터 비율은 약 1.36%이며, 정상 데이터와 이상 데이터의 비율은 약 72.8:1입니다.

따라서 단순히 이상 데이터를 인위적으로 늘리는 것보다 **원본 데이터의 특성을 최대한 유지하면서 이상 탐지 성능을 개선하는 방향**으로 접근하는 것이 좋습니다.

### 최종 권장 방향

| 우선순위 | 기법 | 적용 방향 |
|---|---|---|
| 1 | Cost-sensitive Learning | 클래스별 가중치를 적용하는 기본 모델 구축 |
| 2 | Random Under-sampling | 정상 데이터를 일부 축소하여 학습 효율 개선 |
| 3 | Random Over-sampling | 이상 데이터를 복제하여 학습 비중 조정 |
| 4 | SMOTE | 제한된 조건에서 합성 데이터의 효과 검증 |
| 5 | Borderline-SMOTE / ADASYN | 이상 경계 데이터에 대한 추가 실험 |
| 6 | One-class Classification | 정상 데이터 중심 학습 방식과 성능 비교 |
| 7 | Tomek Links / OSS | 데이터 축소 및 경계 정리 효과 검증 |
| 8 | GAN | 현재 프로젝트에서는 후순위 검토 |

**핵심은 Cost-sensitive Learning을 기준 모델로 설정하고, Under-sampling과 Over-sampling을 조합하여 성능을 비교하는 것입니다.**

## 2. TMS 프로젝트의 불균형 데이터 현황

### 2.1 데이터 현황

현재 TMS 분류 학습 데이터 기준입니다.

| 구분 | 데이터 건수 |
|---|---:|
| 전체 분류 학습 데이터 | 9,857,884 |
| 정상 데이터(0) | 9,724,168 |
| 이상 데이터(1) | 133,716 |
| 이상 데이터 비율 | 약 1.36% |
| 정상 : 이상 비율 | 약 72.8 : 1 |

정상 데이터가 이상 데이터보다 약 72.8배 많습니다.

이러한 데이터 구조에서는 모델이 대부분을 정상으로 예측하더라도 Accuracy가 높게 나올 수 있습니다.

### 2.2 Accuracy만으로 모델을 평가하면 안 되는 이유

예를 들어 다음과 같은 데이터가 있다고 가정하겠습니다.

- 정상 데이터: 10,000건
- 이상 데이터: 10건
- 모델이 이상 데이터를 5건만 탐지

이 경우 Accuracy는 약 99.95%이지만, 실제 이상 데이터 탐지율인 Recall은 50%입니다.

따라서 TMS 프로젝트에서는 Accuracy만으로 모델 성능을 판단해서는 안 됩니다.

### 2.3 주요 평가 지표

| 지표 | 의미 | TMS 적용 관점 |
|---|---|---|
| Precision | 이상이라고 예측한 데이터 중 실제 이상 비율 | 불필요한 경고를 얼마나 줄이는가 |
| Recall | 실제 이상 데이터 중 탐지한 비율 | 실제 이상을 얼마나 놓치지 않는가 |
| F2 Score | Recall에 더 높은 가중치를 둔 종합 지표 | 사전 경고에서 탐지율을 중요하게 평가 |
| PR-AUC | Precision과 Recall의 관계를 종합 평가 | 불균형 데이터에서 모델 비교 |
| FPR | 정상 데이터를 이상으로 잘못 판단한 비율 | 불필요한 경고 발생 수준 |
| Event-level Recall | 실제 이상 이벤트 중 탐지한 이벤트 비율 | 연속된 측정값이 아닌 실제 이상 발생 건 단위 평가 |
| Lead Time | 실제 이상 발생 전 얼마나 일찍 탐지했는가 | 사전 경고 시스템의 실효성 평가 |

특히 TMS는 실제 이상 발생 전에 경고하는 것이 중요하므로 Recall뿐 아니라 Lead Time도 함께 평가하는 것이 좋습니다.

## 3. 샘플링 기법별 TMS 적용 가능성

### 3.1 Cost-sensitive Learning

**가장 먼저 적용할 것을 권장하는 방법입니다.**

정상 데이터와 이상 데이터의 수가 다르더라도 데이터를 제거하거나 새로 생성하지 않고, 이상 데이터에 더 높은 가중치를 부여하여 학습하는 방식입니다.

예를 들어 XGBoost에서는 `scale_pos_weight`를 활용할 수 있습니다.

현재 데이터 기준 계산은 다음과 같습니다.

```python
scale_pos_weight = 정상 데이터 건수 / 이상 데이터 건수

scale_pos_weight = 9_724_168 / 133_716
# 약 72.8
```

72.8은 정상 데이터와 이상 데이터의 비율에서 계산한 초기 참고값입니다. 최적의 값이라는 의미는 아니므로 여러 가중치를 비교해야 합니다.

| 실험 | scale_pos_weight |
|---|---:|
| Baseline | 1 |
| 실험 1 | 5 |
| 실험 2 | 10 |
| 실험 3 | 20 |
| 실험 4 | 40 |
| 실험 5 | 72.8 |

**기대 효과**
- 원본 데이터 유지
- 이상 데이터에 대한 학습 비중 증가
- 데이터 전처리 과정 단순화

**주의 사항**
- 가중치를 높이면 Recall이 개선될 수 있지만 Precision이 낮아질 수 있습니다.
- FPR이 증가할 가능성도 있으므로 함께 확인해야 합니다.

### 3.2 Random Under-sampling

정상 데이터를 일부 제거하여 정상과 이상의 비율을 조정하는 방법입니다.

현재 약 972만 건의 정상 데이터가 있으므로 일부를 줄이더라도 충분한 학습 데이터를 확보할 수 있습니다.

| 정상 : 이상 비율 | 정상 데이터 목표 건수 | 전체 학습 데이터 |
|---|---:|---:|
| 20 : 1 | 2,674,320 | 약 280만 |
| 10 : 1 | 1,337,160 | 약 147만 |
| 5 : 1 | 668,580 | 약 80만 |
| 3 : 1 | 401,148 | 약 53만 |
| 1 : 1 | 133,716 | 약 27만 |

**권장 방향**

처음부터 1:1로 축소하기보다는 20:1, 10:1, 5:1을 중심으로 비교하는 것이 좋습니다.

정상 데이터에는 다양한 사업장, 배출구, 계절 및 시간대의 특성이 포함되어 있으므로 무작위로 제거할 때 특정 특성이 사라지지 않도록 주의해야 합니다.

가능하면 사업장, 배출구, 오염물질, 계절 등을 고려한 층화 샘플링을 적용하는 것이 좋습니다.

**기대 효과**
- 학습 데이터 크기 감소
- 학습 시간 단축
- 정상 데이터의 과도한 비중 완화

**주의 사항**
- 정상 데이터의 다양한 패턴이 사라질 수 있습니다.
- 데이터 축소로 인한 일반화 성능 저하 여부를 확인해야 합니다.

### 3.3 Random Over-sampling

이상 데이터를 복제하여 학습 데이터에서 차지하는 비중을 높이는 방법입니다.

예를 들어 이상 데이터 133,716건을 그대로 유지하면서 정상 데이터 대비 비율을 조정할 수 있습니다.

**기대 효과**
- 원본 데이터의 특성을 유지하면서 이상 데이터 학습 비중 증가
- 적용 방법이 단순함

**주의 사항**
- 새로운 이상 패턴을 생성하는 것은 아닙니다.
- 동일한 데이터가 반복되므로 과적합이 발생할 수 있습니다.
- 학습 데이터 크기가 증가합니다.

Under-sampling과 비교할 수 있는 기본 실험으로 활용하는 것이 좋습니다.

### 3.4 SMOTE

SMOTE는 기존 이상 데이터와 가까운 이웃 데이터 사이를 보간하여 새로운 합성 데이터를 생성하는 방법입니다.

예를 들어 이상 데이터가 다음과 같다고 가정하겠습니다.

- 기존 데이터 A: NOx 75
- 기존 데이터 B: NOx 85
- 합성 데이터: NOx 80

이처럼 기존 데이터 사이의 새로운 데이터를 만들어 이상 데이터 수를 늘립니다.

**TMS 적용 시 고려 사항**

TMS 데이터는 일반적인 수치 데이터와 달리 시간에 따른 변화와 설비별 특성이 중요합니다.

따라서 단순히 수치 사이를 보간하는 것만으로 실제 배출 패턴과 유사한 데이터가 생성된다고 보장할 수 없습니다.

다음 사항을 확인해야 합니다.

- NOx와 SO2의 물리적 범위 및 상관관계
- 사업장 및 배출구별 데이터 특성
- 시간에 따른 측정값 변화 패턴
- 합성 데이터의 실제 발생 가능성

특히 사업장 코드, 배출구 코드 등 식별자 성격의 컬럼을 일반 수치형 변수처럼 보간해서는 안 됩니다.

**권장 방향**

SMOTE는 기본 모델을 구축한 이후 제한된 데이터에서 효과를 검증하는 것이 좋습니다.

### 3.5 Borderline-SMOTE / ADASYN

두 기법 모두 이상 데이터 중에서도 분류 경계에 가까운 데이터를 중심으로 합성 데이터를 생성하는 방법입니다.

- Borderline-SMOTE: 정상 데이터와 이상 데이터의 경계에 있는 이상 데이터를 중심으로 생성
- ADASYN: 분류하기 어려운 데이터에 더 많은 합성 데이터를 생성

**TMS 적용 시 고려 사항**

경계에 있는 데이터가 실제 이상 발생의 초기 패턴일 수 있으므로 탐지 성능 개선 가능성이 있습니다.

다만 측정 노이즈나 잘못된 라벨까지 학습에 반영될 수 있으므로 신중하게 적용해야 합니다.

SMOTE를 먼저 검증한 후 추가 실험하는 것을 권장합니다.

### 3.6 Tomek Links / Edited Nearest Neighbors / NearMiss / OSS

이 기법들은 정상 데이터와 이상 데이터의 경계를 정리하거나 데이터 수를 줄이는 데 활용할 수 있습니다.

| 기법 | 주요 특징 | TMS 적용 의견 |
|---|---|---|
| Tomek Links | 서로 가까운 정상·이상 데이터 쌍을 찾아 경계 정리 | 축소 데이터에서 검증 |
| ENN | 주변 이웃과 다른 데이터 제거 | 경계 노이즈 제거 효과 검증 |
| NearMiss | 이상 데이터와 가까운 정상 데이터를 선택 | 정상 패턴 대표성 확인 필요 |
| OSS | Tomek Links와 CNN 등을 조합 | 대규모 데이터 적용 비용 고려 |

현재 TMS 데이터는 약 986만 건이므로 모든 데이터에 거리 기반 알고리즘을 적용하면 계산 비용이 커질 수 있습니다.

따라서 우선 Random Under-sampling으로 데이터를 축소한 뒤 추가 적용하는 것이 좋습니다.

### 3.7 One-class Classification

정상 데이터만 학습하고 정상 패턴에서 벗어나는 데이터를 이상으로 판단하는 방식입니다.

대표적인 방법은 다음과 같습니다.

- Isolation Forest
- One-Class SVM
- Autoencoder

**TMS 적용 가능성**

실제 이상 데이터의 라벨이 충분하지 않거나, 새로운 이상 패턴이 계속 발생하는 상황에서 대안으로 검토할 수 있습니다.

다만 정상 데이터의 다양성이 크면 정상 패턴을 벗어나는 데이터가 실제 이상이 아닐 수도 있습니다.

기존 지도학습 모델과 비교하는 보조 실험으로 활용하는 것이 좋습니다.

### 3.8 GAN 기반 합성 데이터 생성

GAN은 실제 데이터의 분포를 학습하여 새로운 데이터를 생성하는 방식입니다.

SMOTE보다 복잡한 패턴을 생성할 가능성이 있지만, 실제 데이터와 유사한 결과를 보장하지는 않습니다.

현재 프로젝트에서는 다음과 같은 이유로 우선순위를 낮추는 것이 좋습니다.

- 모델 개발 및 튜닝에 추가 시간이 필요함
- 생성 데이터의 품질 검증이 어려움
- 실제 TMS 데이터의 시간적 특성까지 반영해야 함

기본 모델의 성능 개선이 충분히 검증된 이후 검토하는 것을 권장합니다.

## 4. TMS 프로젝트에서 반드시 추가해야 할 검토 사항

### 4.1 시계열 데이터 분할

TMS는 30분 단위로 측정되는 시계열 데이터입니다.

따라서 일반적인 무작위 Train/Test 분할은 미래 데이터가 학습에 섞이는 데이터 누수 문제를 일으킬 수 있습니다.

시간 순서에 따라 데이터를 분리하는 것이 좋습니다.

예시:

| 구분 | 기간 |
|---|---|
| Train | 과거 24개월 |
| Validation | 이후 6개월 |
| Test | 가장 최근 6개월 |

실제 데이터 기간과 모델 검증 목적에 맞게 조정할 수 있습니다.

또한 동일한 이상 이벤트의 인접 시점 데이터가 서로 다른 데이터셋에 분산되지 않도록 시간 간격을 고려해야 합니다.

### 4.2 샘플링은 Train 데이터에만 적용

샘플링은 반드시 Train 데이터에만 적용해야 합니다.

| 데이터 | 샘플링 적용 |
|---|---|
| Train | 적용 가능 |
| Validation | 적용하지 않음 |
| Test | 적용하지 않음 |

Validation과 Test는 실제 운영 환경의 불균형 비율을 유지해야 합니다.

그래야 실제 운영 환경에서의 Precision, Recall, FPR을 객관적으로 평가할 수 있습니다.

### 4.3 시계열 Feature Engineering

샘플링만으로 성능을 개선하기보다 이상 발생 전의 변화 패턴을 잘 표현하는 Feature를 만드는 것이 중요합니다.

예를 들어 다음과 같은 변수를 검토할 수 있습니다.

| Feature | 설명 |
|---|---|
| current_value | 현재 측정값 |
| lag_1 | 직전 30분 측정값 |
| lag_2 | 직전 60분 측정값 |
| diff_30m | 직전 30분 대비 변화량 |
| diff_60m | 직전 60분 대비 변화량 |
| rolling_mean | 최근 구간 평균 |
| rolling_std | 최근 구간 변동성 |
| rolling_max | 최근 구간 최대값 |
| slope | 최근 구간 변화 추세 |

이러한 Feature를 활용하면 단순히 측정값이 높은지 여부뿐 아니라 이상 발생 전의 변화 패턴도 학습할 수 있습니다.

단, 예측 시점 이후의 데이터가 Feature에 포함되지 않도록 주의해야 합니다.

### 4.4 분류와 회귀 모델의 구분

TMS 프로젝트에서는 분류와 회귀를 구분해서 접근해야 합니다.

| 구분 | 목적 | 불균형 데이터 처리 |
|---|---|---|
| 분류 | 미래 이상 발생 가능성 예측 | Cost-sensitive, Under/Over-sampling |
| 회귀 | 미래 측정값 예측 | 일반적인 클래스 샘플링 적용 대상 아님 |

분류 모델은 이상 발생 여부를 예측하고, 회귀 모델은 미래 측정값 자체를 예측합니다.

따라서 분류 모델의 샘플링 전략을 회귀 모델에 그대로 적용해서는 안 됩니다.

---

## 5. 멘티에게 권장하는 실험 설계

여러 샘플링 기법을 한 번에 적용하기보다는 단계적으로 실험하는 것이 좋습니다.

### 5.1 단계별 실험

| 단계 | 실험 내용 | 목적 |
|---|---|---|
| 1 | 원본 데이터 + 기본 모델 | Baseline 성능 확보 |
| 2 | Cost-sensitive Learning | 클래스 가중치 효과 확인 |
| 3 | Random Under-sampling | 정상 데이터 축소 효과 확인 |
| 4 | Random Over-sampling | 이상 데이터 복제 효과 확인 |
| 5 | SMOTE | 합성 데이터 효과 확인 |
| 6 | Hybrid Sampling | Under + Over 조합 효과 확인 |
| 7 | 최종 모델 비교 | 운영 적합 모델 선정 |

### 5.2 비교 실험 기준

실험 결과는 다음과 같은 기준으로 비교하는 것이 좋습니다.

| 평가 항목 | 확인 목적 |
|---|---|
| Precision | 불필요한 경고가 얼마나 발생하는가 |
| Recall | 실제 이상을 얼마나 탐지하는가 |
| F2 Score | Recall을 중요하게 고려했을 때의 성능 |
| PR-AUC | 불균형 데이터에서 전반적인 분류 성능 |
| FPR | 정상 데이터를 이상으로 오판하는 비율 |
| Event-level Recall | 실제 이상 이벤트를 얼마나 탐지하는가 |
| Lead Time | 이상 발생 전에 얼마나 일찍 경고하는가 |
| 학습 시간 | 운영 및 재학습 비용 |
| 추론 시간 | 실시간 또는 배치 처리 가능 여부 |

특히 TMS는 이상을 놓치지 않는 것도 중요하지만, 지나치게 많은 오경보가 발생하면 운영자가 경고를 신뢰하지 않을 수 있습니다.

따라서 Recall만 높이는 방향이 아니라 Precision과 FPR을 함께 고려해야 합니다.

## 6. TMS 프로젝트 권장 아키텍처

불균형 데이터 처리는 모델 학습 파이프라인의 일부로 구성하는 것이 좋습니다.

```text
Bronze
  |
  v
Silver
  |
  v
Gold / ML-Ready Data
  |
  v
Train / Validation / Test 분리
  |
  +---------------------------+
  |                           |
  v                           v
원본 데이터 학습          샘플링 데이터 학습
  |                           |
  v                           v
Baseline Model           Sampling Model
  |                           |
  +-------------+-------------+
                |
                v
          모델 성능 비교
                |
                v
       최적 모델 및 Threshold 선정
                |
                v
          최종 모델 검증
                |
                v
         TMS 사전 경고 시스템
```

중요한 것은 샘플링 데이터를 별도로 관리하고, 실제 평가 데이터는 원본 분포를 유지하는 것입니다.

또한 운영 환경에서는 모델이 예측한 결과를 그대로 경고로 확정하기보다, 최종 판정 로직과 함께 활용하는 구조를 권장합니다.

## 7. 멘티에게 전달할 최종 멘토링 의견

현재 TMS 프로젝트는 정상 데이터와 이상 데이터의 비율이 약 72.8:1로 차이가 크기 때문에 불균형 데이터 처리 전략이 필요합니다.

다만 이상 데이터의 수를 무조건 늘리는 것이 정답은 아닙니다.

우선 원본 데이터 기반 Baseline을 확보하고, Cost-sensitive Learning을 적용하여 이상 데이터에 대한 학습 가중치를 조정해 보는 것이 좋겠습니다.

이후 Random Under-sampling과 Random Over-sampling을 비교하고, SMOTE는 실제 TMS 측정 데이터의 특성을 고려하여 제한적으로 검증하는 방향을 권장합니다.

특히 TMS는 시계열 데이터이므로 샘플링 기법뿐 아니라 이상 발생 전의 측정값 변화 패턴을 Feature로 잘 반영하는 것이 중요합니다.

**최종적으로는 이상 탐지율(Recall)을 높이면서도 불필요한 경고(FPR)를 적정 수준으로 유지하고, 실제 이상 발생 전에 충분한 시간을 확보할 수 있는 모델을 선정하는 것이 핵심입니다.**

## 8. 추가 멘토링 제안: 샘플링 이전에 이상 발생 패턴부터 분석

샘플링 기법을 적용하기 전에 현재 이상 데이터 133,716건이 어떤 패턴으로 발생하는지 먼저 분석하는 것을 권장합니다.

다음 항목을 확인하면 좋겠습니다.

1. NOx와 SO2의 이상 발생 패턴이 서로 다른가?
2. 특정 사업장이나 배출구에 이상 데이터가 집중되어 있는가?
3. 이상 발생 직전 30분 또는 60분 동안 측정값이 어떤 변화를 보이는가?
4. 이상 데이터가 단발성으로 발생하는가, 연속적으로 발생하는가?
5. 이상 데이터 중 측정 노이즈나 데이터 품질 문제로 의심되는 사례가 있는가?

이 분석 결과를 바탕으로 샘플링 전략을 결정해야 합니다.

예를 들어 특정 배출구에서만 이상 데이터가 집중된다면 단순한 무작위 샘플링보다 배출구별 특성을 고려한 샘플링이 더 적합할 수 있습니다.
