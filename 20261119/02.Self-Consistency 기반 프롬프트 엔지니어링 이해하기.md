# Self-Consistency 기반 프롬프트 엔지니어링 이해하기

## 1. 전체 개념 이해

LLM에게 같은 질문을 하더라도 매번 조금씩 다른 답변이 나올 수 있습니다.

특히 복잡한 질문은 분석 과정이나 판단 기준에 따라 답변이 달라질 수 있습니다.

이러한 문제를 보완하기 위해 **Self-Consistency** 기법을 활용할 수 있습니다.

한 번의 답변만 사용하는 대신 여러 개의 답변을 생성하고, 그중 가장 일관된 결과를 최종 답변으로 선택하는 방식입니다.

여기에 RAG를 결합하면 외부 문서를 참고하여 답변을 생성할 수 있습니다.

| 기술 | 핵심 역할 | 쉽게 이해하기 |
|---|---|---|
| RAG | 관련 자료 검색 | 답변에 필요한 자료 찾기 |
| Self-Consistency | 여러 답변 비교 및 선택 | 여러 답변 중 공통된 결과 찾기 |
| LCEL | 처리 기능 연결 | 여러 기능을 하나의 흐름으로 연결 |

전체 처리 과정은 다음과 같습니다.

```text
사용자 질문
    ↓
RAG : 질문과 관련된 문서 검색
    ↓
Prompt : 검색 문서와 질문을 LLM에 전달
    ↓
LLM : 여러 개의 답변 생성
    ↓
Self-Consistency : 답변 간 유사도 비교
    ↓
가장 일관된 답변 그룹 선택
    ↓
최종 답변
```

## 2. RAG (Retrieval-Augmented Generation)

### RAG란?

RAG는 LLM이 답변을 생성하기 전에 외부 자료를 검색하고, 검색된 내용을 참고하여 답변하도록 하는 기술입니다.

쉽게 말하면 **LLM에게 답변에 필요한 참고 자료를 먼저 찾아주는 방식**입니다.

### RAG가 필요한 이유

일반적인 LLM은 학습된 지식을 바탕으로 답변합니다.

하지만 다음과 같은 한계가 있습니다.

- 최신 정보가 반영되지 않을 수 있습니다.
- 사내 업무 문서나 내부 데이터는 알지 못합니다.
- 근거가 부족한 상황에서도 그럴듯한 답변을 생성할 수 있습니다.

RAG는 외부 문서를 검색하여 LLM에 제공함으로써 이러한 문제를 줄이는 데 도움을 줍니다.

### RAG 처리 과정

| 단계 | 처리 내용 |
|---|---|
| ① 문서 수집 | PDF, Word, 데이터베이스 등에서 자료 확보 |
| ② 문서 분할 | 검색하기 좋은 작은 단위로 분리 |
| ③ 임베딩 | 문서의 의미를 벡터로 변환 |
| ④ 검색 | 질문과 관련된 문서 검색 |
| ⑤ 답변 생성 | 검색된 문서를 참고하여 LLM이 답변 |

### 이번 실습의 RAG 예시

첨부 자료에서는 파리 관련 문서 3개를 사용합니다.

- 문서 1: 파리의 상징은 에펠탑이며, 1889년에 세워졌습니다.
- 문서 2: 파리는 세느강을 따라 발달했으며, 루브르 박물관이 유명합니다.
- 문서 3: 파리는 연간 약 2천만 명의 관광객이 방문하는 도시입니다.

사용자가 "파리의 상징은 무엇인가요?"라고 질문하면 관련 문서를 검색하여 LLM에 전달하는 구조입니다.

**핵심:** RAG는 LLM이 답변할 때 참고할 외부 정보를 제공하는 기술입니다.

※ 첨부 자료의 검색 함수는 실제 문서 유사도를 계산하지 않고 항상 정해진 문서를 반환합니다. 따라서 실제 검색 시스템이 아닌 RAG의 처리 과정을 설명하기 위한 모의 검색입니다.

## 3. Self-Consistency

### Self-Consistency란?

Self-Consistency는 하나의 질문에 대해 LLM이 여러 개의 답변을 생성하도록 한 다음, 답변 간 일관성을 비교하여 최종 결과를 선택하는 기법입니다.

쉽게 말하면 **한 사람에게 한 번만 답을 듣는 것이 아니라, 여러 번 답을 듣고 공통적으로 나오는 답을 선택하는 방식**입니다.

### 왜 필요한가?

LLM은 동일한 질문에도 표현이나 판단이 조금씩 달라질 수 있습니다.

예를 들어 다음 질문을 생각해 보겠습니다.

질문: "파리의 상징은 무엇인가요?"

LLM이 5개의 답변을 생성했다고 가정합니다.

| 생성 결과 | 답변 |
|---|---|
| 답변 1 | 파리의 상징은 에펠탑입니다. |
| 답변 2 | 에펠탑은 파리를 대표하는 상징물입니다. |
| 답변 3 | 파리를 대표하는 건축물은 에펠탑입니다. |
| 답변 4 | 루브르 박물관은 파리의 대표적인 명소입니다. |
| 답변 5 | 파리의 대표 상징물은 에펠탑입니다. |

이 중 1, 2, 3, 5번은 표현은 다르지만 의미가 비슷합니다.

Self-Consistency는 이러한 답변들을 비교하여 가장 많은 답변이 모인 그룹을 선택합니다.

<text>핵심은 문장이 완전히 같은지를 확인하는 것이 아니라, 답변의 의미가 얼마나 비슷한지를 비교하는 것입니다.</text>

### Self-Consistency 처리 과정

| 단계 | 처리 내용 |
|---|---|
| ① 질문 입력 | 사용자 질문 전달 |
| ② 다중 생성 | LLM이 동일한 질문에 대해 여러 답변 생성 |
| ③ 답변 추출 | 각 답변에서 최종 답변 부분 추출 |
| ④ 의미 비교 | 임베딩 벡터와 코사인 유사도로 답변 간 유사도 계산 |
| ⑤ 그룹화 | 유사한 답변끼리 하나의 그룹으로 분류 |
| ⑥ 최종 선택 | 가장 많은 답변이 속한 그룹의 대표 답변 선택 |

### 이번 실습의 핵심 구현 방식

첨부 자료에서는 다음과 같은 방법을 사용합니다.

- LLM이 한 질문에 대해 5개의 답변을 생성합니다.
- 각 답변을 임베딩하여 벡터로 변환합니다.
- 코사인 유사도를 이용해 답변 간 의미적 유사성을 비교합니다.
- 유사도 임계값을 기준으로 답변들을 그룹화합니다.
- 가장 많은 답변이 모인 그룹의 첫 번째 답변을 최종 결과로 선택합니다.

예를 들어 5개 답변 중 4개가 비슷한 의미라면 해당 그룹의 답변을 최종 결과로 선택합니다.

### Self-Consistency의 장점과 주의사항

| 구분 | 내용 |
|---|---|
| 장점 | 한 번의 생성에서 발생한 우연한 오류를 줄이는 데 도움 |
| 장점 | 여러 답변의 공통된 판단을 활용할 수 있음 |
| 단점 | 여러 번 생성하므로 API 비용과 처리 시간이 증가 |
| 단점 | 여러 답변이 모두 같은 오류를 낼 수도 있음 |
| 주의 | 다수의 답변이 항상 정답이라는 보장은 없음 |

**중요:** Self-Consistency는 정답을 검증하는 기술이 아니라, 여러 생성 결과 중 일관된 결과를 선택하는 기술입니다.

잘못된 문서를 참고하거나 잘못된 판단 기준을 사용하면 여러 답변이 동일하게 틀릴 수도 있습니다.

## 4. 난이도별 Self-Consistency 적용

첨부 자료에서는 질문의 난이도를 Easy, Medium, Hard 세 단계로 구분합니다.

난이도가 높아질수록 질문이 요구하는 정보와 판단의 복잡성이 증가합니다.

| 난이도 | 질문 유형 | 질문 예시 | 필요한 처리 |
|---|---|---|---|
| Easy | 단순 사실 확인 | 파리의 상징은 무엇인가요? | 필요한 정보 찾기 |
| Medium | 정보 비교 및 정리 | 파리의 주요 관광지 두 곳과 방문 시기는? | 여러 정보 통합 |
| Hard | 복합적인 분석 및 추천 | 파리의 역사와 관광지를 고려한 3일 여행 일정은? | 여러 조건 종합 및 추천 |

### Easy: 단순 정보 확인

- 질문에 필요한 정보를 문서에서 찾습니다.
- 여러 답변이 동일한 사실을 언급하는지 비교합니다.
- 가장 일관된 답변을 선택합니다.

### Medium: 여러 정보 통합

- 여러 문서에서 필요한 정보를 찾습니다.
- 관광지와 관련된 정보를 함께 정리합니다.
- 답변마다 공통적으로 제시하는 내용을 비교합니다.

### Hard: 복합적인 분석 및 추천

- 여러 문서의 정보를 종합합니다.
- 관광지, 역사, 방문 시기 등 여러 조건을 고려합니다.
- 여러 추천 결과에서 공통적으로 등장하는 내용을 비교합니다.

**주의할 점:** 첨부 자료의 파리 관련 문서에는 관광지와 방문객 수 등의 정보는 있지만, 역사적 배경이나 계절별 최적 방문 시기는 충분히 제공되지 않습니다. 따라서 Hard 단계의 여행 일정 추천은 문서만으로 정확성을 검증하기 어렵습니다.

이처럼 질문의 난이도가 높아질수록 검색 자료의 충분성과 정확성이 중요해집니다.

## 5. LCEL (LangChain Expression Language)

### LCEL이란?

LCEL은 LangChain에서 여러 기능을 연결하여 하나의 실행 파이프라인을 구성하는 표현 방식입니다.

쉽게 말하면 **검색, 프롬프트, LLM, 결과 처리 기능을 하나의 작업 흐름으로 연결하는 방법**입니다.

### LCEL의 기본 구조

```text
Retriever → Prompt → LLM → Output Parser
```

| 구성 요소 | 역할 |
|---|---|
| Retriever | 질문과 관련된 문서 검색 |
| Prompt | 질문과 검색 결과를 LLM 입력으로 구성 |
| LLM | 답변 생성 |
| Output Parser | 생성 결과를 원하는 형태로 변환 |

LCEL에서는 `|` 연산자를 사용해 기능을 순서대로 연결할 수 있습니다.

### Self-Consistency와 LCEL의 관계

Self-Consistency는 여러 답변을 생성하고 비교하는 처리 방식입니다.

LCEL은 이러한 처리 기능을 파이프라인으로 구성하는 데 사용할 수 있습니다.

예를 들어 다음과 같은 흐름으로 확장할 수 있습니다.

```text
질문 입력
   ↓
문서 검색
   ↓
프롬프트 구성
   ↓
LLM 다중 답변 생성
   ↓
답변 비교 및 그룹화
   ↓
최종 답변 선택
```

다만 첨부된 노트북은 LCEL의 개념을 소개하고 있지만, 실제 구현은 프롬프트 생성, LLM 호출, 파서 실행을 개별 함수로 순차 호출하는 방식입니다. 따라서 실제 LCEL 체인을 구현한 예제와는 구분해서 이해해야 합니다.

**핵심:** LCEL은 AI 처리 기능들을 연결하고 관리하기 위한 실행 구조입니다.

## 6. 최종 정리

이번 주제에서 반드시 이해해야 할 내용은 세 가지입니다.

| 기술 | 기억해야 할 한 문장 |
|---|---|
| RAG | LLM에게 답변에 필요한 자료를 찾아준다. |
| Self-Consistency | 여러 답변을 비교하여 가장 일관된 결과를 선택한다. |
| LCEL | 여러 AI 처리 기능을 하나의 실행 흐름으로 연결한다. |

### 강의 핵심 메시지

일반적인 LLM은 질문을 받고 한 번의 답변을 생성합니다.

RAG를 적용하면 외부 자료를 참고할 수 있고, Self-Consistency를 적용하면 여러 답변을 비교하여 일관된 결과를 선택할 수 있습니다.

그리고 LCEL을 활용하면 이러한 기능들을 하나의 파이프라인으로 구성할 수 있습니다.

**단순히 LLM에게 답변을 요청하는 것에서 벗어나, 필요한 정보를 검색하고 여러 결과를 비교하여 더 신뢰할 수 있는 답변을 만드는 것이 이번 학습의 핵심입니다.**
