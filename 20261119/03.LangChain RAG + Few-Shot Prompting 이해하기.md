# LangChain RAG + Few-Shot Prompting 이해하기

## 1. 전체 개념 이해하기

이번 내용은 크게 네 가지 기술을 이해하는 것이 목적입니다.

| 기술 | 역할 | 쉽게 이해하면 |
|---|---|---|
| RAG | 외부 자료 검색 | 답변에 필요한 참고 자료 찾기 |
| Few-Shot Prompting | 답변 예시 제공 | 원하는 답변 방식 보여주기 |
| Output Parser | 결과 구조화 | 답변을 정해진 형식으로 정리하기 |
| LCEL | 기능 연결 | 여러 기능을 하나의 실행 흐름으로 연결하기 |

전체 흐름은 다음과 같습니다.

```text
사용자 질문
    ↓
RAG: 관련 문서 검색
    ↓
Few-Shot: 질문과 답변 예시 제공
    ↓
LLM: 검색 자료와 예시를 참고해 답변 생성
    ↓
Output Parser: 결과를 정해진 형식으로 변환
    ↓
최종 결과
```

핵심은 **RAG로 답변에 필요한 정보를 확보하고, Few-Shot으로 원하는 답변 방식을 알려주는 것**입니다.

---

## 2. RAG란 무엇인가?

RAG(Retrieval-Augmented Generation)는 LLM이 답변을 생성하기 전에 외부 자료를 검색하고, 검색된 내용을 참고하도록 만드는 방식입니다.

일반적인 LLM은 학습 과정에서 습득한 지식을 바탕으로 답변합니다. 하지만 최신 정보나 특정 조직의 내부 자료처럼 모델이 알지 못하는 정보는 정확하게 답변하기 어렵습니다.

RAG는 이런 문제를 보완합니다.

### 예시

다음과 같은 관광지 정보를 가지고 있다고 가정하겠습니다.

| 도시 | 국가 | 연간 관광객 수 |
|---|---|---:|
| 파리 | 프랑스 | 약 3,000만 명 |
| 런던 | 영국 | 약 2,000만 명 |
| 교토 | 일본 | 약 1,500만 명 |

사용자가 다음과 같이 질문합니다.

> 교토는 어느 나라에 있으며, 연간 관광객은 얼마나 되나요?

RAG는 질문과 관련된 문서를 검색하여 LLM에 전달합니다.

LLM은 검색된 자료를 참고해 다음과 같이 답변할 수 있습니다.

> 교토는 일본에 있으며, 연간 관광객은 약 1,500만 명입니다.

### RAG의 처리 과정

1. 사용자가 질문합니다.
2. 질문과 관련된 문서를 검색합니다.
3. 검색된 문서를 LLM에 전달합니다.
4. LLM이 문서 내용을 참고해 답변합니다.

**중요한 점**

RAG는 LLM을 다시 학습시키는 기술이 아닙니다. 외부 자료를 검색해 답변에 필요한 정보를 제공하는 기술입니다.

실제 서비스에서는 검색 결과가 정확한지, 최신 정보인지, 질문과 관련이 있는지도 함께 관리해야 합니다.

## 3. Few-Shot Prompting이란?

Few-Shot Prompting은 LLM에게 몇 가지 질문과 답변 예시를 미리 보여주고, 새로운 질문에도 비슷한 방식으로 답변하도록 유도하는 기법입니다.

쉽게 말하면 **정답을 알려주는 것이 아니라, 답변하는 방법을 예시로 보여주는 것**입니다.

### 일반적인 프롬프트와 Few-Shot 비교

**일반적인 프롬프트**

```text
질문: 파리는 어느 나라에 있나요?

답변:
```

**Few-Shot Prompting**

```text
다음 예시와 같은 방식으로 답변하세요.

질문: 파리는 어느 나라에 있나요?
답변: 프랑스

질문: 런던은 어느 나라에 있나요?
답변: 영국

질문: 교토는 어느 나라에 있나요?
답변:
```

Few-Shot을 사용하면 모델은 앞에 제시된 예시를 참고하여 다음 질문에도 동일한 형식으로 답변하려고 합니다.

### Few-Shot의 장점

- 원하는 답변 형식을 쉽게 유도할 수 있습니다.
- 복잡한 설명 없이도 답변 패턴을 전달할 수 있습니다.
- 특정 업무의 응답 방식이나 분류 기준을 예시로 제시할 수 있습니다.
- 모델을 다시 학습시키지 않고 프롬프트만으로 응답 방식을 조정할 수 있습니다.

### Fine-tuning과의 차이

| 구분 | Few-Shot Prompting | Fine-tuning |
|---|---|---|
| 방식 | 프롬프트에 예시 제공 | 모델 추가 학습 |
| 모델 변경 | 없음 | 모델 파라미터 변경 |
| 적용 | 빠르게 적용 가능 | 학습 데이터와 학습 과정 필요 |
| 목적 | 답변 방식과 패턴 유도 | 모델의 동작이나 특정 작업 성능 조정 |

Few-Shot은 예시를 프롬프트에 넣는 것이므로 모델 자체가 새로운 지식을 학습하는 것은 아닙니다.

## 4. 질문 난이도에 따른 Few-Shot 적용

이번 실습은 질문의 난이도에 따라 답변 방식을 다르게 적용하는 구조입니다.

### 4.1 Easy: 단순 정보 조회

질문에 해당하는 정보를 찾아 간단하게 답변하는 단계입니다.

**예시**

```text
질문: 파리는 어느 나라에 있나요?
답변: 프랑스

질문: 런던은 어느 나라에 있나요?
답변: 영국

질문: 교토는 어느 나라에 있나요?
답변: 일본
```

**핵심**

- 질문과 답변의 관계가 단순합니다.
- 답변 형식이 짧고 명확합니다.
- Few-Shot 예시를 통해 응답 패턴을 쉽게 전달할 수 있습니다.

### 4.2 Medium: 여러 정보의 구조화

단순한 문장 대신 여러 정보를 정해진 JSON 형식으로 반환하는 단계입니다.

**예시**

질문:

> 각 도시의 연간 관광객 수를 알려주세요.

원하는 출력 형식:

```json
[
  {
    "city": "파리",
    "visitors": "약 3,000만 명"
  },
  {
    "city": "런던",
    "visitors": "약 2,000만 명"
  }
]
```

이때 Few-Shot 예시로 JSON 출력 형태를 미리 보여주면 모델이 원하는 구조로 답변하도록 유도할 수 있습니다.

**핵심**

- 여러 정보를 하나의 결과로 정리합니다.
- JSON과 같은 구조화된 형식을 사용합니다.
- 후속 프로그램에서 결과를 처리하기 쉬워집니다.

### 4.3 Hard: 조건에 따른 판단과 예외 처리

단순히 정보를 조회하는 것이 아니라, 자료의 존재 여부를 확인하고 조건에 따라 결과를 다르게 반환하는 단계입니다.

**예시**

질문:

> 교토의 연간 관광객 증가율은 얼마인가요?

검색된 자료에 증가율 정보가 없다면 다음과 같이 반환하도록 지시할 수 있습니다.

```json
[]
```

**핵심**

- 검색 자료에 해당 정보가 있는지 확인합니다.
- 근거가 없는 정보는 임의로 생성하지 않도록 합니다.
- 정보가 없을 때의 처리 방식도 프롬프트에 정의합니다.

다만 Few-Shot 예시 자체에 실제 근거가 없는 수치를 넣으면 모델이 이를 사실로 받아들일 수 있습니다. 예시 데이터와 실제 검색 자료를 명확하게 구분해야 합니다.

## 5. Output Parser란?

Output Parser는 LLM이 생성한 결과를 프로그램에서 사용하기 쉬운 형태로 변환하는 기능입니다.

LLM은 기본적으로 자연어를 생성합니다. 하지만 실제 서비스에서는 JSON, 숫자, 특정 필드 등 정해진 형태의 결과가 필요할 수 있습니다.

예를 들어 다음과 같은 결과가 있다고 가정하겠습니다.

```text
도시는 교토이고 관광객 수는 약 1,500만 명입니다.
```

이 결과를 프로그램에서 사용하려면 다음과 같은 JSON 형태로 변환할 수 있습니다.

```json
{
  "city": "교토",
  "visitors": "약 1,500만 명"
}
```

### 기존 방식: RegexParser

기존 실습에서는 정규표현식을 사용해 LLM 응답에서 특정 문자열을 추출했습니다.

예를 들어 `[...]` 형태의 JSON 배열 부분을 찾아내는 방식입니다.

이 방법은 간단한 실습에는 유용하지만 다음과 같은 한계가 있습니다.

- 모델이 출력 형식을 조금만 바꿔도 추출에 실패할 수 있습니다.
- JSON 내부에 중첩된 구조가 있으면 정규표현식만으로 처리하기 어렵습니다.
- 결과가 JSON 형태라고 해도 필수 필드나 데이터 타입이 올바른지는 별도로 확인해야 합니다.

### 최신 권장 방식: 구조화 출력

최신 LangChain에서는 Pydantic 모델을 이용해 출력 구조를 정의하고, 모델의 `with_structured_output()` 기능으로 해당 구조에 맞는 결과를 생성하도록 하는 방식을 권장합니다.

예를 들어 다음과 같은 구조를 정의할 수 있습니다.

```python
from pydantic import BaseModel, Field

class CityInfo(BaseModel):
    city: str = Field(description="도시 이름")
    visitors: str = Field(description="연간 관광객 수")
```

모델에 구조화 출력을 적용하면 다음과 같이 사용할 수 있습니다.

```python
structured_model = llm.with_structured_output(CityInfo)

result = structured_model.invoke(
    "교토의 관광객 정보를 정리해 주세요."
)
```

이 방식은 단순히 문자열을 추출하는 것보다 결과의 구조와 데이터 타입을 명확하게 관리하기 쉽습니다.

단, **구조가 올바르다는 것과 데이터의 사실 여부가 정확하다는 것은 별개**입니다. 검색 근거와 수치의 정확성은 별도로 검증해야 합니다.

## 6. LCEL이란?

LCEL(LangChain Expression Language)은 LangChain의 여러 기능을 하나의 실행 흐름으로 연결하는 표현 방식입니다.

쉽게 말하면 각각의 기능을 조립해 하나의 파이프라인을 만드는 방법입니다.

### 기본 구조

```text
Prompt → LLM → Output Parser
```

각 기능은 다음과 같은 역할을 합니다.

| 구성 요소 | 역할 |
|---|---|
| Prompt | LLM에 전달할 질문과 지침 구성 |
| LLM | 프롬프트를 바탕으로 답변 생성 |
| Output Parser | 답변을 원하는 형식으로 변환 |

LCEL에서는 `|` 연산자를 사용해 기능을 연결합니다.

```python
chain = prompt | llm | parser

result = chain.invoke({
    "question": "교토는 어느 나라에 있나요?"
})
```

위 코드는 다음 순서로 실행됩니다.

1. Prompt가 입력값을 받아 프롬프트를 구성합니다.
2. LLM이 프롬프트를 전달받아 답변을 생성합니다.
3. Output Parser가 결과를 원하는 형식으로 변환합니다.

LCEL로 구성한 Runnable은 `invoke()` 외에도 비동기 실행, 스트리밍, 배치 실행 등을 지원합니다.

## 7. LangChain 최신 버전 기준 구현 구조

기존 실습의 개념을 유지하면서 최신 패키지 구조에 맞추면 다음과 같이 구성할 수 있습니다.

### 7.1 설치 패키지

```bash
pip install -U langchain langchain-core langchain-openai pydantic
```

실제 RAG 검색을 구현할 때는 사용하는 벡터 데이터베이스나 문서 저장소에 맞는 통합 패키지도 추가해야 합니다.

### 7.2 주요 Import

```python
from langchain_core.prompts import (
    PromptTemplate,
    FewShotPromptTemplate
)

from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI
```

기존 실습에서 사용한 `langchain.prompts` 대신 핵심 프롬프트 기능은 `langchain_core.prompts`에서 가져옵니다.

문서 객체를 직접 사용한다면 다음 경로를 사용합니다.

```python
from langchain_core.documents import Document
```

### 7.3 Few-Shot Prompt와 LCEL 연결

```python
examples = [
    {
        "question": "파리는 어느 나라에 있나요?",
        "answer": "프랑스"
    },
    {
        "question": "런던은 어느 나라에 있나요?",
        "answer": "영국"
    }
]

example_prompt = PromptTemplate.from_template(
    "질문: {question}\n답변: {answer}"
)

prompt = FewShotPromptTemplate(
    examples=examples,
    example_prompt=example_prompt,
    prefix="다음 예시와 같은 방식으로 답변하세요.",
    suffix="질문: {question}\n답변:",
    input_variables=["question"]
)

llm = ChatOpenAI(
    model="사용 가능한 모델명",
    temperature=0
)

parser = StrOutputParser()

chain = prompt | llm | parser

result = chain.invoke({
    "question": "교토는 어느 나라에 있나요?"
})

print(result)
```

위 코드는 Few-Shot Prompting과 LCEL의 연결 구조를 보여주는 예시입니다.

실제 실행을 위해서는 OpenAI API 키와 해당 API에서 사용할 수 있는 모델명을 설정해야 합니다.

또한 이 예제는 Few-Shot Prompting을 설명하기 위한 코드이며, 실제 문서를 검색하는 RAG Retriever는 포함하지 않았습니다.

## 8. 기존 실습에서 개선해야 할 부분

| 기존 구현 | 개선 방향 | 이유 |
|---|---|---|
| `langchain.prompts` 사용 | `langchain_core.prompts` 사용 | 최신 패키지 구조 반영 |
| `langchain.schema.Document` | `langchain_core.documents.Document` | 문서 객체의 최신 Import 경로 |
| RegexParser로 JSON 추출 | Pydantic 구조화 출력 우선 | 출력 형식과 데이터 타입 검증에 유리 |
| 하드코딩된 문서 3개 | 실제 Retriever 연결 | 실제 RAG 검색 과정 구현 |
| Few-Shot 예시의 수치를 사실처럼 사용 | 예시와 검색 근거 구분 | 잘못된 정보 생성 방지 |
| 출력 JSON만 확인 | 필드·타입·값 검증 | 구조와 사실의 정확성을 별도로 관리 |

참고로 LangChain v1에서는 기존 Retriever, 일부 체인 등 레거시 기능이 `langchain-classic`으로 이동했습니다. 따라서 과거 실습 코드의 Import 경로를 그대로 사용하기보다는 현재 사용 중인 패키지 버전에 맞춰 확인하는 것이 좋습니다.

## 9. 멘티가 반드시 이해해야 할 핵심

이번 내용을 다음 네 가지로 정리하면 됩니다.

| 구분 | 핵심 질문 | 답변 |
|---|---|---|
| RAG | 어디서 정보를 가져올 것인가? | 외부 문서 검색 |
| Few-Shot | 어떤 방식으로 답변할 것인가? | 질문과 답변 예시 제공 |
| Output Parser | 결과를 어떤 형태로 사용할 것인가? | JSON 등 구조화 |
| LCEL | 기능을 어떻게 연결할 것인가? | Runnable 파이프라인 구성 |

### 최종 정리

RAG와 Few-Shot은 서로 다른 문제를 해결합니다.

- RAG는 **답변에 필요한 정보**를 제공합니다.
- Few-Shot은 **답변을 만드는 방식**을 알려줍니다.
- Output Parser는 **결과를 프로그램에서 사용할 수 있는 형태**로 정리합니다.
- LCEL은 이 기능들을 **하나의 실행 흐름으로 연결**합니다.

실제 AI 서비스를 개발할 때는 이 네 가지를 함께 활용할 수 있습니다.

다만 검색된 정보가 정확한지, 모델이 근거 없는 내용을 생성하지 않았는지, 결과의 구조가 올바른지는 별도로 검증해야 합니다.
