# TMS 분류 모델의 클래스 불균형 해소 방법

## 1. 데이터 분할 및 데이터 누수 방지

클래스 불균형을 해소하기 전에 먼저 Train, Validation, Test 데이터를 분리해야 한다.

특히 TMS 데이터는 30분 단위로 수집되는 시계열 데이터이므로 일반적인 무작위 분할(Random Split)을 적용하면 데이터 누수가 발생할 수 있다.

### 1.1 데이터 분할 방법

시계열 데이터는 과거 데이터를 학습에 사용하고 미래 데이터를 검증 및 테스트에 사용하는 방식으로 분리한다.

예를 들어 대만 CEMS 데이터 36개월을 사용한다면 다음과 같이 분리할 수 있다.

| 구분 | 데이터 기간 | 비율 | 용도 |
|---|---|---:|---|
| Train | 초기 27개월 | 75% | 모델 학습 |
| Validation | 다음 4.5개월 | 12.5% | 모델 및 파라미터 조정 |
| Test | 마지막 4.5개월 | 12.5% | 최종 성능 평가 |

실제 데이터의 기간과 위험 발생 분포를 확인한 후 최종 분할 기간을 결정한다.

**데이터 분할 시 주의사항**

- Train은 과거 데이터, Validation은 그 이후 데이터, Test는 가장 최근 데이터로 구성한다.
- 동일한 `stack_code + item_code`의 시간 흐름이 유지되도록 한다.
- Train과 Validation, Validation과 Test 경계에서 미래 Label이 다음 구간을 참조하지 않도록 처리한다.
- 분할 후 각 데이터의 양성·음성 비율을 별도로 집계한다.

### 1.2 데이터 누수(Data Leakage)란?

데이터 누수는 모델 학습 과정에서 실제 예측 시점에는 알 수 없는 정보가 학습 데이터에 포함되는 문제다.

TMS 프로젝트에서는 특히 미래 측정값이 Feature에 포함되지 않도록 주의해야 한다.

예를 들어 현재 시점 T에서 향후 60분의 배출비율을 예측하는데, T+30분 또는 T+60분의 측정값이 입력 Feature에 포함되면 안 된다.

| 구분 | 사용 데이터 | 사용 목적 |
|---|---|---|
| 현재 시점 T | 현재 측정값 및 과거 측정값 | 모델 입력 Feature |
| T+30분 | 미래 측정값 | 분류 Label 생성 |
| T+60분 | 미래 측정값 | 분류 및 회귀 Label 생성 |

미래 측정값은 정답(Label)을 생성하는 데만 사용하고 모델 입력 Feature에는 포함하지 않는다.

### 1.3 불균형 조정 시 데이터 누수 방지

Undersampling, Oversampling, SMOTE와 같은 기법은 반드시 Train 데이터에만 적용해야 한다.

잘못된 처리 방식은 다음과 같다.

```python
# 잘못된 예시
# 전체 데이터를 먼저 오버샘플링한 후 분할
X_resampled, y_resampled = smote.fit_resample(X, y)

X_train, X_test, y_train, y_test = train_test_split(
    X_resampled,
    y_resampled,
    test_size=0.2
)
```

이렇게 하면 동일하거나 유사한 데이터가 Train과 Test에 동시에 포함될 수 있어 실제보다 성능이 높게 측정될 수 있다.

올바른 처리 방식은 다음과 같다.

```python
# 1. 시간 기준으로 먼저 데이터 분할
X_train, y_train = ...
X_valid, y_valid = ...
X_test, y_test = ...

# 2. Train 데이터에만 SMOTE 적용
X_train_resampled, y_train_resampled = smote.fit_resample(
    X_train,
    y_train
)

# 3. Validation과 Test는 원본 데이터 유지
model.fit(X_train_resampled, y_train_resampled)

# 4. 원래 데이터 분포를 유지한 Validation 평가
y_pred = model.predict(X_valid)
```

**반드시 지켜야 할 원칙**

1. Train, Validation, Test를 먼저 시간 기준으로 분리한다.
2. Undersampling, Oversampling, SMOTE는 Train에만 적용한다.
3. Validation과 Test는 원래 클래스 분포를 유지한다.
4. Scaling이 필요한 경우에도 Scaler는 Train 데이터로만 Fit한다.
5. Validation으로 모델과 Threshold를 선택하고 Test는 최종 평가에 사용한다.

### 1.4 시계열 데이터의 추가 주의사항

TMS 데이터는 같은 굴뚝과 물질에서 연속적으로 측정되므로 인접한 데이터끼리 유사한 특성을 가질 수 있다.

따라서 다음 사항도 확인해야 한다.

- `stack_code + item_code` 기준으로 시계열을 구분한다.
- 측정 시각 기준으로 정렬한다.
- 30분 간격이 누락된 구간을 임의로 연결하지 않는다.
- Label 생성 시 T+30분 또는 T+60분 데이터가 분할 경계를 넘어가는 행은 정책에 따라 제외한다.
- LSTM Sequence가 Train과 Test 경계를 넘어서 생성되지 않도록 한다.

## 2. 클래스 불균형이란?

클래스 불균형(Class Imbalance)은 분류 모델에서 특정 클래스의 데이터가 다른 클래스보다 지나치게 많은 상태를 의미한다.

현재 TMS 프로젝트는 향후 60분 이내에 배출비율이 90% 이상으로 진입하는지를 예측하는 분류 모델을 개발하고 있다.

분류 Label은 다음과 같이 구분한다.

| Label | 의미 |
|---|---|
| 1 (양성) | 향후 60분 이내 배출비율이 90% 이상으로 진입 |
| 0 (음성) | T+30분과 T+60분 모두 유효하고 90% 미만 |
| NULL | 현재 상태 또는 미래 위험 진입 여부를 판단할 수 없음 |

### 2.1 현재 데이터 현황

| 구분 | NOx | SO₂ | 전체 |
|---|---:|---:|---:|
| 양성(1) | 106,931 | 26,785 | 133,716 |
| 음성(0) | 5,370,463 | 4,353,705 | 9,724,168 |
| 전체 | 5,477,394 | 4,380,490 | 9,857,884 |
| 양성 비율 | 1.95% | 0.61% | 1.36% |

전체 분류 데이터 약 986만 건 중 위험 진입 데이터는 약 13만 건으로 양성 비율이 약 1.36%에 불과하다.

즉, 정상 데이터가 위험 데이터보다 약 73배 많다.

### 2.2 클래스 불균형이 발생하면 어떤 문제가 있는가?

모델은 학습 데이터에서 자주 등장하는 패턴을 중심으로 학습하는 경향이 있다.

현재 데이터처럼 정상 데이터가 대부분이면 모델이 위험 진입 패턴을 충분히 학습하지 못할 수 있다.

모든 데이터를 정상(0)으로 예측하는 모델을 가정해 보자.

- 전체 데이터: 9,857,884건
- 정상 데이터: 9,724,168건
- 위험 데이터: 133,716건

이 모델의 정확도는 약 98.64%이다.

그러나 실제 위험 데이터 133,716건을 하나도 찾아내지 못한다.

따라서 클래스 불균형이 큰 데이터에서는 Accuracy만으로 모델 성능을 판단하면 안 된다.

## 3. 클래스 불균형 해소 방법

클래스 불균형은 크게 세 가지 접근 방법으로 대응할 수 있다.

| 구분 | 접근 방법 | 주요 기법 |
|---|---|---|
| 데이터 수 조정 | 양성 또는 음성 데이터 수 변경 | Undersampling, Oversampling, SMOTE |
| 학습 가중치 조정 | 양성 데이터의 오분류에 더 큰 페널티 부여 | Class Weight, Scale Pos Weight, Weighted Loss |
| 예측 기준 조정 | 위험으로 판단하는 확률 기준 변경 | Threshold Tuning |

각 방법은 적용 방식과 장단점이 다르므로 모델과 데이터 특성에 맞게 선택해야 한다.

## 4. 데이터 수 조정 방법

### 4.1 Undersampling (언더샘플링)

**개념**

음성 데이터가 지나치게 많기 때문에 음성 데이터 일부를 선택하여 학습에 사용하는 방법이다.

현재 데이터는 다음과 같다.

- 양성: 133,716건
- 음성: 9,724,168건

음성 데이터를 양성 데이터의 5배 수준으로 줄인다고 가정하면 다음과 같다.

| 구분 | 기존 데이터 | 언더샘플링 후 |
|---|---:|---:|
| 양성 | 133,716 | 133,716 |
| 음성 | 9,724,168 | 668,580 |
| 전체 | 9,857,884 | 802,296 |
| 양성 비율 | 1.36% | 16.67% |

기존에는 음성 데이터가 양성 데이터보다 약 73배 많았지만, 언더샘플링 후에는 약 5배로 줄어든다.

**Python 구현 예시**

```python
from sklearn.utils import resample
import pandas as pd

positive = train_df[train_df["label_entry_60m"] == 1]
negative = train_df[train_df["label_entry_60m"] == 0]

negative_sampled = resample(
    negative,
    replace=False,
    n_samples=len(positive) * 5,
    random_state=42
)

train_balanced = pd.concat([
    positive,
    negative_sampled
]).sample(frac=1, random_state=42)

print(train_balanced["label_entry_60m"].value_counts())
```

**장점**
- 학습 데이터가 줄어들어 학습 시간과 메모리 사용량을 줄일 수 있다.
- 양성 데이터의 상대적인 학습 비중이 높아진다.
- 구현이 간단하다.

**단점**
- 정상 데이터 중 유용한 패턴이 삭제될 수 있다.
- 정상 상태의 다양한 변화 패턴을 충분히 학습하지 못할 수 있다.
- 어떤 음성 데이터를 선택하느냐에 따라 모델 성능이 달라질 수 있다.

**TMS 적용 시 고려사항**

TMS 데이터는 정상 상태에서도 배출비율이 서서히 상승하거나 급격하게 변하는 등 다양한 패턴이 중요하다.

따라서 음성 데이터를 무작정 줄이면 정상 상태의 중요한 패턴을 잃을 수 있다.

전체 음성 데이터를 사용하는 모델을 기준으로 두고, 1:5 또는 1:10 비율로 샘플링한 모델과 성능을 비교하는 것이 좋다.

### 4.2 Oversampling (오버샘플링)

**개념**

양성 데이터가 부족하므로 기존 양성 데이터를 복제하여 학습 데이터에서 차지하는 비중을 높이는 방법이다.

양성 데이터의 수를 음성 데이터의 1/5 수준으로 늘린다고 가정하면 다음과 같다.

| 구분 | 기존 데이터 | 오버샘플링 후 |
|---|---:|---:|
| 양성 | 133,716 | 1,944,834 |
| 음성 | 9,724,168 | 9,724,168 |
| 전체 | 9,857,884 | 11,669,002 |
| 양성 비율 | 1.36% | 약 16.67% |

기존 양성 데이터를 단순 복제하는 방식이므로 새로운 위험 상황을 만들어 내는 것은 아니다.

**Python 구현 예시**

```python
from sklearn.utils import resample
import pandas as pd

positive = train_df[train_df["label_entry_60m"] == 1]
negative = train_df[train_df["label_entry_60m"] == 0]

positive_oversampled = resample(
    positive,
    replace=True,
    n_samples=len(negative) // 5,
    random_state=42
)

train_balanced = pd.concat([
    negative,
    positive_oversampled
]).sample(frac=1, random_state=42)
```

**장점**
- 기존 양성 데이터를 삭제하지 않는다.
- 양성 데이터의 학습 비중을 높일 수 있다.
- 구현이 간단하다.

**단점**
- 동일한 데이터가 반복되므로 과적합이 발생할 수 있다.
- 새로운 위험 상황의 특징을 만들어 내지는 못한다.
- 학습 데이터가 증가하여 학습 시간이 길어질 수 있다.

**TMS 적용 시 고려사항**

양성 데이터가 약 13만 건이므로 단순 복제 방식의 오버샘플링을 시도할 수 있다.

다만 동일한 위험 이벤트에서 생성된 여러 행이 반복 학습될 수 있으므로 위험 이벤트 단위로 중복 여부를 확인하는 것이 좋다.

### 4.3 SMOTE (Synthetic Minority Over-sampling Technique)

**개념**

SMOTE는 기존 양성 데이터를 단순 복제하는 대신, 비슷한 특성을 가진 양성 데이터 사이에 새로운 합성 데이터를 생성하는 방법이다.

예를 들어 다음 두 양성 데이터가 있다고 가정한다.

| Feature | 양성 데이터 A | 양성 데이터 B |
|---|---:|---:|
| 현재 배출비율 | 80% | 84% |
| 30분 전 배출비율 | 75% | 79% |
| 60분 전 배출비율 | 72% | 76% |

SMOTE는 두 데이터의 특성을 참고하여 중간에 해당하는 새로운 데이터를 생성할 수 있다.

\[
X_{new}=X_A+\lambda(X_B-X_A)
\]

여기서 \(\lambda\)는 0과 1 사이의 임의의 값이다.

**Python 구현 예시**

```python
from imblearn.over_sampling import SMOTE

X_train = train_df[feature_columns]
y_train = train_df["label_entry_60m"]

smote = SMOTE(
    sampling_strategy=0.2,
    random_state=42
)

X_resampled, y_resampled = smote.fit_resample(
    X_train,
    y_train
)

print(y_resampled.value_counts())
```

`sampling_strategy=0.2`는 오버샘플링 후 양성 데이터 수를 음성 데이터 수의 20% 수준으로 맞추겠다는 의미다.

**장점**
- 단순 복제가 아니라 새로운 Feature 조합을 생성한다.
- 양성 데이터가 부족한 문제를 완화할 수 있다.
- 일부 데이터에서는 모델의 일반화 성능을 개선할 수 있다.

**단점**
- 실제로 존재하지 않는 측정 패턴이 생성될 수 있다.
- 서로 다른 설비나 배출물질의 특성이 섞일 수 있다.
- 시계열 데이터의 시간적 연속성을 보장하지 않는다.
- 부적절한 합성 데이터가 생성되면 오히려 모델 성능이 떨어질 수 있다.

**TMS 적용 시 고려사항**

TMS 데이터는 시간에 따른 변화가 중요하다.

배출비율이 80%에서 85%, 90%로 상승하는 과정에는 시간적 순서와 변화 추세가 있다.

SMOTE로 Feature를 독립적으로 보간하면 실제 시간 흐름에서 발생하기 어려운 Feature 조합이 만들어질 수 있다.

따라서 SMOTE는 기본 적용 방법으로 선택하기보다는 Random Forest와 XGBoost에서 다른 불균형 대응 방법을 먼저 비교한 후 추가 실험하는 것이 좋다.

## 5. 학습 가중치 조정 방법

데이터 수 자체를 변경하지 않고 모델이 양성 데이터를 더 중요하게 학습하도록 만드는 방법이다.

현재 TMS 데이터처럼 정상 패턴도 충분히 학습해야 하는 경우 우선 검토할 만하다.

### 5.1 Class Weight (클래스 가중치)

**개념**

모델이 데이터를 학습할 때 양성 데이터의 오분류에 더 큰 페널티를 부여하는 방법이다.

일반적인 학습에서는 양성 1건과 음성 1건의 오분류를 동일한 비중으로 처리한다.

Class Weight를 적용하면 양성 데이터의 오분류에 더 큰 가중치를 부여한다.

현재 전체 데이터 기준 음성/양성 비율은 약 73:1이므로 다음과 같은 가중치를 초기 실험값으로 사용할 수 있다.

| 클래스 | 데이터 수 | 가중치 예시 |
|---|---:|---:|
| 음성(0) | 9,724,168 | 1 |
| 양성(1) | 133,716 | 73 |

이는 양성 데이터 한 건의 오분류 손실을 음성 데이터 한 건보다 약 73배 중요하게 취급하는 설정이다.

**Random Forest 적용 예시**

```python
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(
    n_estimators=200,
    max_depth=15,
    class_weight="balanced",
    random_state=42,
    n_jobs=-1
)

model.fit(X_train, y_train)
```

`class_weight="balanced"`는 클래스별 데이터 수에 반비례하도록 가중치를 자동 계산한다.

가중치를 직접 지정할 수도 있다.

```python
model = RandomForestClassifier(
    n_estimators=200,
    class_weight={
        0: 1,
        1: 73
    },
    random_state=42,
    n_jobs=-1
)
```

NOx와 SO₂를 별도로 학습한다면 각각의 양성 비율에 맞춰 가중치를 다르게 설정할 수 있다.

- NOx: 약 50
- SO₂: 약 163

**장점**
- 원본 데이터 수를 변경하지 않는다.
- 정상 데이터의 다양한 패턴을 유지할 수 있다.
- 구현이 간단하다.

**단점**
- 양성 가중치를 너무 높이면 정상 데이터를 위험으로 잘못 판단하는 오경보가 증가할 수 있다.
- 가중치가 높다고 반드시 Recall이 개선되는 것은 아니다.
- 최적 가중치는 Validation 결과를 통해 결정해야 한다.

### 5.2 XGBoost의 Scale Pos Weight

**개념**

XGBoost에서는 `scale_pos_weight`라는 파라미터로 양성 데이터의 가중치를 조정할 수 있다.

기본 계산식은 다음과 같다.

\[
scale\_pos\_weight=\frac{음성 데이터 수}{양성 데이터 수}
\]

현재 데이터 기준 초기값은 다음과 같다.

| 구분 | 음성/양성 비율 | 초기 설정값 |
|---|---:|---:|
| NOx | 약 50.2 | 50 |
| SO₂ | 약 162.6 | 163 |
| 전체 | 약 72.7 | 73 |

**XGBoost 적용 예시**

```python
from xgboost import XGBClassifier

model = XGBClassifier(
    n_estimators=300,
    max_depth=6,
    learning_rate=0.05,
    scale_pos_weight=73,
    eval_metric="aucpr",
    random_state=42
)

model.fit(X_train, y_train)
```

NOx와 SO₂를 별도로 학습한다면 각각 약 50, 163을 초기값으로 사용할 수 있다.

다만 이 값이 최적값이라는 의미는 아니다. 다음과 같이 여러 값을 비교하는 실험이 필요하다.

| 실험 | Scale Pos Weight | 목적 |
|---|---:|---|
| A | 1 | 가중치 미적용 기준 |
| B | 25 | 약한 양성 가중치 |
| C | 50 | NOx 기준값 |
| D | 73 | 전체 기준값 |
| E | 100 | 높은 양성 가중치 |
| F | 163 | SO₂ 기준값 |

실험 결과에서 Recall, Precision, PR-AUC를 비교하고 오경보 수준까지 고려하여 결정한다.

### 5.3 LSTM의 Weighted Loss

**개념**

LSTM은 신경망 모델이므로 손실 함수에 클래스별 가중치를 적용할 수 있다.

일반적인 Binary Cross Entropy는 양성과 음성의 오분류 손실을 동일한 기준으로 계산한다.

Weighted Loss는 양성 데이터의 손실에 더 큰 가중치를 부여한다.

\[
Loss=-[w_1y\log(p)+w_0(1-y)\log(1-p)]
\]

- \(y\): 실제 Label
- \(p\): 모델이 예측한 양성 확률
- \(w_1\): 양성 데이터 가중치
- \(w_0\): 음성 데이터 가중치

**PyTorch 적용 예시**

```python
import torch
import torch.nn as nn

pos_weight = torch.tensor([73.0])

criterion = nn.BCEWithLogitsLoss(
    pos_weight=pos_weight
)

logits = model(X_batch)

loss = criterion(
    logits,
    y_batch.float()
)
```

이 방법은 양성 데이터의 오분류에 더 큰 손실을 부여한다.

LSTM에서는 데이터 수 조정 없이 Weighted Loss부터 적용해 보는 것을 권장한다.

## 6. 예측 기준 조정 방법 (Threshold Tuning)

**개념**

Threshold Tuning은 학습된 모델이 출력한 확률을 실제 위험 여부로 판단하는 기준을 조정하는 방법이다.

예를 들어 모델이 다음과 같은 예측 확률을 출력했다고 가정한다.

| 데이터 | 위험 진입 확률 |
|---|---:|
| A | 95% |
| B | 80% |
| C | 65% |
| D | 40% |
| E | 10% |

일반적으로 이진 분류에서는 Threshold를 0.5로 설정하는 경우가 많다.

- 예측 확률 50% 이상: 위험(1)
- 예측 확률 50% 미만: 정상(0)

TMS에서는 위험을 사전에 탐지하는 것이 중요하므로 Threshold를 0.5보다 낮춰 볼 수 있다.

### 6.1 Threshold에 따른 예측 결과

| 데이터 | 예측 확률 | Threshold 0.5 | Threshold 0.3 |
|---|---:|---|---|
| A | 95% | 위험 | 위험 |
| B | 80% | 위험 | 위험 |
| C | 65% | 위험 | 위험 |
| D | 40% | 정상 | 위험 |
| E | 10% | 정상 | 정상 |

Threshold를 0.5에서 0.3으로 낮추면 D 데이터도 위험으로 판단한다.

실제 위험 상황을 더 많이 찾아낼 가능성이 있지만 정상 데이터까지 위험으로 판단하는 오경보도 증가할 수 있다.

### 6.2 Threshold별 성능 비교

| Threshold | Recall | Precision | 특징 |
|---:|---:|---:|---|
| 0.5 | 60% | 70% | 기본 기준 |
| 0.4 | 70% | 65% | 위험 탐지 증가 |
| 0.3 | 80% | 55% | 위험 탐지 증가, 오경보 증가 |
| 0.2 | 90% | 40% | 위험 탐지율은 높지만 오경보 증가 |

※ 위 수치는 Threshold 변화에 따른 관계를 설명하기 위한 가상의 예시이며 실제 TMS 모델의 측정 결과가 아니다.

**Python 적용 예시**

```python
from sklearn.metrics import (
    precision_score,
    recall_score,
    f1_score
)

y_prob = model.predict_proba(X_valid)[:, 1]

for threshold in [0.5, 0.4, 0.3, 0.2]:
    y_pred = (y_prob >= threshold).astype(int)

    precision = precision_score(y_valid, y_pred)
    recall = recall_score(y_valid, y_pred)
    f1 = f1_score(y_valid, y_pred)

    print(
        threshold,
        precision,
        recall,
        f1
    )
```

Threshold별 성능을 비교하여 실제 운영 목적에 맞는 기준을 선택한다.

TMS에서는 위험 진입을 놓치지 않는 것이 중요하므로 Recall을 우선 고려하되, 오경보가 운영에서 감당할 수 있는 수준인지 함께 확인해야 한다.

## 7. 불균형 해소 방법별 비교

| 방법 | 데이터 변경 | 장점 | 주의사항 | TMS 적용 |
|---|---|---|---|---|
| Undersampling | 음성 감소 | 학습 시간 감소 | 정상 패턴 손실 | 비교 실험 |
| Oversampling | 양성 복제 | 양성 비중 증가 | 과적합 가능성 | 비교 실험 |
| SMOTE | 양성 합성 | 새로운 Feature 조합 생성 | 시계열 특성 왜곡 | 신중한 추가 실험 |
| Class Weight | 변경 없음 | 구현 간단, 원본 유지 | 오경보 증가 가능 | 우선 권장 |
| Scale Pos Weight | 변경 없음 | XGBoost에 적합 | 가중치 튜닝 필요 | 우선 권장 |
| Weighted Loss | 변경 없음 | LSTM에 적용 가능 | 손실 가중치 튜닝 | 우선 권장 |
| Threshold Tuning | 변경 없음 | 운영 기준에 맞춘 조정 | Precision 저하 가능 | 필수 비교 |

## 8. 교육생 실습 권장 순서

처음부터 여러 방법을 동시에 적용하면 어떤 방법이 성능에 영향을 주었는지 알기 어렵다.

따라서 다음 순서로 실험하는 것을 권장한다.

### 1단계: 기본 모델 학습

불균형 대응을 적용하지 않은 Random Forest 또는 XGBoost를 학습한다.

- 전체 Train 데이터 사용
- 기본 Threshold 0.5
- Recall, Precision, F1, PR-AUC 측정

### 2단계: Class Weight 적용

동일한 데이터에 Class Weight 또는 Scale Pos Weight를 적용한다.

- 가중치 1
- 가중치 25
- 가중치 50
- 가중치 73
- 가중치 100

모델 성능이 어떻게 달라지는지 비교한다.

### 3단계: Undersampling 적용

음성 데이터를 양성 데이터의 5배 또는 10배 수준으로 줄여 학습한다.

전체 데이터를 사용한 모델과 비교하여 학습 시간과 성능 변화를 확인한다.

### 4단계: Oversampling 또는 SMOTE 적용

양성 데이터 복제와 합성 데이터 생성 방식의 차이를 확인한다.

SMOTE는 시간적 연속성이 유지되지 않을 수 있으므로 별도의 데이터 품질 검증을 진행한다.

### 5단계: Threshold 조정

가장 성능이 좋은 모델을 대상으로 Threshold를 0.5, 0.4, 0.3, 0.2 등으로 변경한다.

Recall과 Precision의 균형을 비교한다.

### 6단계: 최종 모델 선정

실제 위험 진입을 놓치는 비율과 오경보 발생 수준을 함께 고려하여 최종 모델을 선정한다.

### 8.1 실험 결과 기록 양식

| 실험 | 불균형 대응 | 가중치/비율 | Threshold | Recall | Precision | PR-AUC |
|---|---|---:|---:|---:|---:|---:|
| A | 미적용 | 1 | 0.5 | 측정 | 측정 | 측정 |
| B | Class Weight | Balanced | 0.5 | 측정 | 측정 | 측정 |
| C | Class Weight | 73 | 0.5 | 측정 | 측정 | 측정 |
| D | Undersampling | 1:5 | 0.5 | 측정 | 측정 | 측정 |
| E | Oversampling | 1:5 | 0.5 | 측정 | 측정 | 측정 |
| F | 최적 모델 | 선택값 | 0.3 | 측정 | 측정 | 측정 |

※ 모든 실험은 동일한 시간 기준 데이터 분할을 사용한다. Validation 데이터는 원래 클래스 비율을 유지하고, 최종 Test 데이터는 모델과 Threshold를 선택한 이후 최종 평가에 사용한다.

## 9. 교육생에게 강조할 핵심 내용

클래스 불균형 문제를 해결하는 목적은 양성과 음성의 숫자를 무조건 똑같이 만드는 것이 아니다.

**실제 위험 데이터가 적더라도 모델이 위험 패턴을 제대로 학습하고, 운영 환경에서 위험 상황을 놓치지 않도록 만드는 것이 목적이다.**

이번 TMS 프로젝트에서는 다음 방향을 권장한다.

1. 데이터 분할과 누수 방지를 먼저 수행한다.
2. Random Forest는 `class_weight="balanced"`를 적용한 모델과 미적용 모델을 비교한다.
3. XGBoost는 `scale_pos_weight`를 조정하면서 성능을 비교한다.
4. LSTM은 Weighted Loss를 적용하여 양성 데이터의 학습 비중을 높인다.
5. Undersampling과 Oversampling은 추가 비교 실험으로 진행한다.
6. SMOTE는 시계열 특성을 고려하여 신중하게 적용한다.
7. 최종 모델은 Threshold를 조정하여 Recall과 Precision의 균형을 확인한다.

**권장 실험 순서**

데이터 분할 및 누수 방지 → 기본 모델 학습 → 가중치 조정 → 데이터 수 조정 → Threshold 조정 → 최종 모델 선정

이 순서로 진행하면 각 방법이 모델 성능에 미치는 영향을 명확하게 비교할 수 있다.
