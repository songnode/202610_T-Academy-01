# LSTM Window Size와 Batch Size 이해하기

## 1. LSTM 학습 데이터의 기본 구조

TMS 프로젝트에서는 굴뚝별·물질별로 30분 간격의 측정 데이터를 수집합니다.

각 측정 시점에는 24개의 Feature가 있습니다.

예를 들어 다음과 같은 데이터가 있다고 가정하겠습니다.

| 측정 시각 | ratio_pct | ratio_lag_30m | ratio_lag_60m | ... | Feature 수 |
|---|---:|---:|---:|---|---:|
| 09:00 | 72.0 | 70.0 | 68.0 | ... | 24 |
| 09:30 | 75.0 | 72.0 | 70.0 | ... | 24 |
| 10:00 | 78.0 | 75.0 | 72.0 | ... | 24 |
| 10:30 | 82.0 | 78.0 | 75.0 | ... | 24 |
| 11:00 | 85.0 | 82.0 | 78.0 | ... | 24 |
| 11:30 | 88.0 | 85.0 | 82.0 | ... | 24 |

RF/XGBoost는 각 시점의 Feature 24개를 독립적인 행으로 학습합니다.

반면 LSTM은 시간에 따른 변화 패턴을 학습하기 위해 여러 시점의 데이터를 하나로 묶어서 사용합니다.

이때 사용하는 개념이 **Window Size**입니다.

---

## 2. Window Size란?

Window Size는 **하나의 Sequence에 포함할 과거 시점의 개수**를 의미합니다.

TMS 프로젝트에서는 30분 간격의 측정 데이터를 사용하므로 Window Size를 6으로 설정하면 최근 6개 시점의 데이터를 하나의 Sequence로 구성합니다.

### 2.1 Window Size = 6인 경우

30분 간격으로 수집된 데이터 6개를 하나로 묶습니다.

```text
Sequence 1

09:00 → 09:30 → 10:00 → 10:30 → 11:00 → 11:30
  ①       ②       ③       ④       ⑤       ⑥

각 시점의 Feature = 24개

하나의 Sequence = (6, 24)
```

즉, 하나의 Sequence는 다음과 같은 형태입니다.

```python
Sequence.shape = (6, 24)
```

- 6: 시간 시점의 개수
- 24: 각 시점의 Feature 개수

LSTM은 이 6개 시점의 데이터를 순서대로 입력받아 시간에 따른 배출비율의 변화 패턴을 학습합니다.

### 2.2 왜 여러 시점을 묶어서 학습할까?

현재 시점의 배출비율만으로는 향후 배출 위험을 판단하기 어려울 수 있습니다.

예를 들어 현재 배출비율이 모두 85%라고 하더라도 과거 변화 양상에 따라 위험 수준이 달라질 수 있습니다.

| 시각 | 상황 A | 상황 B |
|---|---:|---:|
| 10:00 | 65% | 95% |
| 10:30 | 70% | 92% |
| 11:00 | 75% | 90% |
| 11:30 | 80% | 88% |
| 12:00 | 83% | 86% |
| 12:30 | 85% | 85% |

현재 배출비율은 두 상황 모두 85%입니다.

하지만 상황 A는 배출비율이 지속적으로 상승하고 있고, 상황 B는 반대로 하락하고 있습니다.

LSTM은 이러한 시간에 따른 변화 패턴을 학습하여 향후 배출비율이나 위험 진입 가능성을 예측할 수 있습니다.

따라서 Window Size를 사용하는 목적은 **현재 상태뿐 아니라 과거의 변화 흐름을 함께 학습하기 위해서**입니다.

### 2.3 Window Size에 따라 달라지는 데이터

30분 간격의 데이터를 기준으로 Window Size를 변경하면 다음과 같습니다.

| Window Size | 포함되는 시점 수 | 데이터가 나타내는 구간 |
|---:|---:|---:|
| 3 | 3개 | 1시간 |
| 6 | 6개 | 3시간 |
| 12 | 12개 | 6시간 |
| 24 | 24개 | 12시간 |
| 48 | 48개 | 24시간 |

※ 6개 시점은 예를 들어 09:00~11:30에 해당합니다. 첫 시점과 마지막 시점 사이의 경과 시간은 2시간 30분이지만, 각 시점이 30분 측정 구간을 대표하므로 6개 슬롯은 3시간의 측정 구간을 나타냅니다.

Window Size가 커지면 더 긴 과거 흐름을 학습할 수 있지만, 다음과 같은 부담도 생깁니다.

- 입력 데이터 크기가 커집니다.
- 학습에 필요한 메모리가 증가합니다.
- 긴 과거 정보가 반드시 예측 성능을 높여 주는 것은 아닙니다.
- 과거 데이터가 많아질수록 학습 데이터 구성 조건이 까다로워집니다.

따라서 TMS 프로젝트에서는 Window Size 6을 기본값으로 시작하고, 12와 24를 추가로 비교하는 것을 권장합니다.

## 3. Sliding Window란?

Sliding Window는 Window Size만큼 데이터를 묶은 다음, 한 시점씩 이동하면서 다음 Sequence를 생성하는 방식입니다.

Window Size가 6이라면 다음과 같이 구성합니다.

```text
Sequence 1
09:00 ~ 11:30 (6개 시점)

Sequence 2
09:30 ~ 12:00 (6개 시점)

Sequence 3
10:00 ~ 12:30 (6개 시점)

Sequence 4
10:30 ~ 13:00 (6개 시점)
```

즉, 첫 번째 Sequence를 생성한 후 30분 뒤로 이동하여 다음 Sequence를 생성합니다.

이렇게 하면 연속된 시간 데이터를 활용하여 학습용 Sequence를 많이 만들 수 있습니다.

### 3.1 Sequence의 정답(Label)은 어떻게 결정할까?

각 Sequence의 마지막 시점을 예측 기준 시점으로 사용합니다.

TMS 프로젝트의 Label은 다음과 같습니다.

- 분류: `label_entry_60m`
- 회귀: `label_ratio_60m`

예를 들어 다음과 같습니다.

| 구분 | 입력 데이터 | 예측 기준 시점 | 정답 |
|---|---|---|---|
| Sequence 1 | 09:00~11:30 | 11:30 | 12:30의 Label |
| Sequence 2 | 09:30~12:00 | 12:00 | 13:00의 Label |
| Sequence 3 | 10:00~12:30 | 12:30 | 13:30의 Label |

분류 모델은 60분 이내 위험 기준(90%) 진입 여부를 예측하고, 회귀 모델은 정확히 60분 후의 배출비율을 예측합니다.

### 3.2 Sequence 생성 시 주의사항

TMS 데이터는 굴뚝별·물질별로 독립적인 시계열을 유지해야 합니다.

따라서 다음 기준을 지켜야 합니다.

1. `stack_code + item_code` 기준으로 데이터를 그룹화합니다.
2. 각 그룹 안에서 `measured_at` 순서로 정렬합니다.
3. 30분 간격이 정확하게 유지되는 데이터만 하나의 Sequence로 구성합니다.
4. 중간 측정 데이터가 누락되면 해당 구간을 포함하는 Sequence는 제외합니다.
5. Sequence의 정답은 마지막 시점 행의 Label을 사용합니다.

서로 다른 굴뚝이나 NOx와 SO₂ 데이터를 하나의 Sequence로 연결하면 안 됩니다.

## 4. Batch Size란?

Batch Size는 **한 번의 학습 단계에서 모델에 전달하는 Sequence의 개수**를 의미합니다.

Window Size가 하나의 Sequence를 구성하는 방법이라면, Batch Size는 이렇게 만들어진 Sequence를 몇 개씩 묶어서 학습할지 결정하는 값입니다.

예를 들어 다음과 같은 학습 데이터가 있다고 가정하겠습니다.

```python
X_train.shape = (10000, 6, 24)
```

전체 학습 데이터는 10,000개의 Sequence로 구성되어 있습니다.

각 Sequence의 형태는 `(6, 24)`입니다.

Batch Size를 64로 설정하면 한 번에 64개의 Sequence를 모델에 전달합니다.

```python
Batch.shape = (64, 6, 24)
```

각 차원의 의미는 다음과 같습니다.

- 64: 한 번에 전달하는 Sequence 개수
- 6: Sequence 하나에 포함된 시점 수
- 24: 각 시점의 Feature 개수

---

## 5. Batch Size를 사용하는 이유

학습 데이터가 10,000개라고 해서 반드시 10,000개를 한꺼번에 모델에 전달할 필요는 없습니다.

데이터를 적절한 크기로 나누어 학습하면 메모리와 학습 효율을 관리하기 쉽습니다.

### 5.1 메모리 사용량 관리

예를 들어 학습 데이터 10,000개를 한꺼번에 전달하면 한 번에 많은 데이터를 메모리에 올려야 합니다.

반면 Batch Size를 64로 설정하면 64개씩 나누어 처리합니다.

```text
전체 학습 데이터: 10,000개

Batch 1  → 64개 Sequence
Batch 2  → 64개 Sequence
Batch 3  → 64개 Sequence
...
Batch 157 → 마지막 16개 Sequence
```

이렇게 나누면 한 번에 처리하는 데이터 크기를 제한할 수 있습니다.

다만 실제 GPU 메모리 사용량에는 모델 구조, 중간 계산 결과, Gradient 등이 함께 영향을 줍니다.

### 5.2 학습 효율 관리

Batch Size에 따라 한 번의 학습 단계에서 처리하는 데이터 개수가 달라집니다.

| Batch Size | 한 번에 전달하는 Sequence | Epoch당 학습 단계 |
|---:|---:|---:|
| 16 | 16개 | 625회 |
| 32 | 32개 | 313회 |
| 64 | 64개 | 157회 |
| 128 | 128개 | 79회 |
| 256 | 256개 | 40회 |

※ 전체 학습 데이터 10,000개 기준이며, 마지막 Batch에 남은 데이터도 사용합니다.

Batch Size가 작으면 한 Epoch에서 모델의 가중치를 업데이트하는 횟수가 많아집니다.

Batch Size가 크면 한 Epoch에서 가중치를 업데이트하는 횟수가 줄어듭니다.

여기서 중요한 점은 **Batch Size가 크다고 학습이 무조건 빠르거나 성능이 좋아지는 것은 아니라는 것**입니다.

실제 학습 속도와 성능은 GPU 환경, 모델 구조, 데이터 크기, 최적화 설정 등에 따라 달라집니다.

### 5.3 Gradient 업데이트

LSTM은 예측 결과와 실제 정답의 차이를 이용해 모델의 가중치를 업데이트합니다.

Batch Size가 64라면 64개 Sequence의 예측 오차를 바탕으로 Gradient를 계산하고, 이를 이용해 가중치를 업데이트합니다.

```text
Sequence 64개 입력
        ↓
LSTM 모델 예측
        ↓
실제 Label과 예측 결과 비교
        ↓
Loss 계산
        ↓
Gradient 계산
        ↓
모델 가중치 업데이트
```

이 과정을 반복하면서 모델의 예측 성능을 개선합니다.

## 6. Batch Size는 왜 64개를 사용할까?

64는 특별한 의미가 있어서 정해진 숫자가 아닙니다.

학습 효율과 메모리 사용량을 고려해 실험을 시작하기에 적절한 후보 중 하나입니다.

일반적으로 다음과 같은 특징이 있습니다.

| Batch Size | 특징 |
|---:|---|
| 16 | 메모리 사용량이 상대적으로 적고, 업데이트 횟수가 많음 |
| 32 | 비교적 작은 Batch로 시작하기 좋은 설정 |
| 64 | 학습 효율과 메모리 사용량을 비교하기 좋은 설정 |
| 128 | 한 번에 더 많은 데이터를 처리하지만 메모리 사용량 증가 |
| 256 | 메모리 여유가 필요하며 성능 비교가 필요함 |

따라서 처음부터 64로 확정하기보다는 32, 64, 128을 비교하여 결정하는 것이 좋습니다.

### 6.1 TMS 프로젝트 권장 실험

| 실험 | Batch Size | 확인할 내용 |
|---|---:|---|
| 1차 | 32 | 기본 학습 성능 및 메모리 사용량 |
| 2차 | 64 | 학습 속도 및 성능 비교 |
| 3차 | 128 | 메모리 사용량 및 성능 비교 |

주요 비교 항목은 다음과 같습니다.

- GPU 메모리 사용량
- Epoch당 학습 시간
- Validation Loss
- 분류 성능: Recall, Precision, F1-score, PR-AUC
- 회귀 성능: MAE, RMSE

특히 TMS 분류 데이터는 양성 비율이 낮으므로 Accuracy만으로 Batch Size의 성능을 판단하면 안 됩니다.

## 7. Epoch란?

Epoch는 전체 학습 데이터를 한 번 모두 사용하여 학습하는 과정을 의미합니다.

예를 들어 다음과 같은 조건이라고 가정하겠습니다.

- 전체 학습 데이터: 10,000개 Sequence
- Batch Size: 64
- Epoch: 20

한 Epoch에서 약 157번의 Batch 학습을 수행합니다.

```text
Epoch 1
  Batch 1   → 64개
  Batch 2   → 64개
  Batch 3   → 64개
  ...
  Batch 157 → 16개

Epoch 2
  전체 학습 데이터 다시 학습

...

Epoch 20
  전체 학습 데이터 20번째 학습
```

따라서 Epoch 20은 전체 학습 데이터를 20번 반복해서 학습한다는 의미입니다.

---

## 8. 실제 LSTM 학습 코드

TMS 프로젝트에서 다음과 같이 설정할 수 있습니다.

```python
model.fit(
    X_train,
    y_train,
    epochs=20,
    batch_size=64,
    shuffle=True
)
```

각 설정의 의미는 다음과 같습니다.

| 설정 | 값 | 의미 |
|---|---:|---|
| Window Size | 6 | 하나의 Sequence에 포함되는 시점 수 |
| Feature 수 | 24 | 각 시점의 입력 변수 수 |
| Batch Size | 64 | 한 번에 학습하는 Sequence 개수 |
| Epoch | 20 | 전체 학습 데이터를 반복하는 횟수 |
| Shuffle | True | 학습용 Sequence의 순서를 섞음 |

※ `shuffle=True`는 학습용 Sequence 간의 순서를 섞는 것이며, Sequence 내부의 시간 순서는 유지됩니다. 시계열 데이터는 Train/Validation/Test를 시간 기준으로 먼저 분리한 후 학습용 Sequence만 섞어야 합니다.

## 9. Window Size와 Batch Size의 차이

두 개념을 비교하면 다음과 같습니다.

| 구분 | Window Size | Batch Size |
|---|---|---|
| 의미 | 하나의 Sequence에 포함되는 시점 수 | 한 번에 전달하는 Sequence 수 |
| TMS 설정 예시 | 6 | 64 |
| 기준 | 시간 데이터의 길이 | 학습 데이터의 묶음 크기 |
| 역할 | 과거 변화 패턴 학습 | 메모리 및 학습 효율 관리 |
| 변경 효과 | 모델이 참고하는 과거 시간 범위 변경 | 한 번에 처리하는 데이터 양 변경 |

### 전체 데이터 구조

```text
전체 학습 데이터
10,000개 Sequence
        │
        ├── Sequence 1  → (6, 24)
        ├── Sequence 2  → (6, 24)
        ├── Sequence 3  → (6, 24)
        ├── ...
        └── Sequence 10,000 → (6, 24)
                │
                ▼
        Batch Size = 64
                │
                ▼
        한 번의 학습 단계
          (64, 6, 24)
                │
                ▼
          LSTM 모델 학습
                │
                ▼
          Loss 및 Gradient 계산
                │
                ▼
          모델 가중치 업데이트
```

## 10. TMS 프로젝트 권장 시작 설정

| 항목 | 권장 시작값 | 설명 |
|---|---:|---|
| Window Size | 6 | 과거 3시간 측정 구간 |
| Feature 수 | 24 | ML-ready 입력 Feature |
| Batch Size | 64 | 한 번에 64개 Sequence 학습 |
| Epoch | 20 | 전체 학습 데이터 20회 반복 |
| Optimizer | Adam | 가중치 최적화 |
| Loss (분류) | Binary Crossentropy | 위험 진입 여부 예측 |
| Loss (회귀) | MAE 또는 MSE | 60분 후 배출비율 예측 |

위 설정은 최초 실험을 위한 시작값이며, 최종 설정은 Validation 성능과 학습 시간, GPU 메모리 사용량을 비교하여 결정합니다.

**핵심 정리**

1. Window Size는 하나의 Sequence에 과거 데이터를 몇 개의 시점까지 포함할 것인지 결정합니다.
2. Batch Size는 만들어진 Sequence를 한 번에 몇 개씩 모델에 전달할 것인지 결정합니다.
3. Epoch는 전체 학습 데이터를 몇 번 반복해서 학습할 것인지 결정합니다.

따라서 TMS 프로젝트에서 `Window Size=6`, `Batch Size=64`라면 **30분 간격의 과거 6개 시점으로 구성된 Sequence 64개를 한 번에 LSTM 모델에 전달하여 학습한다는 의미**입니다.
