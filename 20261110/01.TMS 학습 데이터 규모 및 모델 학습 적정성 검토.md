현재 생성된 ML-ready 데이터를 기준으로 분류 및 회귀 학습 데이터 규모를 정리하였다.

### 1.1 전체 데이터 현황

| 구분 | NOx | SO₂ | 합계 |

- 전체 ML-ready 데이터는 약 1,764만 건이다.
- 분류 학습 가능 데이터는 약 986만 건이다.

- 다만 회귀 학습 가능 데이터가 분류보다 약 82만 건 많은 이유는 실제 Label 생성 SQL과 결측 처리 로직을 확인할 필요가 있다.

현재 데이터 규모는 Random Forest, XGBoost, LSTM 모델의 학습 실험을 진행할 만한 수준이다. 다만 실제 학습 적정성은 데이터 품질, 시간 기준 데이터 분리, 클래스 불균형, LSTM Sequence 생성 후 데이터 규모 등을 함께 확인해야 한다.

## 2. 분류 학습 데이터는 어떻게 생성하는가?

분류 모델은 현재 배출비율을 기준으로 향후 60분 이내에 위험 수준에 도달할 가능성을 예측한다.

### 2.1 분류 목적

현재 배출비율이 90% 미만인 시점을 대상으로 향후 60분 이내에 배출비율이 90% 이상으로 진입하는지를 판단한다.

- 현재 시점: T
- 미래 확인 시점: T+30분, T+60분
- 위험 판단 기준: 배출비율 90% 이상
- Label: `label_entry_60m`

### 2.2 분류 판단 기준

분류 Label은 양성(1), 음성(0), 판정 제외(NULL)로 구분한다.

| 구분 | 현재(T) | T+30분 | T+60분 | Label | 판단 결과 |
|---|---:|---:|---:|---:|---|
| 양성 | 80% | 92% | 95% | 1 | 30분 후 위험 진입 |
| 양성 | 85% | 88% | 93% | 1 | 60분 후 위험 진입 |
| 양성 | 85% | 92% | 누락 | 1 | 30분 후 위험 진입 확인 |
| 양성 | 85% | 누락 | 93% | 1 | 60분 후 위험 진입 확인 |
| 음성 | 75% | 80% | 85% | 0 | 두 미래 시점 모두 90% 미만 |
| 판정 제외 | 85% | 87% | 누락 | NULL | 위험 진입 여부 판정 불가 |
| 판정 제외 | 85% | 누락 | 85% | NULL | 위험 진입 여부 판정 불가 |
| 판정 제외 | 92% | 95% | 98% | NULL | 현재 이미 위험 기준 이상 |
| 판정 제외 | 누락 | 85% | 88% | NULL | 현재 상태 확인 불가 |

### 2.3 최종 Label 생성 규칙

다음 순서로 판단한다.

1. 현재 배출비율이 유효하지 않으면 NULL로 처리한다.
2. 현재 배출비율이 90% 이상이면 NULL로 처리한다.
3. T+30분 또는 T+60분 중 유효한 측정값 하나라도 90% 이상이면 1(양성)로 처리한다.
4. T+30분과 T+60분이 모두 유효하고 90% 미만이면 0(음성)으로 처리한다.
5. 나머지 경우는 위험 진입 여부를 확정할 수 없으므로 NULL로 처리한다.

**중요한 판단 원칙**

- 90%와 정확히 같은 값도 위험 진입으로 판단한다.
- T+30분에서 위험 진입이 확인되면 T+60분 값이 누락되어도 양성이다.
- 음성으로 판단하려면 T+30분과 T+60분 두 값이 모두 유효해야 한다.
- 미래 측정값이 일부 누락된 경우 무조건 음성으로 처리하면 안 된다.
- 현재 이미 위험 수준에 도달한 데이터는 신규 위험 진입 예측 대상에서 제외한다.

### 2.4 Python Label 생성 예시

```python
def create_label(current, future_30m, future_60m):

    # 현재 측정값 확인
    if current is None:
        return None

    # 현재 이미 위험 기준 이상인 경우
    if current >= 90:
        return None

    # 미래 측정값 중 위험 기준 이상이 있는 경우
    if (
        (future_30m is not None and future_30m >= 90)
        or
        (future_60m is not None and future_60m >= 90)
    ):
        return 1

    # 두 미래 측정값이 모두 유효하고 90% 미만인 경우
    if (
        future_30m is not None
        and future_60m is not None
        and future_30m < 90
        and future_60m < 90
    ):
        return 0

    # 위험 진입 여부를 확정할 수 없는 경우
    return None
```

※ 실제 구현에서는 `None`뿐 아니라 NaN, 측정 오류 상태 등도 유효하지 않은 값으로 처리해야 한다.

### 2.5 분류 학습 데이터 생성 결과

| Label | 의미 | 학습 처리 |
|---|---|---|
| 1 | 향후 60분 이내 90% 이상 진입 | 양성 데이터로 학습 |
| 0 | 향후 60분 동안 모두 90% 미만 | 음성 데이터로 학습 |
| NULL | 현재 상태 또는 미래 위험 진입 여부 확인 불가 | 분류 학습에서 제외 |

분류 학습 가능 데이터는 다음과 같이 계산한다.

`분류 학습 가능 데이터 = Label 1 데이터 + Label 0 데이터`

현재 집계 결과는 다음과 같다.

- 양성 데이터: 133,716건
- 음성 데이터: 9,724,168건
- 분류 학습 가능 데이터: 9,857,884건

## 3. 양성 데이터와 클래스 불균형

### 3.1 양성 데이터 비율

| 구분 | 양성 | 음성 | 양성 비율 |
|---|---:|---:|---:|
| NOx | 106,931 | 5,370,463 | 약 1.95% |
| SO₂ | 26,785 | 4,353,705 | 약 0.61% |
| 전체 | 133,716 | 9,724,168 | 약 1.36% |

전체 분류 데이터에서 양성 비율은 약 1.36%로 낮은 편이다.

즉, 대부분의 데이터는 정상 범위에 해당하고 실제 위험 진입 데이터는 상대적으로 적다.

### 3.2 클래스 불균형 문제

전체 데이터에서 양성 데이터가 약 1.36%라면 모든 데이터를 정상(0)으로 예측하더라도 정확도는 약 98.64%가 된다.

따라서 Accuracy만으로 모델 성능을 평가하면 실제 위험 진입을 제대로 예측하지 못하는 모델도 성능이 좋은 것처럼 보일 수 있다.

### 3.3 클래스 불균형 대응 방법

| 모델 | 대응 방법 | 설명 |
|---|---|---|
| Random Forest | Class Weight | 양성 데이터의 학습 가중치를 높임 |
| XGBoost | Scale Pos Weight | 양성 데이터의 가중치를 조정 |
| LSTM | Weighted Loss | 양성 데이터의 오분류 손실을 높임 |
| 공통 | Threshold 조정 | 위험 예측 확률의 판정 기준을 조정 |
| 공통 | Negative Sampling | 학습용 음성 데이터 일부를 샘플링 |

XGBoost의 초기 `scale_pos_weight` 참고값은 다음과 같다.

| 구분 | 음성/양성 비율 |
|---|---:|
| NOx | 약 50 |
| SO₂ | 약 163 |
| 전체 | 약 73 |

이 값은 초기 실험을 위한 참고값이며 최종 설정값은 아니다. Validation 데이터에서 Recall, Precision, PR-AUC를 비교하여 조정해야 한다.

※ Negative Sampling을 적용하더라도 Validation 및 Test 데이터는 실제 클래스 분포를 유지해야 한다.

### 3.4 평가 지표

| 평가 지표 | 의미 | 중요도 |
|---|---|---|
| Recall | 실제 위험 진입 데이터 중 찾아낸 비율 | 중요 |
| Precision | 위험 진입으로 예측한 데이터 중 실제 위험 진입 비율 | 중요 |
| F1-Score | Precision과 Recall의 조화 평균 | 중요 |
| PR-AUC | 불균형 데이터에서 양성 클래스 예측 성능 평가 | 중요 |
| Confusion Matrix | 실제값과 예측값의 조합 확인 | 필수 |
| Accuracy | 전체 예측 정확도 | 참고 |

사전 경고 시스템은 위험 상황을 놓치지 않는 것이 중요하므로 Recall을 중요하게 봐야 한다. 다만 Recall을 높이는 과정에서 오경보가 지나치게 증가하지 않도록 Precision도 함께 확인해야 한다.

## 4. 회귀 학습 데이터는 어떻게 생성하는가?

회귀 모델은 현재 시점의 Feature를 기반으로 정확히 60분 후의 배출비율을 예측한다.

### 4.1 회귀 목적

- 입력: 현재 시점의 Feature 24개
- 예측 대상: T+60분의 배출비율
- Label: `label_ratio_60m`

회귀 Label은 다음과 같이 생성한다.

`label_ratio_60m = future_60m_ratio`

예를 들어 다음과 같다.

| 현재(T) | T+30분 | T+60분 | 회귀 Label |
|---:|---:|---:|---:|
| 70% | 75% | 80% | 80% |
| 80% | 85% | 95% | 95% |
| 85% | 90% | 105% | 105% |
| 92% | 95% | 98% | 98% |

### 4.2 회귀 Label 생성 기준

1. 현재 시점의 Feature가 유효해야 한다.
2. 정확히 T+60분의 측정값이 존재해야 한다.
3. T+60분의 배출비율을 계산할 수 있어야 한다.
4. T+30분의 측정값은 회귀 Label 생성에 필수 조건이 아니다.
5. 90% 초과 데이터도 그대로 유지한다.

회귀 모델은 배출비율 자체를 예측하는 것이 목적이므로 현재 이미 90% 이상인 데이터도 학습에 포함할 수 있다.

### 4.3 회귀 학습 데이터 규모

| 구분 | NOx | SO₂ | 합계 |
|---|---:|---:|---:|
| 회귀 학습 가능 데이터 | 5,960,021 | 4,727,123 | 10,687,144 |

회귀 학습 가능 데이터는 분류 학습 가능 데이터보다 829,260건 많다.

이는 분류와 회귀의 Label 생성 조건이 다르기 때문에 발생할 수 있다.

다만 실제 차이가 발생한 원인을 확인하려면 다음을 점검해야 한다.

- 분류와 회귀의 현재 Feature 유효성 조건이 동일한지
- 분류에서 현재 90% 이상인 데이터가 제외되는지
- 미래 T+30분 및 T+60분 결측 처리 기준이 올바른지
- 회귀 Label 생성 시 정확히 T+60분 데이터만 연결했는지
- 분류와 회귀 데이터 집계 시 중복 및 NULL 처리 기준이 동일한지

## 5. 현재 데이터 규모는 학습하기에 적절한가?

현재 데이터 규모를 기준으로 Random Forest, XGBoost, LSTM의 학습 가능성을 검토한다.

### 5.1 Random Forest

Random Forest는 여러 개의 Decision Tree를 생성하고 각 Tree의 결과를 종합하는 방식이다.

- 입력 데이터: Feature 24개
- 입력 Shape: `(N, 24)`
- 분류 데이터: 약 986만 건
- 회귀 데이터: 약 1,069만 건

**적정성 검토**

현재 데이터 규모라면 학습 실험을 진행할 수 있다.

다만 수백만 건 이상의 데이터를 사용하면 메모리 사용량과 학습 시간이 증가할 수 있으므로 초기에는 일부 데이터를 활용하여 파라미터를 조정한 후 전체 데이터 학습을 검토하는 것이 좋다.

분류 모델에서는 `class_weight="balanced"` 또는 `balanced_subsample`을 적용하는 방법을 검토한다.

### 5.2 XGBoost

XGBoost는 여러 개의 Decision Tree를 순차적으로 학습하면서 이전 모델의 오차를 보완하는 방식이다.

- 입력 데이터: Feature 24개
- 입력 Shape: `(N, 24)`
- 분류 데이터: 약 986만 건
- 회귀 데이터: 약 1,069만 건

**적정성 검토**

현재 데이터 규모는 XGBoost 학습 실험을 진행하기에 충분한 수준이다.

특히 현재와 과거의 배출비율, 추세, 이동평균 등으로 구성된 Feature를 활용하여 위험 진입 가능성과 미래 배출비율을 예측하는 데 적합하다.

분류 모델에서는 `scale_pos_weight`를 적용하여 클래스 불균형을 보정하는 실험을 권장한다.

### 5.3 LSTM

LSTM은 시간의 흐름에 따른 데이터 패턴을 학습하는 시계열 모델이다.

Random Forest와 XGBoost가 한 시점의 Feature 24개를 입력으로 사용하는 것과 달리, LSTM은 여러 시점의 Feature를 하나의 Sequence로 구성한다.

**입력 데이터 구성**

- Feature 개수: 24개
- Window Size: 6
- Batch Size: 64

하나의 Sequence는 다음과 같이 구성된다.

`(6, 24)`

즉, 과거 6개 시점의 Feature 24개를 하나의 입력으로 사용한다.

Batch Size가 64라면 한 번의 학습 단계에서 64개의 Sequence를 처리한다.

`(64, 6, 24)`

**적정성 검토**

현재 데이터 규모라면 LSTM 학습도 시도할 수 있다.

다만 LSTM은 분류 또는 회귀 학습 가능 행 수를 그대로 사용할 수 없다. 각 그룹별로 연속된 30분 간격의 데이터 6개가 확보되어야 하나의 Sequence를 생성할 수 있기 때문이다.

다음 사항을 확인해야 한다.

- `stack_code + item_code` 기준으로 그룹화
- `measured_at` 기준 오름차순 정렬
- 30분 간격으로 연속된 6개 시점 확인
- 6개 시점의 Feature가 모두 유효한지 확인
- 마지막 시점의 Label이 유효한지 확인
- 결측 시점을 건너뛰어 Sequence를 연결하지 않도록 처리

따라서 실제 LSTM 학습 가능 데이터는 Sequence 생성 이후 별도로 집계해야 한다.

## 6. 모델별 학습 적정성 종합 비교

| 구분 | Random Forest | XGBoost | LSTM |
|---|---|---|---|
| 입력 데이터 | Feature 24개 | Feature 24개 | Feature 24개 × 6시점 |
| 입력 Shape | `(N, 24)` | `(N, 24)` | `(N, 6, 24)` |
| 시간 흐름 학습 | 직접 반영 제한적 | Feature를 통한 간접 반영 | Sequence로 직접 반영 |
| Scaling | 일반적으로 불필요 | 일반적으로 불필요 | 권장 |
| 클래스 불균형 대응 | Class Weight | Scale Pos Weight | Weighted Loss |
| 학습 규모 | 충분한 실험 가능 | 충분한 실험 가능 | Sequence 생성 후 판단 |
| 주요 검토 사항 | 메모리 및 학습 시간 | 파라미터 및 불균형 | Sequence 수 및 시간 연속성 |

### 종합 의견

1. Random Forest와 XGBoost는 현재 Feature 24개를 활용하여 기본 모델을 구성하고 성능을 비교하기에 적합하다.
2. LSTM은 시간에 따른 배출비율 변화 패턴을 학습할 수 있으므로 추가 비교 모델로 활용할 수 있다.
3. LSTM은 Window Size 6 적용 후 실제 Sequence 수를 별도로 확인해야 한다.
4. 분류는 클래스 불균형이 크므로 Recall, Precision, PR-AUC 중심으로 평가해야 한다.
5. 최종 모델은 동일한 Train/Validation/Test 조건에서 비교해야 한다.

## 7. 학습하기 전에 반드시 확인해야 할 사항

### 7.1 Label 생성 로직

- 분류 Label의 90% 기준이 일관되게 적용되었는가?
- T+30분 또는 T+60분 중 하나라도 90% 이상이면 양성으로 처리하는가?
- 음성은 두 미래 시점이 모두 유효하고 90% 미만인 경우에만 부여하는가?
- 미래 측정값이 누락된 경우 잘못해서 음성으로 처리하지 않는가?
- 회귀 Label은 정확히 T+60분의 배출비율을 사용하고 있는가?

### 7.2 양성 데이터 집계

현재 양성 데이터 133,716건은 Label이 1인 행의 수이다.

이 값이 실제 위험 발생 이벤트 133,716건을 의미하는 것은 아니다.

예를 들어 30분 간격으로 연속해서 위험 진입이 발생하면 여러 행이 양성으로 기록될 수 있다.

따라서 연속된 양성 구간을 하나의 위험 이벤트로 묶어 실제 위험 이벤트 수도 별도로 집계하는 것이 좋다.

### 7.3 데이터 분리

시계열 데이터이므로 무작위 분리보다는 시간 순서에 따른 Train/Validation/Test 분리를 권장한다.

예시:

| 구분 | 데이터 기간 | 비율 |
|---|---|---:|
| Train | 초기 27개월 | 75% |
| Validation | 다음 4.5개월 | 12.5% |
| Test | 마지막 4.5개월 | 12.5% |

실제 데이터 기간과 위험 발생 분포를 확인한 후 최종 기간을 결정한다.

특히 분할 경계에서 미래 Label이 Validation 또는 Test 기간을 참조하지 않도록 주의해야 한다.

### 7.4 LSTM Sequence 생성

LSTM은 전체 행 수가 아닌 실제 Sequence 수를 기준으로 학습 규모를 판단해야 한다.

- 분류 Sequence 수
- 회귀 Sequence 수
- NOx 및 SO₂별 Sequence 수
- Sequence 생성 과정에서 제외된 데이터 수

위 항목을 별도로 집계하는 것이 좋다.

### 7.5 Scaling

LSTM은 입력 Feature별 값의 범위 차이가 학습에 영향을 줄 수 있으므로 Scaling을 권장한다.

- Train 데이터로만 Scaler Fit
- Validation/Test는 Train에서 생성한 Scaler로 Transform
- Label은 입력 Feature와 별도로 처리
- 데이터 분리 전에 전체 데이터를 대상으로 Scaler를 Fit하지 않도록 주의

## 10. 종합 검토 의견

현재 확보된 약 1,764만 건의 ML-ready 데이터는 TMS 배출비율 예측 모델을 실험하기에 의미 있는 규모이다.

분류 학습 가능 데이터는 약 986만 건, 회귀 학습 가능 데이터는 약 1,069만 건으로 Random Forest와 XGBoost 모델을 우선 적용하여 성능을 비교할 수 있다.

분류 모델은 양성 데이터 비율이 약 1.36%로 낮기 때문에 단순 정확도보다는 Recall, Precision, PR-AUC를 중심으로 평가해야 한다.

또한 분류 Label은 현재 배출비율이 90% 미만인 경우에 한해 향후 60분 이내 위험 기준 진입 여부를 판단하도록 일관되게 적용해야 한다. 특히 미래 측정값이 일부 누락된 경우 이를 무조건 음성으로 처리하지 않도록 주의해야 한다.

LSTM은 Window Size 6을 적용한 후 실제 Sequence 수를 확인해야 하며, 시간 순서와 연속성이 유지되는 데이터로 학습해야 한다.

**최종적으로 Random Forest와 XGBoost를 기본 비교 모델로 구성하고, LSTM을 추가하여 시계열 패턴 학습 효과를 비교하는 방향을 권장한다.**
