# 시간 블록 Bootstrap 쉽게 이해하기

## 1. 시간 블록 Bootstrap이란?

시간 블록 Bootstrap(Time Block Bootstrap)은 **시간 순서가 있는 데이터를
일정한 시간 구간으로 묶은 다음, 그 구간을 반복해서 추출하여 모델 성능의
안정성을 확인하는 방법**입니다.

TMS 데이터는 30분 간격으로 연속 수집됩니다. 인접한 시간의 농도는 서로
비슷하거나 연속적인 패턴을 보일 수 있습니다. 예를 들어 NOx 농도가 10시
30분에 상승했다면 11시와 11시 30분에도 상승 상태가 이어질 수 있습니다.

일반 Bootstrap은 개별 행을 무작위로 추출하지만, 시간 블록 Bootstrap은
연속된 시간 구간을 하나의 묶음으로 추출합니다.

**핵심:** 시간 블록 Bootstrap은 시계열 데이터의 시간적 연속성을 어느
정도 유지하면서 여러 평가 표본을 만드는 방법입니다.

## 2. 일반 Bootstrap과 시간 블록 Bootstrap 비교

  구분            일반 Bootstrap              시간 블록 Bootstrap
  --------------- --------------------------- ---------------------
  추출 단위       개별 데이터 행              연속된 시간 구간
  시간 순서       섞일 수 있음                블록 내부 순서 유지
  시계열 연속성   반영하기 어려움             어느 정도 반영
  TMS 적용        주 평가 방법으로는 비추천   추천

예를 들어 30분 단위 데이터에서 2시간 블록은 연속된 4개 관측값으로
구성됩니다.

  블록 예시   포함 시간        관측값 수
  ----------- -------------- -----------
  A           09:00\~10:30           4개
  B           09:30\~11:00           4개
  C           10:00\~11:30           4개

위 예시는 블록 구성 개념을 설명하기 위한 것입니다. 실제 구현에서는 관측
간격이 일정한지 먼저 확인해야 합니다.

## 3. TMS 프로젝트에 왜 필요한가?

이번 프로젝트에서는 RF와 XGBoost 분류모형을 비교합니다. 최종 Test 평가를
하면 Precision, Recall, FPR, F2-Score를 계산할 수 있습니다.

하지만 한 번 계산한 점수만으로는 그 성능 차이가 얼마나 안정적인지 알기
어렵습니다.

시간 블록 Bootstrap을 적용하면 다음을 확인할 수 있습니다.

1.  RF의 성능이 시간 구간에 따라 얼마나 달라지는가?
2.  XGBoost의 성능은 얼마나 안정적인가?
3.  두 모델의 F2-Score 차이가 여러 표본에서도 유지되는가?
4.  모델 간 성능 차이의 95% 신뢰구간은 어느 정도인가?

즉, **한 번의 Test 평가에만 의존하지 않고, 여러 시간 구간 표본에서도
모델 간 성능 차이가 일관적인지 확인**할 수 있습니다.

## 4. 어떤 시간 블록 방식을 사용할까?

  -----------------------------------------------------------------------
  방식                    설명                    TMS 적용 의견
  ----------------------- ----------------------- -----------------------
  일반 Bootstrap          개별 행을 무작위 추출   시계열 주 평가에는
                                                  비추천

  Moving Block            겹칠 수 있는 연속 블록  우선 추천
  Bootstrap(MBB)          추출                    

  Non-overlapping Block   겹치지 않는 블록 추출   비교용
  Bootstrap                                       

  Stationary Bootstrap    블록 길이를 확률적으로  확장 검토
                          결정                    
  -----------------------------------------------------------------------

이번 프로젝트에서는 **Moving Block Bootstrap(MBB)**부터 적용하는 것을
권장합니다. MBB는 연속된 블록을 추출하되 블록끼리 겹치는 것을
허용합니다.

## 5. 블록 길이는 어떻게 정할까?

TMS 데이터는 30분 단위이므로 다음과 같이 블록 길이를 정할 수 있습니다.

  블록 길이     관측값 수 실제 시간
  ----------- ----------- -----------
  2시간               4개 4 × 30분
  4시간               8개 8 × 30분
  6시간              12개 12 × 30분
  12시간             24개 24 × 30분
  24시간             48개 48 × 30분

초기 실험에서는 **4시간, 6시간, 12시간 블록**을 비교하는 것을
제안합니다.

이 값이 최적이라고 미리 정해진 것은 아닙니다. 실제 데이터의 자기상관,
이상 상태의 지속시간, 일중 패턴 등을 확인해 결정해야 합니다. 미래
30분·60분을 기준으로 라벨을 생성한다는 점도 고려해야 합니다.

## 6. TMS 프로젝트 적용 절차

시간 블록 Bootstrap은 모델을 매번 다시 학습하는 과정이 아닙니다. 이미
확정된 모델의 최종 Test 예측 결과를 이용해 성능의 불확실성을 평가합니다.

### 1단계. 최종 Test 결과 준비

각 관측값에 다음 정보가 있어야 합니다.

-   측정 시간
-   굴뚝 코드(`stack_code`)
-   측정 항목(`item_code`: NOx 또는 SO₂)
-   실제 정답 라벨
-   RF 예측 결과
-   XGBoost 예측 결과

RF와 XGBoost의 결과는 동일한 Test 관측값에 대응해야 합니다.

### 2단계. 시간순 정렬 및 블록 구성

측정 항목과 굴뚝을 고려해 데이터를 정렬합니다. 30분 단위라면 8개
관측값을 하나의 4시간 블록으로 구성할 수 있습니다.

결측 시간이나 관측 간격이 불규칙한 구간을 무조건 연속 블록으로 취급하지
않도록 주의합니다.

### 3단계. 블록 단위 복원 추출

구성된 블록 중 일부를 복원 추출하여 Bootstrap 표본을 만듭니다. 복원
추출은 한 번 선택한 블록이 다음 추출에서 다시 선택될 수 있다는 뜻입니다.

### 4단계. 평가 지표 계산

각 표본에서 다음 지표를 계산합니다.

  지표        의미                                     좋은 방향
  ----------- ---------------------------------------- ---------------
  Precision   이상이라고 예측한 것 중 실제 이상 비율   높을수록 좋음
  Recall      실제 이상 중 모델이 찾아낸 비율          높을수록 좋음
  FPR         실제 정상 중 이상으로 잘못 예측한 비율   낮을수록 좋음
  F2-Score    Recall에 더 큰 가중치를 둔 종합 점수     높을수록 좋음

### 5단계. 반복 수행 및 신뢰구간 계산

초기 설정으로 1,000\~2,000회 반복을 제안합니다. 각 반복의 지표 분포를
이용해 95% 신뢰구간을 계산합니다.

양성 사례가 전혀 포함되지 않아 Recall이나 F2를 계산할 수 없는 표본이
발생할 수 있으므로, 반복별 양성 사례 수와 유효 평가 횟수도 기록해야
합니다.

### 6단계. RF와 XGBoost의 성능 차이 비교

각 반복에서 RF와 XGBoost에 **동일한 시간 블록을 적용**해야 합니다.

예를 들어 매 반복에서 다음 차이를 계산합니다.

`성능 차이 = XGBoost F2-Score - RF F2-Score`

이 차이의 95% 신뢰구간을 확인합니다.

-   신뢰구간이 0보다 큰 범위에 있으면 XGBoost의 F2-Score가 더 높다는
    근거가 됩니다.
-   신뢰구간이 0을 포함하면 성능 차이가 명확하다고 보기 어렵습니다.
-   신뢰구간이 0보다 작은 범위에 있으면 RF의 F2-Score가 더 높다는 근거가
    됩니다.

통계적 차이뿐 아니라 오경보 비용과 이상 누락 위험도 함께 고려해야
합니다.

## 7. TMS 데이터에서 특별히 주의할 점

### ① NOx와 SO₂를 구분해서 평가

NOx와 SO₂는 데이터 분포와 이상 발생 패턴이 다를 수 있습니다. 따라서
NOx와 SO₂의 결과를 각각 산출하는 것을 권장합니다. 전체 데이터를 합친
점수만 제시하면 특정 항목의 성능 저하가 가려질 수 있습니다.

### ② 굴뚝별 시계열 구조 고려

현재 데이터는 `stack_code × item_code × 30분` 단위입니다.

서로 다른 굴뚝의 데이터를 시간순으로 단순 연결해 하나의 시계열처럼
블록을 만들면 안 됩니다. 굴뚝별 시계열을 따로 평가할지, 여러 굴뚝의 같은
시간대를 함께 추출할지 분석 목적에 맞게 정해야 합니다.

여러 굴뚝이 같은 시간대의 공통 영향을 받을 수 있다면 동일 시간 블록을
함께 추출하는 방식도 고려합니다.

### ③ 양성 데이터가 충분한지 확인

TMS 데이터는 정상 데이터에 비해 이상 데이터가 적습니다. Bootstrap 표본에
이상 사례가 충분히 포함되지 않으면 Recall과 F2-Score가 불안정하거나
계산되지 않을 수 있습니다.

반복별로 전체 표본 수, 실제 이상 수, 실제 정상 수, 지표 계산 가능 여부를
기록합니다. 시간적 연속성을 깨뜨리는 행 단위 양성·음성 층화 추출을
무조건 적용해서는 안 됩니다.

### ④ Test 데이터는 학습에 다시 사용하지 않기

Bootstrap은 최종 Test 예측 결과를 반복 추출해 평가하는 과정입니다.
따라서 매 반복마다 모델을 다시 학습하지 않습니다.

Bootstrap 결과를 보고 모델이나 임계값을 수정하면 최종 Test의 독립
평가라는 의미가 약해집니다.

## 8. Python 구현 흐름 예시

다음은 실제 구현의 전체 흐름을 이해하기 위한 의사 코드입니다.

``` python
for bootstrap_iteration in range(2000):

    # 1. 시간 블록을 복원 추출
    sampled_blocks = sample_time_blocks(
        test_data,
        block_size=8
    )

    # 2. 추출한 블록을 평가 표본으로 구성
    bootstrap_data = combine_blocks(sampled_blocks)

    # 3. RF와 XGBoost에 동일한 표본 적용
    rf_score = evaluate_classifier(
        bootstrap_data["y_true"],
        bootstrap_data["rf_pred"]
    )

    xgb_score = evaluate_classifier(
        bootstrap_data["y_true"],
        bootstrap_data["xgb_pred"]
    )

    # 4. 모델 간 성능 차이 저장
    score_difference = (
        xgb_score["F2"] - rf_score["F2"]
    )
```

※ `sample_time_blocks`, `combine_blocks`, `evaluate_classifier`는 설명을
위한 가상 함수입니다. 실제 구현에서는 굴뚝별 시계열, 결측 시간, 블록
경계, 양성 사례 부족 등을 반영해야 합니다.

활용할 주요 라이브러리는 다음과 같습니다.

  라이브러리     활용
  -------------- ---------------------------------------------
  NumPy          블록 인덱스 생성 및 복원 추출
  Pandas         시간순 정렬 및 굴뚝·측정 항목별 데이터 관리
  scikit-learn   Precision, Recall, FPR, F2-Score 계산
  SciPy          통계량 및 신뢰구간 계산

## 9. 최종 결과 보고서 구성

### 모델별 성능과 신뢰구간

  평가 지표   RF               XGBoost
  ----------- ---------------- ----------------
  Recall      점수 및 95% CI   점수 및 95% CI
  Precision   점수 및 95% CI   점수 및 95% CI
  FPR         점수 및 95% CI   점수 및 95% CI
  F2-Score    점수 및 95% CI   점수 및 95% CI

### 모델 간 성능 차이

  비교 항목          결과
  ------------------ -----------------------------
  F2-Score 차이      XGBoost - RF
  95% 신뢰구간       Bootstrap으로 계산
  블록 길이별 결과   4시간 / 6시간 / 12시간
  최종 해석          성능 차이의 방향과 불확실성

블록 길이에 따라 결론이 크게 달라지는지도 확인합니다. 특정 블록
길이에서만 한 모델이 우수하다면 그 결과를 일반적인 우위로 단정하지
않습니다.

## 10. TMS 프로젝트 최종 검증 흐름

1.  **모델 선정 및 임계값 확정:** Train / Validation 데이터로 RF와
    XGBoost를 비교하고 임계값을 결정합니다.
2.  **최종 Test 평가:** 확정된 모델과 임계값으로 미사용 Test 데이터를
    평가합니다.
3.  **시간 블록 Bootstrap:** Test 예측 결과를 대상으로 모델별 성능의 95%
    신뢰구간과 성능 차이를 분석합니다.
4.  **McNemar 검정:** 동일 Test 데이터에서 두 모델의 정답·오답 패턴을
    보조적으로 비교합니다.
5.  **최종 모델 선정:** 예측 성능, 오경보 수준, 통계적 불확실성을 함께
    고려합니다.

McNemar 검정은 이진 정답·오답 패턴을 비교하는 방법입니다. 시간적
자기상관이 있는 TMS 데이터에서는 독립성 가정에 주의해야 하므로, 시간
블록 Bootstrap을 주요 통계 검증으로 활용하고 McNemar는 보조 분석으로
해석하는 것이 좋습니다.

## 핵심 정리

-   시간 블록 Bootstrap은 연속된 시간 구간을 묶어 재표본을 만드는
    방법입니다.
-   TMS처럼 30분 단위로 수집되는 시계열 데이터에 적합한 검증 방법입니다.
-   RF와 XGBoost에는 반드시 동일한 Bootstrap 시간 블록을 적용합니다.
-   초기에는 4시간, 6시간, 12시간 블록을 비교하고 실제 데이터의 시간적
    특성을 바탕으로 결정합니다.
-   Bootstrap으로 모델별 성능의 95% 신뢰구간과 두 모델 간 성능 차이를
    확인합니다.
-   Bootstrap은 모델을 다시 학습하는 과정이 아니며, 최종 Test 결과의
    독립성을 유지해야 합니다.

> **멘티에게 한 문장으로 설명하기**
>
> 시간 블록 Bootstrap은 TMS 데이터를 시간 구간별로 묶어 여러 번 다시
> 평가함으로써, RF와 XGBoost 중 어느 모델의 성능이 더 안정적인지
> 확인하는 통계적 검증 방법입니다.
