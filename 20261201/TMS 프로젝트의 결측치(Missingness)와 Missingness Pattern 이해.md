# TMS 프로젝트의 결측치(Missingness)와 Missingness Pattern 이해

## 1. 결측치(Missingness)란?

결측치(Missingness)는 데이터가 수집되어야 하는 시점에 실제 측정값이 존재하지 않는 상태를 의미합니다.

일반적인 데이터 분석에서는 결측치를 비어 있는 값으로 생각하고 제거하거나 평균값 등으로 대체하는 경우가 많습니다.

하지만 TMS(Tele-Monitoring System)에서는 조금 다르게 접근해야 합니다.

굴뚝에서 NOx, SO2 등의 배출량을 30분 단위로 측정한다고 가정해 보겠습니다.

정상적으로 측정되었다면 다음과 같은 데이터가 수집됩니다.

| 측정 시간 | NOx | SO2 |
|---|---:|---:|
| 09:00 | 35.2 | 12.4 |
| 09:30 | 37.1 | 13.0 |
| 10:00 | 39.5 | 14.2 |
| 10:30 | NULL | 15.1 |
| 11:00 | NULL | NULL |
| 11:30 | 42.3 | 16.0 |

위 데이터에서 10:30에는 NOx만 결측되었고, 11:00에는 NOx와 SO2가 모두 결측되었습니다.

여기서 중요한 것은 단순히 값이 없다는 사실이 아닙니다.

- NOx 측정기만 문제가 발생했을까요?
- 굴뚝 전체의 측정 데이터가 수집되지 않은 것일까요?
- 통신 장애가 발생했을까요?
- 측정기 점검이나 설비 비가동 상태였을까요?
- 특정 시간대에 반복적으로 발생하는 현상일까요?

이처럼 결측이 발생한 원인과 패턴을 함께 분석하는 것이 중요합니다.

## 2. Missingness와 Missingness Pattern의 차이

두 용어는 구분해서 이해해야 합니다.

### 2.1 Missingness

개별 데이터가 결측된 상태 자체를 의미합니다.

예를 들어 다음과 같습니다.

```text
2026-11-26 10:30
NOx = NULL
```

특정 시점의 NOx 측정값이 존재하지 않는다는 의미입니다.

### 2.2 Missingness Pattern

결측이 어떤 규칙이나 형태로 발생하는지를 의미합니다.

예를 들어 다음과 같습니다.

```text
09:00  정상
09:30  정상
10:00  정상
10:30  결측
11:00  결측
11:30  결측
12:00  정상
```

이 경우 10:30부터 11:30까지 연속적으로 결측이 발생했습니다.

단순히 결측 데이터 3건이 발생했다는 것보다 다음과 같은 정보를 얻을 수 있습니다.

- 결측이 시작된 시간
- 결측이 지속된 시간
- 연속적으로 발생했는지
- 특정 측정 항목에서만 발생했는지
- 여러 측정 항목에서 동시에 발생했는지
- 특정 굴뚝이나 설비에서 반복되는지

즉, Missingness Pattern은 **결측이 발생하는 방식과 반복되는 구조를 분석하는 관점**입니다.

## 3. TMS 프로젝트에서 발생할 수 있는 결측 유형

TMS 데이터에서는 결측이 발생했다고 해서 모두 동일한 의미로 처리하면 안 됩니다.

실제 프로젝트에서는 원천 데이터의 상태 코드와 설비 운영 이력을 확인하여 결측 원인을 구분해야 합니다.

### 3.1 설비 비가동에 따른 결측

공장이 가동되지 않거나 굴뚝 설비가 운전하지 않는 경우 측정값이 존재하지 않을 수 있습니다.

예시:

| 시간 | NOx | 설비 상태 |
|---|---:|---|
| 09:00 | 35.2 | 가동 |
| 09:30 | 37.1 | 가동 |
| 10:00 | NULL | 비가동 |
| 10:30 | NULL | 비가동 |
| 11:00 | 38.5 | 가동 |

이 경우 결측은 반드시 센서 오류를 의미하지 않습니다.

설비가 정상적으로 비가동 상태에 들어갔기 때문에 측정값이 없는 것일 수 있습니다.

**분석 관점**

- 특정 설비의 비가동 시간이 반복되는가?
- 비가동 전후 배출량은 어떤 변화를 보이는가?
- 비가동 상태가 전체 결측의 어느 정도를 차지하는가?

### 3.2 측정기 점검 및 교정에 따른 결측

NOx 또는 SO2 측정기를 점검하거나 교정하는 동안 측정값이 수집되지 않을 수 있습니다.

| 시간 | NOx | 측정기 상태 |
|---|---:|---|
| 09:00 | 35.2 | 정상 |
| 09:30 | 37.1 | 정상 |
| 10:00 | NULL | 점검 |
| 10:30 | NULL | 점검 |
| 11:00 | 38.5 | 정상 |

이 경우 결측은 측정기 유지보수와 관련된 현상일 수 있습니다.

**분석 관점**

- 점검이 주기적으로 발생하는가?
- 점검 시간이 일정한가?
- 특정 측정기에서 점검이 빈번하게 발생하는가?
- 점검 종료 후 측정값이 정상적으로 복구되는가?

### 3.3 통신 장애에 따른 결측

측정 장비에서는 값이 생성되었지만 서버 또는 수집 시스템으로 전달되지 못하는 경우입니다.

| 시간 | NOx | 통신 상태 |
|---|---:|---|
| 09:00 | 35.2 | 정상 |
| 09:30 | 37.1 | 정상 |
| 10:00 | NULL | 통신 장애 |
| 10:30 | NULL | 통신 장애 |
| 11:00 | 38.5 | 정상 |

이 경우 측정기 자체는 정상일 수도 있습니다.

따라서 측정기 오류와 통신 장애를 구분해야 합니다.

**분석 관점**

- 특정 시간대에 통신 장애가 집중되는가?
- 특정 굴뚝이나 수집 장비에서 반복되는가?
- NOx와 SO2가 동시에 누락되는가?
- 통신 복구 이후 데이터가 정상적으로 수집되는가?

### 3.4 특정 측정 항목에서만 발생하는 결측

NOx와 SO2 중 특정 항목의 측정값만 누락되는 경우입니다.

| 시간 | NOx | SO2 |
|---|---:|---:|
| 09:00 | 35.2 | 12.4 |
| 09:30 | 37.1 | 13.0 |
| 10:00 | NULL | 14.2 |
| 10:30 | NULL | 15.1 |
| 11:00 | 42.3 | 16.0 |

이 경우 전체 설비의 문제가 아니라 NOx 측정기 또는 해당 데이터 수집 경로의 문제일 가능성을 살펴볼 수 있습니다.

**분석 관점**

- 특정 측정 항목에서 결측이 집중되는가?
- 다른 항목은 정상적으로 수집되는가?
- 특정 측정기 또는 센서에 문제가 반복되는가?

## 4. 결측 데이터 발생 유형: MCAR, MAR, MNAR

머신러닝과 통계 분석에서는 결측이 발생하는 특성을 크게 세 가지로 구분합니다.

이 구분은 결측 원인을 이해하고 처리 방법을 결정하는 데 도움이 됩니다.

### 4.1 MCAR (Missing Completely At Random)

완전 무작위 결측입니다.

다른 데이터 값이나 관측된 변수와 관계없이 우연히 결측이 발생하는 경우입니다.

**TMS 사례**

- 일시적인 수집 시스템 오류
- 우연히 발생한 데이터 전송 누락
- 특정 조건과 관련성이 확인되지 않는 일회성 결측

예를 들어 특정 굴뚝의 NOx 값이 우연한 통신 오류로 한 번 누락되었다면 MCAR 가능성을 검토할 수 있습니다.

### 4.2 MAR (Missing At Random)

관측 가능한 다른 변수와 관련되어 결측이 발생하는 경우입니다.

**TMS 사례**

- 특정 설비 상태에서 결측이 집중됨
- 특정 시간대에 통신 장애가 자주 발생함
- 특정 굴뚝에서 점검 시간이 반복됨

예를 들어 설비 상태 코드가 '점검'인 경우 NOx 측정값이 누락되는 현상이 반복된다면, 관측 가능한 설비 상태와 결측의 관계를 확인할 수 있습니다.

### 4.3 MNAR (Missing Not At Random)

결측이 발생한 값 자체 또는 관측되지 않은 요인과 관련된 경우입니다.

**TMS 사례로 생각해 볼 수 있는 가설**

- 특정 배출량 수준에서 측정값 누락이 더 자주 발생하는가?
- 실제 측정값이 높아지는 상황과 결측 발생 사이에 관계가 있는가?
- 측정값이 관측되지 않는 원인이 측정값 자체와 연관되어 있는가?

다만 결측 직전에 NOx가 상승했다는 사실만으로 MNAR이라고 단정할 수는 없습니다.

실제 측정값과 결측 발생 원인 사이의 관계를 확인할 수 있는 추가 데이터와 근거가 필요합니다.

### 4.4 세 가지 유형 비교

| 구분 | 결측 발생 특성 | TMS 사례 |
|---|---|---|
| MCAR | 다른 변수와 관계없이 무작위 발생 | 우연한 일회성 데이터 누락 |
| MAR | 관측 가능한 변수와 관련 | 설비 점검, 특정 시간대 통신 장애 |
| MNAR | 미관측 값 또는 관련 미관측 요인과 관련 | 실제 배출량 수준과 결측 발생의 관계가 의심되는 상황 |

주의할 점은 실제 TMS 데이터의 결측이 MCAR, MAR, MNAR 중 하나로 명확하게 분류되지 않을 수도 있다는 것입니다.

결측 원인을 알 수 없는 경우에는 무리하게 유형을 지정하지 않고 미확인 상태로 관리하는 것이 좋습니다.

## 5. Missingness Pattern을 분석하면 무엇을 알 수 있을까?

TMS 프로젝트에서는 결측 건수만 집계하는 것보다 결측이 발생하는 형태를 분석하는 것이 중요합니다.

다음과 같은 분석 관점을 생각해 볼 수 있습니다.

### 5.1 결측 발생 빈도

특정 굴뚝이나 측정 항목에서 결측이 얼마나 자주 발생하는지 확인합니다.

예시:

| 굴뚝 | 측정 항목 | 전체 건수 | 결측 건수 | 결측률 |
|---|---|---:|---:|---:|
| STACK-01 | NOx | 1,000 | 20 | 2.0% |
| STACK-01 | SO2 | 1,000 | 10 | 1.0% |
| STACK-02 | NOx | 1,000 | 150 | 15.0% |
| STACK-02 | SO2 | 1,000 | 140 | 14.0% |

위 결과에서는 STACK-02의 NOx와 SO2에서 결측률이 모두 높습니다.

이 경우 특정 측정기 하나의 문제인지, 공통 수집 장비나 통신 경로의 문제인지 추가로 확인할 필요가 있습니다.

### 5.2 연속 결측 시간

결측이 한 번 발생하고 끝나는지, 일정 시간 동안 계속되는지 확인합니다.

예시:

```text
10:00 정상
10:30 결측
11:00 결측
11:30 결측
12:00 결측
12:30 정상
```

이 경우 10:30부터 12:00까지 4회 연속 결측이 발생했습니다.

30분 단위 데이터이므로 연속 결측 횟수와 지속 시간을 함께 계산할 수 있습니다.

| 결측 시작 | 결측 종료 | 연속 결측 횟수 | 지속 시간 |
|---|---|---:|---:|
| 10:30 | 12:00 | 4회 | 2시간 |

이러한 정보는 일시적인 누락과 장시간 지속되는 문제를 구분하는 데 유용합니다.

### 5.3 동시 결측 여부

NOx와 SO2가 같은 시간에 함께 누락되는지 확인합니다.

| 시간 | NOx | SO2 | 결측 형태 |
|---|---|---|---|
| 09:00 | 정상 | 정상 | 정상 |
| 09:30 | 결측 | 정상 | NOx 단독 결측 |
| 10:00 | 정상 | 결측 | SO2 단독 결측 |
| 10:30 | 결측 | 결측 | 동시 결측 |

동시 결측이 반복된다면 개별 측정기 문제뿐 아니라 공통 수집 시스템이나 통신 상태와의 관계도 살펴볼 수 있습니다.

### 5.4 결측 발생 전후의 배출량 변화

결측이 발생하기 직전과 복구된 이후의 NOx, SO2 값을 비교합니다.

예시:

| 시간 | NOx | 상태 |
|---|---:|---|
| 09:00 | 35 | 정상 |
| 09:30 | 42 | 정상 |
| 10:00 | 55 | 정상 |
| 10:30 | NULL | 결측 |
| 11:00 | NULL | 결측 |
| 11:30 | 48 | 정상 |

이 경우 결측 직전 NOx가 상승한 것을 확인할 수 있습니다.

다만 이것만으로 배출량 상승이 결측의 원인이라고 판단하면 안 됩니다.

측정기 점검, 설비 운전 상태, 통신 장애 등 다른 원인이 있을 수 있습니다.

따라서 결측 전후의 배출량 변화는 원인을 단정하는 근거가 아니라 추가 분석이 필요한 후보 정보로 활용해야 합니다.

### 5.5 시간대 및 요일별 결측

결측이 특정 시간대나 요일에 집중되는지 분석합니다.

예시:

- 매일 새벽 02:00~03:00에 결측이 반복됨
- 주말에 특정 굴뚝의 결측이 증가함
- 특정 날짜에 여러 굴뚝의 결측이 동시에 발생함

이러한 패턴은 설비 운전 일정, 정기 점검, 수집 시스템 작업 등과 연관되어 있을 수 있습니다.

## 6. TMS 프로젝트에서 Missingness Pattern을 어떻게 활용할까?

결측 패턴은 단순히 데이터 전처리를 위한 정보가 아닙니다.

TMS 프로젝트에서는 데이터 품질 관리와 설비 운영 상태 분석에 활용할 수 있습니다.

### 6.1 데이터 품질 관리

결측률과 연속 결측 시간을 관리하면 데이터 수집 상태를 파악할 수 있습니다.

예를 들어 다음과 같은 관리 기준을 생각해 볼 수 있습니다.

| 관리 항목 | 분석 내용 |
|---|---|
| 결측률 | 굴뚝별, 측정 항목별 결측 비율 |
| 연속 결측 | 연속적으로 누락된 측정 횟수 |
| 동시 결측 | NOx와 SO2의 동시 누락 여부 |
| 결측 발생 시간 | 특정 시간대 집중 여부 |
| 복구 시간 | 결측 발생부터 정상 수집까지 걸린 시간 |

이 정보를 통해 데이터 수집 상태를 지속적으로 확인할 수 있습니다.

### 6.2 설비 운영 상태 분석

결측이 설비 비가동, 측정기 점검, 통신 장애 등과 관련되어 있다면 설비 운영 이력과 함께 분석할 수 있습니다.

예를 들어 특정 굴뚝에서 측정기 점검이 반복적으로 발생한다면 점검 이력과 결측 발생 빈도를 비교할 수 있습니다.

단, 결측만으로 설비 상태를 추정하기보다는 실제 상태 코드와 운영 이력을 우선적으로 활용해야 합니다.

### 6.3 배출량 변화와 결측의 관계 분석

결측 발생 직전과 직후의 배출량을 비교하면 결측이 특정 배출량 변화와 함께 나타나는지 확인할 수 있습니다.

예를 들어 다음과 같은 질문을 만들 수 있습니다.

- NOx가 급격하게 상승한 이후 결측이 자주 발생하는가?
- 특정 굴뚝에서 배출량 변동이 클 때 결측도 증가하는가?
- 결측 이후 측정값이 복구되었을 때 이전과 다른 배출량 패턴이 나타나는가?

이러한 관계는 분석을 통해 검증해야 하며, 단순한 시간적 선후 관계를 인과관계로 해석해서는 안 됩니다.

---

## 7. 기존 TMS 머신러닝 학습 데이터와의 관계

여기서 중요한 것은 결측 패턴 분석과 배출량 예측 모델의 학습 데이터를 구분하는 것입니다.

현재 프로젝트는 NOx, SO2의 미래 30분 또는 60분 후 기준치 초과 가능성을 예측하는 것이 목적입니다.

따라서 결측 데이터를 모두 학습에 포함하거나 무조건 삭제하는 방식은 적절하지 않습니다.

### 7.1 결측 데이터 유형별 처리 방향

| 데이터 유형 | 배출량 예측 모델 학습 | 별도 분석 |
|---|---|---|
| 정상 측정 데이터 | 유효 Label이면 포함 | 정상 패턴 분석 |
| 설비 비가동 | 원칙적으로 제외 | 설비 운영 상태 분석 |
| 측정기 점검 | 원칙적으로 제외 | 점검 및 결측 패턴 분석 |
| 통신 장애 | 원칙적으로 제외 | 통신 장애 패턴 분석 |
| 측정 오류 | 검증 후 제외 또는 별도 처리 | 데이터 품질 분석 |
| 실제 결측 | 측정값 기반 학습에서 제외 | Missingness Pattern 분석 |
| 실제 배출량 급증 | 유효한 측정값과 Label이면 포함 가능 | Outlier 및 Anomaly 관점 분석 |

핵심은 결측 데이터가 배출량 예측 모델에 적합하지 않다고 해서 분석 가치까지 없는 것은 아니라는 점입니다.

### 7.2 결측 패턴을 Feature로 활용할 수 있을까?

가능합니다.

다만 결측 자체를 무조건 Feature로 추가하기보다는 예측 시점에 실제로 알 수 있는 정보를 활용해야 합니다.

예를 들어 다음과 같은 Feature를 생각할 수 있습니다.

| Feature | 의미 |
|---|---|
| `nox_missing_flag` | NOx 결측 여부 |
| `so2_missing_flag` | SO2 결측 여부 |
| `missing_count_3` | 최근 3개 구간의 결측 횟수 |
| `consecutive_missing_count` | 연속 결측 횟수 |
| `last_valid_elapsed_minutes` | 마지막 정상 측정 이후 경과 시간 |

이러한 Feature는 결측 패턴과 예측 결과의 관계를 분석하는 데 활용할 수 있습니다.

그러나 주의해야 할 점이 있습니다.

1. 예측 시점에 이미 확인할 수 있는 정보만 Feature로 사용해야 합니다.
2. 미래에 발생한 결측 정보를 현재 Feature로 사용하면 데이터 누수가 발생합니다.
3. 결측 상태가 설비 비가동이나 통신 장애를 의미한다면 배출량 예측보다 운영 상태 판단에 더 적합할 수 있습니다.
4. 결측 여부를 Feature로 추가했을 때 실제로 예측 성능이 개선되는지 시간 순서에 따른 테스트 데이터로 검증해야 합니다.

현재 프로젝트에서는 우선 결측 패턴을 별도 분석하고, 그 결과를 바탕으로 Feature 활용 여부를 결정하는 것을 권장합니다.

---

## 8. TMS 프로젝트에서 권장하는 결측 분석 구조

결측 데이터를 하나의 NULL 값으로만 관리하기보다는 원천 상태와 분석 결과를 구분하는 것이 좋습니다.

```text
                 [TMS 원천 데이터]
                         |
                         v
                 [결측 여부 확인]
                         |
                         v
                [결측 원인 및 상태 확인]
                         |
          +--------------+--------------+
          |              |              |
          v              v              v
      설비 비가동      측정기 점검      통신 장애
          |              |              |
          +--------------+--------------+
                         |
                         v
                [Missingness Pattern]
                         |
          +--------------+--------------+
          |              |              |
          v              v              v
       결측률 분석     연속 결측 분석    동시 결측 분석
          |              |              |
          +--------------+--------------+
                         |
                         v
                [결측 패턴 분석 결과]
                         |
          +--------------+--------------+
          |                             |
          v                             v
   데이터 품질 관리               설비 운영 상태 분석
          |
          v
   [머신러닝 학습 데이터 구성]
          |
          v
   유효 측정값 및 Label 확인
          |
          v
   [NOx / SO2 미래 위험 예측]
```

위 구조는 결측 원인을 확인하고 분석 결과를 활용하는 개념적인 흐름입니다.

실제 구현에서는 결측 원인을 알 수 없는 데이터도 별도로 관리해야 합니다. 원인을 확인하지 못한 데이터를 임의로 통신 장애나 설비 비가동으로 분류하면 안 됩니다.

## 9. 멘티들이 꼭 이해해야 할 핵심 사항

1. **Missingness는 데이터가 존재하지 않는 상태이고, Missingness Pattern은 결측이 발생하는 방식과 반복되는 구조를 분석하는 관점입니다.**

2. TMS에서는 설비 비가동, 측정기 점검, 통신 장애, 측정 오류 등 결측의 원인이 서로 다를 수 있습니다.

3. 결측이 발생했다고 무조건 삭제하거나 평균값으로 대체해서는 안 됩니다. 먼저 원천 상태와 결측 원인을 확인해야 합니다.

4. 결측이 발생한 시간, 지속 시간, 반복 주기, 동시 결측 여부 등을 분석하면 데이터 품질과 설비 운영 상태를 이해하는 데 도움이 됩니다.

5. 결측 직전 배출량이 상승했다고 해서 배출량 상승이 결측의 원인이라고 단정해서는 안 됩니다.

6. 결측 데이터가 배출량 예측 모델의 학습 대상에서 제외되더라도 Missingness Pattern 분석에는 활용할 가치가 있습니다.

7. 결측 패턴을 Feature로 활용할 수 있지만, 예측 시점에 확인 가능한 정보만 사용해야 하며 데이터 누수를 주의해야 합니다.

---

## 10. 최종 정리

TMS 프로젝트에서 결측치는 단순히 제거해야 하는 데이터가 아닙니다.

결측이 발생한 원인과 패턴을 분석하면 데이터 수집 시스템의 품질, 측정기 상태, 설비 운영 이력 등을 이해하는 데 도움이 됩니다.

특히 다음 세 가지 관점을 구분하는 것이 중요합니다.

| 분석 관점 | 핵심 질문 |
|---|---|
| 결측 데이터 분석 | 어떤 측정값이 누락되었는가? |
| Missingness Pattern 분석 | 언제, 얼마나 오래, 어떤 규칙으로 누락되는가? |
| 결측 원인 분석 | 왜 해당 시점에 측정값이 누락되었는가? |

**멘티들에게 전달할 핵심 메시지**

> 결측치는 단순히 비어 있는 데이터가 아닙니다. TMS에서는 결측이 발생한 시간과 반복 패턴 자체가 설비 운영 상태와 데이터 수집 품질을 이해하는 중요한 정보가 될 수 있습니다. 따라서 결측값을 무조건 제거하기 전에 왜 발생했는지, 어떤 형태로 반복되는지부터 분석해야 합니다.
