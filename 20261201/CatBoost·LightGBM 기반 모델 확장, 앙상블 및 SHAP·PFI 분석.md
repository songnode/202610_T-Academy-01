# TMS 프로젝트: CatBoost·LightGBM 기반 모델 확장, 앙상블 및 SHAP·PFI 분석

## 1. 문서 목적

이번 실험의 목적은 기존 TMS AI 사전 경고 모델에 CatBoost와 LightGBM을 추가하고, 다양한 머신러닝 모델의 성능을 비교하여 TMS 데이터에 적합한 모델을 선정하는 것입니다.

단순히 예측 성능이 높은 모델을 찾는 것에 그치지 않고, 앙상블을 통한 성능 개선 가능성과 SHAP 및 PFI를 활용한 모델 설명 가능성까지 검증합니다.

주요 목표는 다음과 같습니다.

1. CatBoost와 LightGBM을 추가하여 기존 모델과 성능 비교
2. NOx와 SO2의 통합 모델 및 개별 모델 비교
3. 앙상블을 적용하여 예측 성능 개선 가능성 검증
4. SHAP을 활용하여 개별 예측 결과와 전체 Feature 영향도 분석
5. PFI를 활용하여 모델 성능에 기여하는 Feature 중요도 분석
6. Feature 선정 및 제거 실험을 통한 모델 최적화
7. 예측 성능, 학습 효율, 운영 가능성을 종합적으로 고려한 최종 모델 선정

## 2. CatBoost와 LightGBM을 추가하는 이유

현재 TMS 프로젝트에서는 XGBoost와 LSTM 등을 활용하여 NOx, SO2의 사전 경고 가능성을 예측하고 있습니다.

여기에 CatBoost와 LightGBM을 추가하면 서로 다른 학습 방식의 모델을 비교하여 예측 성능을 개선할 수 있는지 확인할 수 있습니다.

TMS 데이터는 다음과 같은 특성이 있습니다.

- 약 1,764만 건의 대용량 시계열 데이터
- NOx, SO2 측정 항목별 특성 차이
- 굴뚝(Stack)별 측정 환경 차이
- 현재 측정값, 과거 Lag, Rolling 통계 등 다양한 Feature
- 기준치 도달 이전의 사전 경고 예측이 목적

CatBoost와 LightGBM은 모두 Gradient Boosting Decision Tree(GBDT) 계열의 머신러닝 모델로, 이러한 정형 데이터 기반 예측 문제에 적용할 수 있습니다.

다만 어떤 모델이 더 우수한지는 실제 데이터로 비교 실험해야 합니다.

## 3. CatBoost의 특징

CatBoost는 범주형 변수를 효과적으로 처리하도록 설계된 Gradient Boosting 기반 머신러닝 모델입니다.

### 주요 특징

| 특징 | 설명 |
|---|---|
| 범주형 변수 처리 | 범주형 데이터를 효과적으로 처리할 수 있음 |
| Ordered Boosting | 학습 과정에서 발생할 수 있는 Prediction Shift 문제를 줄이기 위한 방식 |
| Ordered Target Statistics | 범주형 변수의 통계적 정보를 계산하는 방식 |
| Symmetric Tree | 기본적으로 균형 잡힌 대칭 트리 구조를 활용 |
| 과적합 제어 | 다양한 정규화 및 학습 파라미터 제공 |

### TMS 적용 예시

TMS 데이터에는 다음과 같은 범주형 변수가 존재할 수 있습니다.

- stack_code: 굴뚝 식별 코드
- item_code: NOx 또는 SO2
- 사업장 코드
- 설비 유형

CatBoost는 이러한 범주형 변수를 활용하는 데 유리한 후보 모델입니다.

예를 들어 특정 굴뚝에서 NOx 농도가 지속적으로 상승하는 패턴과 다른 굴뚝의 패턴을 구분하여 학습할 수 있습니다.

실제 구현에서는 범주형 변수의 자료형과 CatBoost 입력 처리 방식을 확인해야 합니다.

## 4. LightGBM의 특징

LightGBM은 대용량 데이터를 효율적으로 학습하도록 설계된 Gradient Boosting 기반 머신러닝 모델입니다.

### 주요 특징

| 특징 | 설명 |
|---|---|
| Leaf-wise 성장 | 손실 감소가 큰 Leaf를 우선 분할 |
| Histogram 기반 학습 | 연속형 데이터를 구간으로 나누어 효율적으로 학습 |
| 빠른 학습 속도 | 대규모 정형 데이터에서 효율적인 학습 가능 |
| 메모리 효율 | 데이터 처리 및 학습 과정에서 메모리 사용을 줄이도록 설계 |
| 범주형 변수 지원 | 설정에 따라 범주형 Feature를 직접 처리 가능 |

### Leaf-wise 방식이란?

일반적인 Level-wise 방식은 트리의 동일한 깊이에 있는 노드를 순서대로 분할합니다.

반면 LightGBM의 Leaf-wise 방식은 현재 손실을 가장 크게 줄일 수 있는 Leaf를 우선적으로 분할합니다.

따라서 데이터의 복잡한 패턴을 효과적으로 학습할 수 있지만, 데이터가 적거나 트리가 지나치게 깊어지면 과적합이 발생할 수 있습니다.

이를 방지하기 위해 다음 파라미터를 조정해야 합니다.

- num_leaves
- max_depth
- min_data_in_leaf
- learning_rate
- feature_fraction
- lambda_l1, lambda_l2

### TMS 적용 예시

TMS 프로젝트는 약 1,764만 건의 데이터가 있으므로 학습 속도와 메모리 효율이 중요합니다.

LightGBM은 대규모 정형 데이터 학습에 적합한 후보이며, 기존 XGBoost와 학습 시간 및 예측 성능을 비교할 수 있습니다.

## 5. CatBoost와 LightGBM 비교

| 구분 | CatBoost | LightGBM |
|---|---|---|
| 알고리즘 | GBDT | GBDT |
| 트리 성장 방식 | Symmetric Tree 기본 구조 | Leaf-wise |
| 범주형 변수 | 강점 중 하나 | 지원하지만 별도 설정 필요 |
| 학습 속도 | 데이터와 설정에 따라 다름 | 대규모 데이터에서 효율적일 가능성 |
| 메모리 | 데이터와 설정에 따라 부담 가능 | 상대적으로 효율적인 편 |
| 과적합 관리 | Ordered Boosting 및 정규화 | Leaf 수, 깊이, 최소 데이터 수 등 |
| TMS 적용 | 굴뚝 및 측정 항목별 특성 학습 | 대규모 Feature 기반 예측 |

두 모델 중 어느 하나가 항상 우수한 것은 아닙니다.

동일한 데이터, Feature, Label, Train/Validation/Test 분할 조건에서 비교해야 합니다.

## 6. 기존 ML Ready 데이터 재사용

새로운 모델을 추가한다고 해서 데이터 파이프라인을 처음부터 다시 만들 필요는 없습니다.

기존 `tw_cems_ml_ready` 데이터를 재사용하여 모델을 추가할 수 있습니다.

### 데이터 구성

| 항목 | 내용 |
|---|---|
| 데이터 단위 | 굴뚝 × 측정 항목 × 30분 |
| 측정 항목 | NOx, SO2 |
| 주요 식별자 | stack_code, item_code |
| Feature | 현재 측정값, Lag, Rolling 등 |
| Label | 미래 30분 또는 60분 내 기준치 도달 여부 |
| 전체 데이터 규모 | 약 1,764만 건 |

### 학습 데이터 구성 시 주의사항

1. 기존 ML Ready의 Feature 생성 로직을 재사용합니다.
2. 시간 순서를 보존하여 Train/Validation/Test를 분리합니다.
3. Label이 NULL인 데이터는 정상(0)으로 변경하지 않고 학습 대상에서 제외합니다.
4. 현재 측정값이 이미 기준치 이상인 데이터는 사전 경고 학습 대상과 구분합니다.
5. 미래 시점의 정보가 현재 Feature에 포함되지 않도록 데이터 누수를 방지합니다.

특히 TMS 프로젝트의 목적은 현재 기준치 미만인 상태에서 미래 기준치 도달 가능성을 예측하는 것입니다.

따라서 현재 기준치 이상인 데이터를 사전 경고 Label 0으로 처리해서는 안 됩니다.

## 7. 모델 성능 비교 방법

CatBoost와 LightGBM을 추가한 후 기존 모델과 동일한 조건에서 성능을 비교합니다.

### 비교 대상 모델

| 모델 | 역할 |
|---|---|
| Persistence | 기준선(Baseline) |
| Random Forest | 전통적인 머신러닝 비교 모델 |
| XGBoost | 기존 GBDT 모델 |
| CatBoost | 범주형 변수 처리 및 GBDT 비교 |
| LightGBM | 대용량 정형 데이터 학습 비교 |
| LSTM | 시계열 딥러닝 비교 모델 |

LSTM의 성능이 좋지 않았다면 무조건 유지할 필요는 없습니다. 동일한 평가 기준으로 성능을 비교한 뒤 활용 여부를 결정하면 됩니다.

### 주요 평가 지표

| 지표 | 의미 | TMS에서의 활용 |
|---|---|---|
| Precision | 경고 중 실제 위험의 비율 | 오경보 감소 |
| Recall | 실제 위험 중 찾아낸 비율 | 위험 상황 누락 방지 |
| F1-score | Precision과 Recall의 조화평균 | 종합적인 분류 성능 |
| PR-AUC | Precision-Recall 곡선 아래 면적 | 불균형 데이터 평가 |
| ROC-AUC | 양성과 음성을 구분하는 능력 | 모델의 전반적인 분류 성능 |
| Confusion Matrix | 실제값과 예측값의 관계 | 오경보 및 미탐 분석 |

TMS 데이터는 정상 데이터에 비해 위험 데이터가 적은 불균형 데이터이므로 Accuracy만으로 모델을 평가하면 안 됩니다.

특히 PR-AUC와 Recall을 중요하게 확인하는 것이 좋습니다.

### 추가 측정 항목

예측 성능 외에도 다음 항목을 함께 측정합니다.

- 모델 학습 시간
- 최대 메모리 사용량
- 모델 파일 크기
- 추론 시간
- 대용량 데이터 처리 가능 여부

실제 운영 환경에서는 예측 성능뿐 아니라 처리 효율도 중요하기 때문입니다.

## 8. 앙상블(Ensemble) 적용

앙상블은 여러 모델의 예측 결과를 결합하여 최종 예측 성능을 개선하는 방법입니다.

CatBoost와 LightGBM을 추가하는 목적 중 하나도 서로 다른 모델의 예측 결과를 결합할 수 있는지 확인하는 것입니다.

### 8.1 Soft Voting

각 모델이 예측한 확률을 평균하여 최종 확률을 계산합니다.

예시:

| 모델 | 위험 예측 확률 |
|---|---:|
| XGBoost | 0.80 |
| CatBoost | 0.75 |
| LightGBM | 0.85 |

최종 확률:

`(0.80 + 0.75 + 0.85) / 3 = 0.80`

최종 위험 예측 확률은 80%입니다.

이후 설정한 임계값에 따라 위험 여부를 판단합니다.

### 8.2 Weighted Voting

모델별 성능에 따라 가중치를 다르게 적용합니다.

예시:

| 모델 | 가중치 | 위험 예측 확률 |
|---|---:|---:|
| XGBoost | 0.3 | 0.80 |
| CatBoost | 0.3 | 0.75 |
| LightGBM | 0.4 | 0.85 |

최종 확률:

`(0.80 × 0.3) + (0.75 × 0.3) + (0.85 × 0.4) = 0.805`

최종 위험 예측 확률은 80.5%입니다.

가중치는 Validation 데이터에서 결정하고 Test 데이터로 최종 검증해야 합니다.

### 8.3 Stacking

Stacking은 여러 모델의 예측 결과를 새로운 모델의 입력 Feature로 활용하는 방식입니다.

```text
                 ML Ready Data
                       |
          +------------+------------+
          |            |            |
          v            v            v
       XGBoost       CatBoost     LightGBM
          |            |            |
          v            v            v
       예측 확률     예측 확률    예측 확률
          |            |            |
          +------------+------------+
                       |
                       v
                 Meta Model
                       |
                       v
                  최종 예측
```

Meta Model은 Logistic Regression 등을 사용할 수 있습니다.

주의할 점은 Meta Model 학습에 사용하는 예측값이 해당 행의 정답을 미리 학습한 모델에서 나온 값이면 안 된다는 것입니다.

따라서 시간 순서를 보존하는 Out-of-Fold(OOF) 예측을 구성하여 데이터 누수를 방지해야 합니다.

### 8.4 앙상블 적용 시 주의사항

XGBoost, CatBoost, LightGBM은 모두 GBDT 계열이므로 서로 비슷한 오류를 발생시킬 수 있습니다.

앙상블이 효과를 내려면 각 모델의 예측 성능뿐 아니라 모델 간 오류 패턴의 차이도 확인해야 합니다.

앙상블 결과가 단일 모델보다 항상 우수한 것은 아니므로 실제 검증 결과를 기준으로 적용 여부를 결정합니다.

## 9. SHAP을 활용한 모델 설명 및 해석

SHAP(SHapley Additive exPlanations)은 머신러닝 모델이 특정 예측을 내린 이유를 설명하는 기법입니다.

모델이 위험하다고 예측했을 때 어떤 Feature가 예측에 영향을 주었는지 확인할 수 있습니다.

**SHAP은 모델의 예측 성능을 평가하는 지표가 아니라 모델의 예측 결과를 설명하는 해석 기법입니다.**

### 9.1 SHAP을 사용하는 이유

TMS 프로젝트에서는 단순히 미래 위험 여부를 예측하는 것만으로는 부족합니다.

운영자가 다음과 같은 질문에 답할 수 있어야 합니다.

- 왜 특정 굴뚝을 위험하다고 판단했는가?
- 어떤 Feature가 예측에 가장 큰 영향을 주었는가?
- 현재 측정값이 상승해서 위험하다고 판단했는가?
- 최근 30분 또는 60분의 변화량이 영향을 주었는가?
- 특정 측정 항목이나 굴뚝의 특성이 영향을 주었는가?

SHAP을 활용하면 이러한 질문에 대한 근거를 분석할 수 있습니다.

### 9.2 SHAP 분석 예시

특정 굴뚝의 NOx 미래 위험 확률을 모델이 85%로 예측했다고 가정하겠습니다.

SHAP 분석 결과가 다음과 같이 나왔다고 가정합니다.

| Feature | SHAP 값 | 영향 |
|---|---:|---|
| current_value | +0.25 | 위험 예측 방향으로 기여 |
| lag_1 | +0.18 | 위험 예측 방향으로 기여 |
| rolling_mean_3 | +0.12 | 위험 예측 방향으로 기여 |
| rolling_std_3 | +0.08 | 위험 예측 방향으로 기여 |
| temperature | -0.05 | 위험 예측 반대 방향으로 기여 |

해석:

- 현재 NOx 측정값이 높아 위험 예측 방향으로 영향을 주었습니다.
- 직전 측정값도 높아 상승 흐름이 이어지고 있습니다.
- 최근 3개 측정값의 평균이 높아 위험 가능성이 커지는 방향으로 작용했습니다.
- 측정값의 변동성도 예측에 영향을 주었습니다.
- 온도 Feature는 해당 예측에서 위험 예측을 낮추는 방향으로 작용했습니다.

위 숫자는 이해를 돕기 위한 가상 예시입니다. SHAP 값의 수치는 모델 출력 공간에 따라 달라지므로 확률 변화량으로 그대로 해석해서는 안 됩니다.

### 9.3 SHAP 주요 분석 방법

| 분석 방법 | 설명 | TMS 적용 |
|---|---|---|
| SHAP Summary Plot | 전체 데이터에서 Feature 영향도와 방향 분석 | 위험 예측에 중요한 변수 파악 |
| SHAP Bar Plot | Feature별 평균 절대 SHAP 값 비교 | 주요 영향 변수 순위 확인 |
| SHAP Beeswarm Plot | Feature 값과 SHAP 값의 분포 확인 | 값이 높거나 낮을 때 예측에 미치는 영향 확인 |
| SHAP Waterfall Plot | 개별 예측의 Feature별 기여도 분석 | 특정 굴뚝의 위험 판정 이유 설명 |
| SHAP Dependence Plot | Feature 값과 SHAP 값의 관계 분석 | NOx 농도 상승에 따른 영향 확인 |

```text
                       |
                       v
               Feature별 SHAP 값 계산
                       |
          +------------+------------+
          |            |            |
          v            v            v
      Summary       Bar Plot     Waterfall
          |            |            |
          v            v            v
      전체 영향도    중요 변수 순위  개별 예측 설명

          +------------+------------+
                       |
                       v
                TMS 위험 예측 근거
```

### 9.5 TMS 프로젝트에서 SHAP 활용 방향

SHAP 분석은 두 가지 관점으로 진행합니다.

**첫 번째: 전체 모델 관점**

전체 데이터에서 어떤 Feature가 NOx와 SO2의 미래 위험 예측에 중요한지 분석합니다.

- 현재 측정값이 가장 중요한 변수인가?
- Lag Feature가 중요한 역할을 하는가?
- Rolling 평균과 표준편차가 예측에 기여하는가?
- 굴뚝별 특성이 예측에 영향을 주는가?

**두 번째: 개별 위험 예측 관점**

특정 굴뚝에서 위험 경고가 발생했을 때 해당 예측의 주요 근거를 확인합니다.

예를 들어 다음과 같이 설명할 수 있습니다.

> 해당 굴뚝의 NOx 위험 확률이 높게 예측된 주요 원인은 현재 측정값 상승, 최근 측정값의 지속적인 증가, 최근 구간 평균의 상승입니다.

이러한 분석 결과를 운영자에게 제공하면 AI 예측 결과에 대한 이해와 신뢰도를 높이는 데 도움이 됩니다.

단, SHAP은 모델이 학습한 관계를 설명하는 것이므로 실제 환경에서의 인과관계를 증명하는 것은 아닙니다.

또한 상관관계가 높은 Feature가 여러 개 존재하면 SHAP 기여도가 서로 분산될 수 있습니다.

## 10. PFI를 활용한 Feature 중요도 분석

PFI(Permutation Feature Importance)는 특정 Feature가 모델의 예측 성능에 얼마나 기여하는지 확인하는 분석 기법입니다.

특정 Feature의 값을 무작위로 섞은 후 모델 성능이 얼마나 하락하는지 측정합니다.

**PFI는 Feature가 모델의 예측 성능에 미치는 영향을 확인하는 기법입니다.**

### 10.1 PFI를 사용하는 이유

TMS 프로젝트에서는 현재 측정값, Lag, Rolling 등 다양한 Feature를 사용합니다.

하지만 모든 Feature가 실제 예측 성능에 동일하게 기여하는 것은 아닙니다.

PFI를 활용하면 다음과 같은 내용을 확인할 수 있습니다.

- 어떤 Feature가 모델 성능에 가장 크게 기여하는가?
- 불필요하거나 영향력이 낮은 Feature는 무엇인가?
- Lag와 Rolling Feature 중 어떤 변수가 더 중요한가?
- 모델별로 중요하게 사용하는 Feature가 다른가?
- Feature를 제거했을 때 모델 성능이 어떻게 변하는가?

### 10.2 PFI 분석 원리

예를 들어 모델의 원래 PR-AUC가 0.85라고 가정하겠습니다.

이후 특정 Feature의 값을 무작위로 섞고 다시 평가합니다.

| Feature | 원래 PR-AUC | Feature 섞은 후 PR-AUC | 성능 하락 폭 |
|---|---:|---:|---:|
| current_value | 0.85 | 0.70 | 0.15 |
| lag_1 | 0.85 | 0.74 | 0.11 |
| rolling_mean_3 | 0.85 | 0.77 | 0.08 |
| rolling_std_3 | 0.85 | 0.81 | 0.04 |
| temperature | 0.85 | 0.84 | 0.01 |

해석:

- current_value를 섞었을 때 PR-AUC가 0.15 하락했습니다.
- lag_1을 섞었을 때 0.11 하락했습니다.
- rolling_mean_3을 섞었을 때 0.08 하락했습니다.
- temperature를 섞었을 때 0.01 하락했습니다.

따라서 이 예시에서는 current_value가 모델의 예측 성능에 가장 크게 기여한다고 해석할 수 있습니다.

위 수치는 이해를 돕기 위한 가상 데이터입니다.

### 10.3 PFI 분석 구조

```text
                 학습 완료 모델
                       |
                       v
                 원본 성능 측정
                       |
                       v
                Feature 하나 선택
                       |
                       v
               Feature 값 무작위 섞기
                       |
                       v
                 성능 다시 측정
                       |
                       v
                 성능 하락 폭 계산
                       |
                       v
                Feature 중요도 산출
                       |
                       v
               중요 Feature 순위 도출
```

### 10.4 TMS 프로젝트에서 PFI 활용 방향

**첫 번째: Feature 선정**

현재 약 1,764만 건의 데이터에서 다양한 Lag, Rolling Feature를 생성하고 있습니다.

PFI를 통해 실제 예측 성능에 기여하는 Feature를 확인할 수 있습니다.

**두 번째: 불필요한 Feature 제거 검토**

중요도가 낮은 Feature를 제거한 모델과 기존 모델을 비교할 수 있습니다.

다만 중요도가 낮다고 바로 제거하지 말고 제거 전후의 성능을 검증해야 합니다.

**세 번째: 모델별 중요 Feature 비교**

XGBoost, CatBoost, LightGBM에서 각각 PFI를 계산하면 모델별로 중요하게 사용하는 Feature가 어떻게 다른지 확인할 수 있습니다.

### 10.5 PFI 적용 시 주의사항

TMS의 Lag와 Rolling Feature는 서로 높은 상관관계를 가질 수 있습니다.

예를 들어 다음과 같은 Feature가 존재한다고 가정하겠습니다.

- lag_1
- lag_2
- rolling_mean_3
- rolling_mean_6

이 변수들은 서로 유사한 정보를 가지고 있을 수 있습니다.

이 경우 한 Feature만 무작위로 섞으면 다른 Feature가 유사한 정보를 제공하므로 해당 Feature의 중요도가 실제보다 낮게 측정될 수 있습니다.

이를 보완하기 위해 다음 방법을 검토합니다.

1. 반복 측정을 통해 PFI 결과의 평균과 표준편차를 확인합니다.
2. 상관관계가 높은 Feature를 그룹으로 묶어 함께 섞는 Grouped PFI를 검토합니다.
3. Validation 데이터를 사용하여 Feature 중요도를 측정합니다.
4. 시간 순서와 굴뚝별 데이터 구조를 고려하여 평가합니다.
5. Feature 제거 전후의 성능을 비교하여 실제 개선 여부를 확인합니다.

## 11. SHAP과 PFI 비교 및 함께 활용하기

SHAP과 PFI는 모두 Feature 중요도를 분석할 수 있지만 접근 방식과 분석 목적이 다릅니다.

| 구분 | SHAP | PFI |
|---|---|---|
| 정식 명칭 | SHapley Additive exPlanations | Permutation Feature Importance |
| 분석 목적 | 개별 예측 및 전체 예측의 기여도 설명 | 특정 Feature가 모델 성능에 미치는 영향 측정 |
| 분석 방식 | Feature별 예측 기여도 계산 | Feature 값을 무작위로 섞어 성능 변화 측정 |
| 개별 예측 설명 | 가능 | 일반적으로 어려움 |
| 전체 중요도 분석 | 가능 | 가능 |
| 영향 방향 확인 | 가능 | 일반적으로 불가능 |
| Feature 제거 실험 | 직접적인 성능 변화 측정은 아님 | Feature 제거 후보 선별에 활용 |
| 계산 비용 | 모델과 데이터에 따라 높을 수 있음 | Feature 수와 반복 횟수에 따라 증가 |
| TMS 활용 | 개별 위험 경고의 근거 설명 | 모델 성능에 기여하는 변수 확인 |

### 두 기법을 함께 적용하는 이유

SHAP은 모델이 특정 위험을 예측한 이유를 설명하고, PFI는 해당 Feature가 실제 모델 성능에 얼마나 중요한지 확인합니다.

예를 들어 다음과 같은 분석이 가능합니다.

| 분석 결과 | SHAP | PFI |
|---|---|---|
| current_value | 높은 영향도 | 성능 하락 폭 큼 |
| lag_1 | 높은 영향도 | 성능 하락 폭 큼 |
| rolling_mean_3 | 높은 영향도 | 성능 하락 폭 큼 |
| temperature | 일부 예측에서 영향 | 전체 성능 영향 낮음 |

이러한 결과를 비교하면 특정 Feature가 개별 예측에는 영향을 주지만 전체적인 모델 성능에는 상대적으로 기여하지 않는 경우도 확인할 수 있습니다.

### 권장 분석 흐름

```text
                 학습 완료 모델
                       |
          +------------+------------+
          |                         |
          v                         v
       SHAP 분석                 PFI 분석
          |                         |
          v                         v
   예측 기여도 분석             성능 기여도 분석
          |                         |
          +------------+------------+
                       |
                       v
                결과 비교 및 해석
                       |
                       v
                Feature 선정 검토
                       |
                       v
                 Feature 제거 실험
                       |
                       v
                  모델 재학습
                       |
                       v
                  성능 재평가
```

**중요한 점은 SHAP과 PFI의 결과가 반드시 동일할 필요는 없다는 것입니다.**

두 기법은 분석 관점이 다르므로 결과 차이 자체도 의미 있는 분석 대상입니다.

## 12. NOx/SO2 통합 모델과 개별 모델 비교

TMS 데이터에서는 NOx와 SO2를 통합하여 하나의 모델로 학습할지, 측정 항목별로 별도의 모델을 만들지도 중요한 실험 주제입니다.

### 12.1 통합 모델

```text
             NOx 데이터
                 |
             SO2 데이터
                 |
                 v
          통합 ML Ready Data
                 |
                 v
             통합 모델
                 |
          +------+------+
          |             |
          v             v
        NOx 예측      SO2 예측
```

장점:

- 하나의 모델로 관리 가능
- 데이터 규모 확대
- 공통적인 패턴을 학습할 가능성

주의사항:

- NOx와 SO2의 측정 단위 및 값의 분포 차이
- 측정 항목별 기준치 차이
- 측정 항목별 위험 발생 특성 차이

### 12.2 개별 모델

```text
        NOx 데이터             SO2 데이터
            |                     |
            v                     v
         NOx 모델              SO2 모델
            |                     |
            v                     v
         NOx 예측              SO2 예측
```

장점:

- 측정 항목별 특성을 독립적으로 학습
- 각 항목에 맞는 Feature와 파라미터 조정 가능
- 결과 해석이 상대적으로 명확함

### 12.3 권장 실험

통합 모델과 개별 모델을 동일한 시간 기준으로 분리한 데이터에서 비교합니다.

어느 방식이 더 우수한지는 PR-AUC, Recall, Precision, 학습 시간 등을 기준으로 결정합니다.

통합 모델에서는 `item_code`를 범주형 Feature로 활용하는 방안을 검토하고, 측정 항목별 단위와 기준치 차이를 고려해야 합니다.

## 13. 권장 실험 순서

모델을 한꺼번에 추가하기보다는 단계적으로 검증하는 것이 좋습니다.

| 단계 | 실험 내용 | 목적 |

### 반드시 확인할 사항

- 모든 모델에 동일한 Train/Validation/Test 기간을 적용합니다.
- 데이터 분할은 시간 순서를 보존합니다.
- 모델별 예측 임계값은 Validation 데이터에서 결정합니다.
- 앙상블 가중치 역시 Validation 데이터에서 결정합니다.
- 최종 Test 데이터는 모델 선택이나 파라미터 조정에 사용하지 않습니다.
- 학습 시간, 메모리 사용량, 추론 시간도 함께 측정합니다.
- SHAP과 PFI는 최종 선정 모델을 중심으로 분석합니다.
- SHAP과 PFI의 분석 결과가 다른 경우 그 차이를 해석합니다.
- Feature 제거 후에는 반드시 동일한 평가 조건에서 성능을 재측정합니다.

## 15. 이번 실험에서 확인할 핵심 연구 질문

이번 모델 추가 및 비교 실험은 단순히 새로운 알고리즘을 적용하는 데 목적이 있는 것은 아닙니다.

다음 질문에 답할 수 있도록 실험을 설계하는 것이 중요합니다.

1. CatBoost와 LightGBM은 기존 XGBoost보다 예측 성능이 좋은가?
2. NOx와 SO2를 통합하여 학습하는 것이 개별 학습보다 효과적인가?
3. GBDT 모델의 앙상블을 적용하면 사전 경고 성능이 개선되는가?
4. 앙상블 모델은 단일 모델보다 위험 상황을 더 잘 탐지하는가?
5. SHAP 분석을 통해 위험 예측에 영향을 주는 주요 Feature를 설명할 수 있는가?
6. PFI 분석을 통해 실제 모델 성능에 기여하는 주요 Feature를 확인할 수 있는가?
7. SHAP과 PFI의 결과를 비교했을 때 공통적으로 중요한 Feature는 무엇인가?
8. 중요도가 낮은 Feature를 제거하면 모델 성능과 학습 효율이 개선되는가?
9. 굴뚝별, 측정 항목별로 위험 예측에 영향을 주는 Feature가 다른가?
10. 예측 성능뿐 아니라 학습 시간과 추론 시간까지 고려했을 때 가장 적합한 모델은 무엇인가?

## 16. 최종 목표

이번 실험의 목표는 가장 높은 성능을 보이는 모델 하나를 찾는 것만이 아닙니다.

**예측 성능, 학습 효율, 운영 가능성, 설명 가능성을 종합적으로 고려하여 TMS에 적합한 AI 사전 경고 모델을 선정하는 것**입니다.

- CatBoost와 LightGBM으로 기존 모델의 성능 개선 가능성을 검증합니다.
- 앙상블을 통해 여러 모델의 예측 결과를 결합할 수 있는지 확인합니다.
- SHAP을 활용하여 AI가 위험을 예측한 근거와 Feature별 기여도를 설명합니다.
- PFI를 활용하여 실제 모델 성능에 기여하는 Feature를 분석합니다.
- SHAP과 PFI의 결과를 비교하여 Feature 중요도를 다각도로 검증합니다.
- Feature 선정 및 제거 실험을 통해 모델을 최적화합니다.
- 최종적으로 운영자가 이해하고 활용할 수 있는 TMS AI 사전 경고 체계를 구축합니다.

단순히 AI가 위험하다고 판단하는 시스템이 아니라, **왜 위험하다고 판단했는지 설명할 수 있고, 어떤 데이터가 예측에 중요한 역할을 했는지 검증할 수 있는 AI 시스템**을 만드는 것이 중요합니다.
