## 0. 결론 한눈에 보기

| # | 기법 | 프로젝트와의 관계 | 꼭 적용? | 할 일 |
|:---:|---|---|:---:|---|
| 1 | 경사하강법 | **간접적으로 깊다.** XGBoost는 "함수 공간의 경사하강"이다. 직접 구현할 곳은 없다 | 아니오 | `learning_rate`·`n_estimators`·Early Stopping을 경사하강의 보폭·반복 횟수로 이해하고 설정한다 |
| 2 | 다항 회귀 | **거의 없다.** 트리가 비선형·상호작용을 스스로 만든다 | 아니오 | 적용하지 않는다. "곡률" 정보가 필요하면 Feature(가속도)로 만든다 |
| 3 | 학습 곡선 | **깊다.** 지금 빠진 진단(Train 성능, 데이터 양의 효과)을 채워 준다 | **예 (권장)** | 반복 곡선(트리 수별 Train·Val)과 데이터 양 곡선(학습 개월 수별)을 그린다 |
| 4 | 로지스틱 회귀 | 이전 계획에는 있었고 정본에서 빠졌다. XGBoost 분류도 같은 로그 손실을 쓴다 | 아니오 (선택) | 결과표에 **해석용 기준선 1행**으로만 넣는 것을 권한다 |
| 5 | 축 방향 민감성 | **깊다. 이 프로젝트에서 가장 실질적인 항목이다.** `ratio_pct` 설계가 이 문제를 이미 하나 풀었고, 하나가 남아 있다 | 대응 권장 | "궤적 투영" Feature(예: `ratio_pct + 2 × ratio_diff_30m`)를 실험한다. PCA 회전은 쓰지 않는다 |
| 6 | 결정 트리의 분산 | 단일 트리는 쓰지 않아 직접 문제는 아니다. 그러나 **실행 간 분산(seed)**은 지금 측정되지 않았다 | 측정 권장 | seed 3~5개로 반복해 실험 간 차이가 seed 흔들림보다 큰지 확인한다 |
| 7 | 배깅과 페이스팅 | **RF가 바로 배깅이다. XGBoost `subsample`은 페이스팅 방식이다** | 이미 적용됨 | RF는 배깅 유지(OOB 필요). 시계열 행 샘플링 때문에 OOB가 낙관적이라는 점을 기록한다 |

**한 줄 요약:** 7개 중 **새로 적용할 것은 학습 곡선(3)과 축 방향 대응 Feature(5)**, **측정할 것은 seed 분산(6)**이다. 나머지는 이미 모델 안에 들어 있거나(1·7) 지금 모델 구성에서는 필요 없다(2·4).

## 1. 경사하강법 (Gradient Descent)

### 1.1 우리 모델과의 관계

| 모델 | 학습 방식 | 경사하강법과의 관계 |
|---|---|---|
| **XGBoost** (분류·회귀) | 그레이디언트 부스팅 | **트리 하나하나가 "손실의 경사(gradient)"를 따라 한 걸음씩 내려가는 단계다.** 각 트리는 지금까지 예측의 오차 방향(1차 기울기)과 곡률(2차)을 보고 만들어진다. 파라미터가 아니라 **예측값(함수)을 경사하강**한다 |
| RF | 트리를 독립적으로 만들어 평균 | 관계없다. 손실을 반복해서 줄이는 과정이 없다 |
| Linear Regression (기준선) | scikit-learn `LinearRegression`은 최소제곱 해를 한 번에 계산한다 | 경사하강을 쓰지 않는다 |
| Logistic Regression (선택, 4절) | `lbfgs` 등 기울기 기반 최적화 | 경사하강 계열이다. 그래서 스케일링이 필요해진다 |

### 1.2 경사하강 개념이 XGBoost 설정에 그대로 들어 있다

| 경사하강의 개념 | XGBoost의 대응 | 이 프로젝트에서 |
|---|---|---|
| 보폭(learning rate) | `learning_rate` (eta) | 하이퍼파라미터 검토에서 0.05 고정 제안 |
| 반복 횟수 | `n_estimators` (트리 수) | Early Stopping으로 정한다 |
| 너무 오래 내려가면 Train에 과적합 | 트리가 늘수록 Train 손실은 계속 준다 | **Validation이 나빠지기 시작하면 멈춘다** = Early Stopping |
| 무엇의 기울기인가 = 손실 함수 | `objective` | 분류 `binary:logistic`(로그 손실), 회귀 `reg:squarederror` 기본. 회귀 손실 선택이 중요하다(하이퍼파라미터 검토 2.4절) |
| 확률적 경사하강(SGD)의 미니배치 | `subsample` (트리마다 행 일부만 사용) | 0.8 고정 제안. 7절 페이스팅과 같은 개념이다 |

### 1.3 판단

- **직접 구현하거나 별도로 적용할 일은 없다.**
- 그러나 교육 관점에서 **"XGBoost의 `learning_rate`와 트리 수가 왜 서로 맞바꾸는 관계인가"**를 경사하강법으로 설명할 수 있다. 보폭을 반으로 줄이면 같은 거리를 가는 데 걸음이 약 두 배 필요하다.
- 트리 모델의 경사하강은 **예측값 공간**에서 일어나므로 입력 스케일과 무관하다. 선형 모델의 경사하강과 달리 스케일링이 필요 없는 이유다(스케일링 검토 1절).

## 2. 다항 회귀 (Polynomial Regression)

### 2.1 다항 회귀가 하는 일

입력을 거듭제곱·곱으로 늘려(`x`, `x²`, `x₁x₂` …) **선형 모델이 곡선과 상호작용을 표현**하게 만든다.

### 2.2 우리 프로젝트에서

| 관점 | 판단 |
|---|---|
| 주 모델(XGBoost·RF) | **필요 없다.** 트리는 구간을 나눠 곡선을 계단으로 근사하고, 분할을 겹쳐 상호작용(예: "비율 높고 **그리고** 상승 중")을 스스로 만든다 |
| Linear Regression 기준선 | 기준선의 역할은 "단순한 모델이면 이 정도"를 보여 주는 것이다. 다항으로 만들면 기준선의 뜻이 흐려진다 |
| 비용 | 입력 22개를 2차로 늘리면 약 275개 열이 된다. 520만 행에서 메모리·시간이 크게 는다 |
| 외삽 위험 | 다항식은 학습 범위 밖에서 급격히 발산한다. 국내 분포가 대만과 다르므로 위험이 더 크다 **(추론)** |

### 2.3 대신 쓸 수 있는 것 — "곡률"을 Feature로

다항 회귀의 아이디어 중 쓸모 있는 것은 **"변화의 변화(가속도)"**다. 모델이 아니라 Feature로 넣는다.

| 후보 | 계산 | 뜻 |
|---|---|---|
| (기존 후보) `ratio_slope_3h` | 3시간 창의 1차 직선 기울기 | 정본 Task 4의 추가 후보. 1차 다항 적합이다 |
| `ratio_accel_30m` (제안) | `ratio_diff_30m − (30분 전의 ratio_diff_30m)` | 상승이 빨라지는 중인가. 급등 초입을 잡는 데 도움이 될 수 있다 **(추론)** |

→ **다항 회귀는 적용하지 않는다.** 가속도 Feature는 추가 후보 3개와 같은 시점(11/18 결정)에 함께 검토할 수 있다.

## 3. 학습 곡선 (Learning Curve)

### 3.1 두 가지 학습 곡선

| 종류 | x축 | y축 | 알 수 있는 것 |
|---|---|---|---|
| **반복 곡선** | XGBoost 트리 수(반복) | Train·Validation AP(또는 MAE) | 언제부터 과적합되는가, Early Stopping 지점이 적절한가 |
| **데이터 양 곡선** | 학습 데이터 양 | Train·Validation 지표 | **데이터를 더 모으면 나아지는가**, 과적합(분산)인가 과소적합(편향)인가 |

### 3.2 왜 이 프로젝트에 특히 필요한가

| 지금의 공백 | 학습 곡선이 주는 답 |
|---|---|
| **Train 성능이 4개 모델 모두 없다** (통합 비교 C7, P1-7) | 반복 곡선에 Train 곡선이 함께 그려진다. 과적합 판단이 바로 된다 |
| Early Stopping을 썼는지 모른다 | 반복 곡선이 Validation 최고점 이후로 계속 가면 트리가 너무 많다 |
| 대만 데이터 24개월이 충분한가 | 데이터 양 곡선이 18→24개월에서 평평하면 데이터보다 Feature·모델이 병목이다 |
| SOx 양성이 적다 (train 0.46%) | SOx 곡선이 아직 올라가는 중이면 **데이터를 더 모으는 게 가장 효과적인 개선**이다 |
| 정본의 국내 단독 분할(Train 2주) | 대만 곡선에서 "2주 분량"일 때의 성능을 보면 국내 단독 학습의 한계를 미리 알 수 있다 **(추론)** |

### 3.3 시계열에서 그리는 방법 — 무작위로 행을 줄이면 안 된다

- scikit-learn `learning_curve`는 기본적으로 **행을 무작위로 뽑아** 양을 늘린다. 30분 간격 행은 이웃끼리 거의 같아서, 같은 기간에서 행을 더 뽑아도 새 정보가 거의 늘지 않는다. 곡선이 실제보다 빨리 평평해진다 **(추론)**.
- **x축을 "학습 개월 수"로** 한다. 검증 구간(2025-11~2026-04)은 고정하고, 학습 시작점을 뒤로 당겨 3·6·12·18·24개월로 늘린다. 각 경계는 60분을 뺀다.

```text
학습  3개월 [                    2025-08 ~ 10]  ▒ [검증 2025-11 ~ 2026-04]
학습  6개월 [               2025-05 ~ 10     ]  ▒ [검증 고정]
학습 12개월 [        2024-11 ~ 2025-10       ]  ▒ [검증 고정]
학습 24개월 [2023-11 ~ 2025-10               ]  ▒ [검증 고정]
```

- 짧은 학습 구간은 특정 계절만 담는다. 곡선의 초반 흔들림은 데이터 양과 계절이 섞인 결과로 읽는다.

### 3.4 판단

→ **적용을 권장한다.** 반복 곡선은 XGBoost `evals_result()`로 추가 학습 없이 얻는다. 데이터 양 곡선은 5번 학습이면 된다. 비용 대비 얻는 정보가 7개 기법 중 가장 크다.

## 4. 로지스틱 회귀 (Logistic Regression)

### 4.1 이력

- 10/30~10/31 계획에는 "Logistic Regression·RF·XGBoost를 비교해 하나를 고른다"가 있었다.
- 11/01 정본에서 분류 후보는 **XGBoost·RF 두 개**로 줄었다. 뺀 이유는 정본에 적혀 있지 않다 `[확인 필요: 결정 기록]`.

### 4.2 이미 우리 모델 안에 있는 것

- XGBoost 분류의 `binary:logistic`은 **로지스틱 회귀와 같은 로그 손실·시그모이드 출력**을 쓴다. 차이는 "선형식 대신 트리 합"을 시그모이드에 넣는다는 점이다.
- 그래서 "진입 확률 0.52" 같은 출력의 뜻은 두 모델이 같다.

### 4.3 지금 추가하면 얻는 것과 치르는 것

| 얻는 것 | 치르는 것 |
|---|---|
| **"비선형 모델이 정말 필요한가"에 답한다.** 단순 규칙(AP 0.198) → 로지스틱 → XGBoost(AP 0.311) 사이 어디에 있는지 보인다 | **스케일링이 필요하다** (스케일링 검토 3절) |
| 계수로 해석이 쉽다 (예: `ratio_diff_30m` 1%p당 오즈 변화) | **빈 값을 받지 못한다.** 정본의 "결측을 채우지 않는다" 규칙과 부딪친다. 대체값 + 결측 표시 열이 필요하다 |
| 확률이 비교적 잘 보정되어 나온다 | 상호작용·축 방향 문제(5절)를 직접 Feature로 만들어 줘야 한다 |
| 학습이 빠르다 | 결과표의 비교 모델이 하나 더 늘어난다 |

### 4.4 판단

- **꼭 적용할 필요는 없다.** 승인 모델 후보에 넣지 않는다.
- 다만 **결과표의 기준선 1행으로 넣는 것은 권한다 (선택).** Persistence·Rule Engine 옆에 두면 XGBoost의 가치를 설명하기 좋다. 넣는다면 `Pipeline([결측 대체 + 결측 표시, StandardScaler, LogisticRegression(class_weight="balanced")])`로 만들고 운영 경로에는 넣지 않는다.

## 5. 결정 트리의 축 방향 민감성 (Axis-aligned Splits)

### 5.1 문제

트리는 한 번에 **열 하나**로만 자른다(`x ≤ a`). 그래서 결정 경계가 축에 평행한 선뿐이다. 실제 경계가 **대각선**(두 열의 조합)이면 계단을 많이 쌓아 근사해야 하고, 데이터가 적은 곳에서는 계단이 거칠어 틀린다.

### 5.2 이 프로젝트에서 이미 해결된 대각선 — `ratio_pct`

| 입력 방식 | 위험 경계 | 트리에게 |
|---|---|---|
| 측정값(ppm)과 기준값을 따로 넣으면 | `측정값 ÷ 기준값 ≥ 0.9` → (측정값, 기준값) 평면의 **대각선** | 굴뚝마다 기준이 달라 계단을 아주 많이 쌓아야 한다 |
| **`ratio_pct` 하나로 넣으면** | `ratio_pct ≥ 90` → **축에 평행한 선 하나** | 분할 한 번이면 된다 |

→ 대만 모델이 `measure_value`·`standard_value`를 빼고 `ratio` 중심으로 입력을 만든 것(데이터관점 §2)은 **축 방향 문제를 Feature 설계로 푼 사례**다.

### 5.3 아직 남아 있는 대각선 — "궤적이 90%에 닿는가"

60분 안 진입 여부는 직관적으로 **"지금 수준 + 상승 속도 × 남은 시간 ≥ 90"**에 가깝다.

```text
ratio_diff_30m (상승 속도)
   ▲
 20│ ╲ 위험
 10│    ╲
  0│───────╲──────▶ ratio_pct
   50   70   90
경계: ratio_pct + 2 × ratio_diff_30m ≈ 90  (60분 = 30분 × 2구간 선형 외삽)
```

- 이 경계는 (`ratio_pct`, `ratio_diff_30m`) 평면의 **대각선**이다. 트리는 이것을 계단으로 근사한다.
- 계단 근사는 데이터가 많은 영역(대만, 비율 70~90%)에서는 잘 되고, **데이터가 적은 영역(비율 50~70%에서 빠르게 오르는 경우)**에서는 거칠다. 그런데 이것이 바로 놓친 위험이 많은 영역이고(데이터관점 §3: FN의 23.6%가 50~70%), 국내에서는 더 낮은 수준에서 오르는 양성이 많다(국내 양성 직전 행의 13.5%가 50% 미만, 대만은 1.6%) **(추론: 원인 중 하나일 수 있다)**.

### 5.4 대응 방법 비교

| 방법 | 내용 | 판단 |
|---|---|---|
| **대각선을 Feature로 만든다 (권장)** | `ratio_proj_60m = ratio_pct + 2 × ratio_diff_30m`(선형 외삽), `gap_to_90 = 90 − ratio_pct`, `time_to_90 = gap_to_90 ÷ ratio_diff_30m`(상승 중일 때만) | 축에 평행한 분할 한 번으로 대각선을 표현한다. 국내·대만에서 같은 식으로 계산된다. 뜻이 분명하다 |
| PCA 등으로 축 회전 | 입력 공간을 회전해 경계를 축에 맞춘다 | **쓰지 않는다.** 회전 행렬을 대만에서 `fit`하면 국내 분포에서 뜻이 달라진다. 운영 경로 전체에 회전을 맞춰야 한다. 해석이 사라진다(스케일링 검토 2.3·2.6절과 같은 이유) |
| 트리를 더 깊게·더 많이 | 계단을 더 촘촘하게 | 데이터가 적은 영역에서는 효과가 작고 과적합만 는다 |
| 사선 분할 트리(Oblique tree) | 열 조합으로 자르는 트리 | XGBoost·sklearn에 없다. 범위 밖 |

### 5.5 판단

→ **대응을 권장한다.** `ratio_proj_60m` 하나(또는 `time_to_90`까지 둘)를 추가 후보로 실험한다. 정본의 추가 후보 3개(`ratio_diff_60m`·`ratio_diff_120m`·`ratio_slope_3h`)와 같은 "0단계 Feature 세트" 비교에 넣으면 일정 변경 없이 할 수 있다.

> 주의: 놓친 위험의 62%는 **직전 1시간 변화가 거의 없거나 내려가던** 경우다(데이터관점 §3). 이런 "예고 없는 급등"은 궤적 투영으로도 잡을 수 없다. 기대 효과를 과장하지 않는다.

## 6. 결정 트리의 분산 문제 (High Variance)

### 6.1 문제

단일 결정 트리는 학습 데이터가 조금만 바뀌어도 맨 위 분할이 바뀌고, 그 아래 전체가 달라진다. 예측이 불안정하다(분산이 크다).

### 6.2 우리 모델에서

| 모델 | 분산 문제 | 이유 |
|---|---|---|
| 단일 트리 | — | 쓰지 않는다 |
| **RF** | 크게 줄어 있다 | 트리 수백 개를 서로 다른 표본·열로 만들어 평균한다(7절 배깅). 분산을 줄이는 것이 RF의 목적이다 |
| **XGBoost** | 통제되어 있다 | 작은 보폭(`learning_rate`), 깊이 제한, `min_child_weight`, `subsample`이 분산을 누른다. 부스팅은 주로 **편향**을 줄이는 방법이라 이 규제들이 중요하다 |

→ 모델 자체의 분산은 이미 처리되어 있다. **남은 분산은 다른 곳에 있다.**

### 6.3 이 프로젝트에 남아 있는 분산

| 분산의 원천 | 지금 상태 | 위험 |
|---|---|---|
| **실행(seed) 분산** | 모든 실험이 `random_state` 42 한 번이다(데이터관점 §6) | 굴뚝 이력 실험의 국내 AP −7%·−8%가 seed만 바꿔도 생기는 차이인지 모른다 |
| 데이터(기간·굴뚝) 분산 | 신뢰 구간 없음 | 일반화 오차 검토 3.3절 — 배출구 단위 부트스트랩 |
| 임계값 분산 | Validation 한 구간에서 F2 최대 1회 | S1-C 임계값 0.0424는 확률이 낮게 몰린 영역이라 조금만 바뀌어도 경보 수가 크게 변할 수 있다 **(추론)** |

### 6.4 분산을 신호로 쓰는 곳 — 불일치 검사

- 정본의 `|RF − XGBoost| ≥ 기준값` 검사는 **두 모델이 갈리는 정도**, 즉 일종의 예측 분산을 위험 신호로 쓴다.
- RF는 트리 수백 개의 예측을 가지고 있다. **트리 간 예측의 표준편차**도 "이 행은 모델이 확신하지 못한다"는 신호가 된다. 추가 학습 없이 계산된다. 불일치 검사를 보완하는 후보로 기록해 둔다 (Could) **(추론: 효과는 미검증)**.

### 6.5 판단

→ **seed 분산을 측정한다.** 채택 결정을 내리는 실험(0단계 Feature 세트, B → B+E → +S)은 seed 3~5개로 돌려 평균과 범위를 적는다. 실험 간 차이가 seed 범위 안이면 "차이 없음"으로 보고 단순한 쪽을 고른다(정본의 동점 규칙과 같은 방향).

## 7. 배깅과 페이스팅 (Bagging & Pasting)

### 7.1 개념

| | 표본 추출 | 대표 예 |
|---|---|---|
| **배깅 (Bagging)** | 각 모델이 학습 행을 **중복을 허용해** 뽑는다(부트스트랩) | RF (`bootstrap=True`, 기본값) |
| **페이스팅 (Pasting)** | 각 모델이 학습 행을 **중복 없이** 뽑는다 | `BaggingClassifier(bootstrap=False, max_samples<1.0)`, XGBoost `subsample<1.0`(트리마다 중복 없이 일부 행) |

공통점: 서로 조금씩 다른 데이터로 여러 모델을 만들어 합쳐 **분산을 줄인다**(6절).

### 7.2 우리 모델에 이미 들어 있다

| 모델 | 방식 | 설정 |
|---|---|---|
| **RF** (분류 사슬, `rf-reg-v1`) | **배깅** + 분할마다 열 일부만 보는 무작위성 | `bootstrap=True`, 하이퍼파라미터 검토의 `max_samples=0.2` 제안 = 트리마다 20%를 중복 허용으로 추출 |
| **XGBoost** | 트리마다 행 일부를 중복 없이 사용 → **페이스팅과 같은 방식**(확률적 그레이디언트 부스팅) | `subsample=0.8` 제안 |

### 7.3 배깅이냐 페이스팅이냐 — RF는 배깅을 유지한다

| 기준 | 배깅 | 페이스팅 | 이 프로젝트 |
|---|---|---|---|
| 성능 | 520만 행에서 20%만 뽑으면 중복 행이 적어 두 방식의 차이가 작다 **(추론)** | 〃 | 차이 없음 |
| **OOB 평가** | 각 트리가 안 쓴 행으로 평가 가능 | 불가 | **배깅이 필요하다.** RF 훈련 오차를 OOB로 재기로 했다(일반화 오차 검토 3.1절) |
| 구현 | RF 기본값 | RF로는 불가(`bootstrap=False`는 페이스팅이 아니라 "전체 행 사용"이다) | RF 그대로 |

### 7.4 시계열 주의 — 행 단위 추출의 한계

- 배깅·페이스팅 모두 **행을 독립적으로** 뽑는다. 30분 간격 행은 이웃끼리 거의 같아서, 어떤 행이 OOB여도 그 앞뒤 행은 학습에 들어가 있다.
- 결과: **RF의 OOB 점수는 실제 시간 분할 성능보다 낙관적이다 (추론).** OOB는 "훈련 오차의 대용"으로만 쓰고, 일반화 성능 판단에는 시간 분할 Validation·Test를 쓴다.
- 굴뚝·기간 단위로 묶어 뽑는 블록 배깅은 scikit-learn RF가 지원하지 않는다. 지금 범위에서는 하지 않는다.

### 7.5 XGBoost를 배깅으로 한 번 더 감싸야 하나

- `BaggingClassifier(XGBClassifier)`처럼 XGBoost 여러 개를 다시 평균하는 방법이 있다.
- **하지 않는다.** 학습 시간이 배로 늘고, 이미 `subsample`·규제로 분산이 통제되어 있으며, 승인 모델 묶음·운영 경로가 복잡해진다. 6.5절 seed 분산이 크게 나올 때만 재검토한다.

### 7.6 판단

→ **이미 적용되어 있다. 추가로 할 것은 설정을 기록하는 일뿐이다.** RF는 배깅(`bootstrap=True`)을 유지하고, OOB가 낙관적이라는 한계를 보고서에 적는다.

## 8. 기법 사이의 연결

```text
           분산 ↓                                   편향 ↓
  ┌────────────────────────┐            ┌──────────────────────────┐
  │ 6. 트리 분산 문제        │            │ 1. 경사하강법             │
  │    └ 7. 배깅 → RF        │            │    └ 그레이디언트 부스팅   │
  │    └ 7. 페이스팅         │            │       → XGBoost          │
  │       → XGBoost subsample│            │ 2. 다항 회귀 (선형 모델용) │
  └────────────┬───────────┘            └────────────┬─────────────┘
               │      3. 학습 곡선: 지금 편향 문제인가, 분산 문제인가?  │
               └────────────────────┬──────────────────┘
                                    ▼
                5. 축 방향 민감성: 모델이 아니라 Feature로 푼다
                   (ratio_pct ✅, 궤적 투영 ⬜)
                4. 로지스틱 회귀: 위 전체의 "선형 기준선"
```

- **학습 곡선(3)이 다른 기법을 고르는 기준이 된다.** Train은 높고 Validation이 낮으면 분산 문제(→ 6·7: 규제, 단순한 조합), 둘 다 낮으면 편향 문제(→ 5: Feature 추가, 1: 트리 수·깊이).
- 국내 전이 하락은 편향·분산 어느 쪽도 아닌 **분포 차이**다. 7개 기법 모두 이 문제를 직접 풀지 못한다. Feature 설계(5)가 그나마 가장 가깝다.

## 10. 요약

- **경사하강법**은 XGBoost 안에 이미 있다. 직접 적용할 것은 없고, `learning_rate`·트리 수·Early Stopping을 이 관점으로 설정한다.
- **다항 회귀**는 필요 없다. 트리가 비선형을 처리한다. 곡률이 필요하면 가속도 Feature로 만든다.
- **학습 곡선**은 꼭 그리기를 권한다. 빠져 있는 Train 성능과 "데이터를 더 모으면 나아지는가"를 한 번에 채운다. x축은 무작위 행 수가 아니라 **학습 개월 수**다.
- **로지스틱 회귀**는 승인 후보가 아니라 **해석용 기준선**으로만 선택적으로 넣는다. 넣으면 스케일링·결측 대체가 필요하다.
- **축 방향 민감성**은 가장 실질적인 항목이다. `ratio_pct`가 이미 하나를 풀었고, "지금 수준 + 상승 속도"의 대각선 경계가 남아 있다. **궤적 투영 Feature**로 대응하고 PCA 회전은 쓰지 않는다.
- **트리의 분산**은 RF·XGBoost가 이미 줄였다. 대신 **seed 한 번짜리 실험**이라는 다른 분산이 남아 있다. seed를 여러 개로 돌린다.
- **배깅과 페이스팅**은 RF(배깅)와 XGBoost `subsample`(페이스팅 방식)로 이미 쓰고 있다. RF는 OOB 때문에 배깅을 유지하고, 시계열이라 OOB가 낙관적이라는 점을 기록한다.
