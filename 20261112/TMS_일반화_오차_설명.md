# TMS 프로젝트 – 샘플의 일반화 오차(Generalization Error)

## 1. 일반화 오차란?

샘플의 일반화 오차는 **모델이 학습할 때 사용하지 않은 새로운 데이터에 적용되었을 때, 실제값과 예측값 사이에 발생하는 오차**를 의미합니다.

쉽게 말하면, 모델이 학습 데이터를 얼마나 잘 외웠는지가 아니라 **처음 보는 데이터에서도 얼마나 정확하게 예측할 수 있는지**를 평가하는 개념입니다.

TMS 프로젝트를 예로 들면, 과거 24개월의 NOx·SO₂ 데이터를 이용해 모델을 학습시킨 후, 학습에 사용하지 않은 이후 기간의 데이터를 입력했을 때 미래 배출비율을 얼마나 정확하게 예측하는지가 일반화 성능과 관련됩니다.

## 2. 일반화 오차가 중요한 이유

머신러닝의 목적은 주어진 학습 데이터를 그대로 재현하는 것이 아닙니다. 학습 데이터에서 발견한 패턴을 바탕으로 앞으로 들어올 새로운 데이터의 결과를 예측하는 것입니다.

예를 들어 다음과 같은 두 모델이 있다고 가정하겠습니다.

- **모델 A:** 학습 데이터에서는 예측 성능이 매우 좋지만, 새로운 데이터에서는 성능이 크게 떨어집니다.
- **모델 B:** 학습 데이터에서는 모델 A보다 성능이 조금 낮지만, 새로운 데이터에서도 비슷한 성능을 유지합니다.

이 경우 실제 운영 환경에서는 모델 B가 더 적합할 수 있습니다.

즉, **학습 데이터에 대한 성능이 높은 것과 실제 운영 환경에서 예측을 잘하는 것은 서로 다른 문제입니다.**

## 3. 훈련 오차와 일반화 오차의 차이

| 구분 | 훈련 오차(Training Error) | 일반화 오차(Generalization Error) |
|---|---|---|
| 평가 대상 | 학습에 사용한 데이터 | 학습에 사용하지 않은 새로운 데이터 전체에 대한 기대 오차 |
| 목적 | 모델이 학습 데이터를 얼마나 잘 학습했는지 확인 | 새로운 데이터에서도 예측을 잘하는지 확인 |
| 실제 측정 | Train 데이터의 실제값과 예측값 비교 | 별도로 보관한 Test 데이터로 추정 |

엄밀히 말하면 일반화 오차는 모델이 앞으로 접하게 될 새로운 데이터 전체에 대한 기대 오차입니다. 미래의 모든 데이터를 미리 확인할 수는 없으므로, 실제로는 별도로 보관한 Test 데이터에서 측정한 오차를 이용해 일반화 오차를 추정합니다.

### 예시

TMS 데이터로 모델을 학습했다고 가정하겠습니다.

| 평가 구분 | 평가 데이터 | 예측 오차(MAE) |
|---|---|---:|
| Train | 학습 데이터 | 2.0 |
| Validation | 모델 비교 데이터 | 3.0 |
| Test | 최종 평가 데이터 | 3.5 |
| 실제 운영 | 새로운 운영 데이터 | 아직 측정 전 |

> 위 수치는 이해를 위한 가상 예시입니다.

- **Train 오차 2.0:** 모델이 학습 데이터에서는 평균적으로 2.0만큼 오차가 발생합니다.
- **Validation 오차 3.0:** 학습에 사용하지 않은 데이터에서는 오차가 커졌습니다.
- **Test 오차 3.5:** 최종 평가 데이터에서도 오차가 발생합니다.
- **실제 운영 데이터:** 향후 새로운 데이터가 유입되면 실제 운영 성능을 별도로 측정해야 합니다.

이 경우 Test 오차 3.5를 일반화 오차의 추정값으로 볼 수 있습니다. 다만 Test 데이터가 실제 운영 데이터를 대표한다는 전제가 필요합니다.

## 4. 일반화 오차가 커지는 주요 원인

### 4.1 과대적합(Overfitting)

모델이 학습 데이터의 일반적인 패턴뿐 아니라 우연한 특징이나 잡음까지 학습한 경우입니다.

예를 들어 특정 굴뚝의 측정 패턴에 지나치게 맞춰 학습하면 다른 굴뚝의 데이터를 입력했을 때 예측 성능이 떨어질 수 있습니다.

| 구분 | 예측 오차(MAE) |
|---|---:|
| Train | 1.0 |
| Validation | 5.0 |
| Test | 5.5 |

훈련 오차는 매우 낮지만 새로운 데이터에서 오차가 크게 증가했습니다.

**개선 방법**
- 모델 복잡도 조정
- Regularization 적용
- Early Stopping 적용
- 불필요한 Feature 제거 검토
- 충분하고 다양한 학습 데이터 확보

### 4.2 과소적합(Underfitting)

모델이 데이터의 패턴을 충분히 학습하지 못한 경우입니다.

예를 들어 실제 배출량은 시간대, 계절, 굴뚝별로 복잡하게 변하는데 지나치게 단순한 모델을 사용하면 학습 데이터에서도 예측 오차가 높게 나타납니다.

| 구분 | 예측 오차(MAE) |
|---|---:|
| Train | 5.0 |
| Validation | 5.5 |
| Test | 5.8 |

Train과 Test 모두 오차가 높은 편입니다.

**개선 방법**
- 예측에 필요한 Feature 추가 및 개선
- 모델 복잡도 조정
- 학습 파라미터 조정
- 시계열 특성을 반영하는 모델 검토

### 4.3 학습 데이터와 실제 운영 데이터의 차이

학습 데이터와 실제 운영 데이터의 특성이 달라지는 경우에도 일반화 오차가 커질 수 있습니다.

예를 들어 다음과 같은 상황입니다.

- 학습 데이터에는 특정 계절의 데이터가 부족합니다.
- 새로운 굴뚝이 운영되기 시작합니다.
- 설비 교체로 측정 패턴이 달라집니다.
- 배출 허용기준이나 운영 조건이 변경됩니다.
- 측정 장비의 교체 또는 보정으로 데이터 특성이 달라집니다.

이러한 현상은 데이터 분포 변화(Data Distribution Shift)와 관련됩니다.

## 5. 일반화 오차를 어떻게 측정하는가?

일반화 오차는 실제로 접하게 될 모든 미래 데이터에 대한 평균 예측 오차를 의미합니다.

수식으로 표현하면 다음과 같습니다.

\[
E_{\text{generalization}}
=
E_{(X,Y)\sim P}
[L(Y,\hat{f}(X))]
\]

- \(X\): 모델 입력 데이터(Feature)
- \(Y\): 실제 정답(Label)
- \(\hat{f}(X)\): 모델의 예측 결과
- \(L\): 실제값과 예측값 사이의 손실 함수
- \(P\): 실제 운영 환경의 데이터 분포

실제 미래 데이터 전체를 알 수 없기 때문에 Test 데이터의 평균 오차를 이용하여 추정합니다.

\[
\hat{E}_{\text{test}}
=
\frac{1}{N}
\sum_{i=1}^{N}
L(y_i,\hat{f}(x_i))
\]

여기서 \(N\)은 Test 데이터의 샘플 수입니다.

즉, Test 데이터에서 계산한 오차가 낮고 Test 데이터가 실제 운영 환경을 잘 대표할수록 일반화 성능이 좋다고 판단할 근거가 됩니다.

## 6. TMS 프로젝트에서 일반화 오차를 확인하는 방법

TMS 프로젝트에서는 분류 모델과 회귀 모델의 목적이 다르므로 일반화 성능을 평가하는 방법도 구분해야 합니다.

### 6.1 분류 모델의 일반화 성능

분류 모델은 향후 배출비율이 위험 수준에 도달하는지를 예측합니다.

현재 프로젝트의 분류 기준은 현재 배출비율이 90% 미만인 데이터 중에서 향후 30분 또는 60분 시점 중 하나라도 90% 이상이면 Label=1로 판단하는 것입니다.

Test 데이터에 모델을 적용한 후 다음 지표를 확인합니다.

| 평가 지표 | 확인 목적 |
|---|---|
| Precision | 위험이라고 예측한 결과 중 실제 위험의 비율 |
| Recall | 실제 위험 사례 중 모델이 찾아낸 비율 |
| F1-score | Precision과 Recall의 균형 |
| PR-AUC | 위험 데이터가 적은 상황에서의 전반적인 분류 성능 |
| Confusion Matrix | 정상과 위험을 각각 얼마나 정확하게 구분했는지 확인 |

예를 들어 Validation에서는 Recall이 90%였지만 Test에서는 60%로 떨어졌다면, 새로운 데이터에서 위험 상황을 탐지하는 능력이 낮아졌다고 볼 수 있습니다.

특히 TMS 프로젝트는 양성 데이터가 약 1.36%로 적기 때문에 Accuracy만 비교해서는 일반화 성능을 제대로 판단하기 어렵습니다.

### 6.2 회귀 모델의 일반화 성능

회귀 모델은 60분 후의 배출비율을 예측합니다.

Test 데이터에 모델을 적용한 후 실제 배출비율과 예측 배출비율의 차이를 측정합니다.

| 평가 지표 | 확인 목적 |
|---|---|
| MAE | 평균적으로 얼마나 차이가 나는지 확인 |
| RMSE | 큰 예측 오차가 얼마나 발생하는지 확인 |

예를 들어 다음과 같은 결과가 나왔다고 가정하겠습니다.

| 구분 | Train MAE | Validation MAE | Test MAE |
|---|---:|---:|---:|
| Random Forest | 2.0 | 3.0 | 3.5 |
| XGBoost | 1.5 | 2.5 | 3.0 |
| LSTM | 1.8 | 2.8 | 3.2 |

> 가상 데이터이며 실제 프로젝트 측정 결과가 아닙니다.

이 경우 XGBoost는 Test MAE가 3.0으로 가장 낮으므로 새로운 데이터에 대한 예측 성능이 가장 좋은 모델로 판단할 수 있습니다.

다만 Test 결과를 확인하기 전에는 Validation 성능을 기준으로 모델을 선택해야 합니다. Test 결과를 반복적으로 확인하면서 모델을 변경하면 Test 데이터가 더 이상 독립적인 최종 평가 자료가 아니게 됩니다.

## 7. 일반화 오차와 과대적합의 관계

일반화 오차를 이해할 때 함께 알아야 하는 개념이 일반화 격차(Generalization Gap)입니다.

일반화 격차는 학습 데이터에서의 오차와 새로운 데이터에서의 오차 사이의 차이를 의미합니다.

\[
Generalization\ Gap
=
Test\ Error - Train\ Error
\]

예를 들어 다음과 같습니다.

| 구분 | Train Error | Test Error | Generalization Gap |
|---|---:|---:|---:|
| 모델 A | 1.0 | 5.0 | 4.0 |
| 모델 B | 2.0 | 3.0 | 1.0 |
| 모델 C | 5.0 | 5.5 | 0.5 |

> 이 표는 개념 설명을 위한 가상 수치입니다.

- **모델 A:** 학습 데이터에서는 성능이 좋지만 새로운 데이터에서 성능이 크게 떨어집니다. 과대적합 가능성이 있습니다.
- **모델 B:** 학습 데이터와 새로운 데이터 모두에서 비교적 좋은 성능을 보입니다.
- **모델 C:** 학습 데이터와 새로운 데이터의 차이는 작지만 두 데이터 모두에서 오차가 높습니다. 과소적합 가능성이 있습니다.

따라서 일반화 격차가 작다고 무조건 좋은 모델은 아닙니다.

**중요한 것은 새로운 데이터에서의 오차 자체가 낮으면서 Train과 Test의 성능 차이도 적절하게 유지되는 것입니다.**

## 8. TMS 프로젝트에서 특히 주의해야 할 사항

TMS는 30분 단위로 측정되는 시계열 데이터이므로 일반적인 이미지나 텍스트 분류 프로젝트와 다른 점이 있습니다.

### 8.1 시간순으로 데이터 분리

무작위로 Train과 Test를 나누면 과거와 미래 데이터가 섞이게 됩니다.

TMS에서는 과거 데이터로 학습하고 이후 데이터로 평가하는 방식이 적합합니다.

예를 들어 다음과 같이 구성할 수 있습니다.

| 구분 | 기간 | 활용 목적 |
|---|---|---|
| Train | 과거 24개월 | 모델 학습 |
| Validation | 이후 6개월 | 모델 비교 |
| Test | 마지막 6개월 | 최종 일반화 성능 평가 |

### 8.2 미래 정보가 학습 데이터에 포함되지 않도록 관리

TMS 분류 Label은 향후 30분 또는 60분의 데이터를 이용해 생성합니다.

따라서 데이터 분할 경계에서 미래 측정값을 이용해 Label을 생성하는 과정이 누수로 이어지지 않도록 주의해야 합니다.

특히 과거 시점의 Feature와 미래 시점의 Label이 어떤 기간의 데이터를 참조하는지 확인해야 합니다.

### 8.3 굴뚝별 일반화 성능 확인

전체 Test 성능만 확인하면 특정 굴뚝에서 예측 성능이 낮은 문제를 발견하지 못할 수 있습니다.

따라서 다음과 같이 세분화해서 확인하는 것이 좋습니다.

- 전체 굴뚝 기준 성능
- 굴뚝별 성능
- NOx와 SO₂별 성능
- 계절별 성능
- 월별 성능
- 위험 수준별 성능

### 8.4 실제 운영 데이터로 지속적인 성능 확인

초기 Test 평가에서 좋은 성능이 나왔다고 해서 실제 운영에서도 계속 좋은 성능을 유지한다고 보장할 수는 없습니다.

새로운 데이터가 들어오면 예측값과 실제 측정값을 비교하고, 성능이 저하되는지 확인해야 합니다.

| 관리 항목 | 확인 내용 |
|---|---|
| 예측 오차 | 실제값과 예측값의 차이 |
| 위험 탐지율 | 실제 위험 사례 중 탐지한 비율 |
| 오경보율 | 정상 상황을 위험으로 판단한 비율 |
| 월별 성능 | 시간 경과에 따른 성능 변화 |
| 굴뚝별 성능 | 특정 굴뚝에서 성능 저하 여부 |

## 9. 교육생에게 강조할 핵심 내용

| 구분 | 핵심 내용 |
|---|---|
| 훈련 오차 | 학습에 사용한 데이터에서 발생하는 오차 |
| 일반화 오차 | 학습하지 않은 새로운 데이터에서 기대되는 오차 |
| Test 오차 | 일반화 오차를 추정하기 위해 Test 데이터에서 계산한 오차 |
| 일반화 격차 | Train 오차와 Test 오차의 차이 |
| 과대적합 | Train 성능은 좋지만 새로운 데이터에서 성능이 나빠지는 현상 |
| 과소적합 | Train과 새로운 데이터 모두에서 성능이 좋지 않은 현상 |

**교육생에게는 다음과 같이 설명하면 이해하기 쉽습니다.**

> 모델을 학습시키는 목적은 학습 데이터를 잘 맞추는 것이 아니라, 앞으로 들어올 새로운 데이터도 정확하게 예측하는 것입니다.
>
> 학습 데이터에서 오차가 낮게 나왔다고 해서 좋은 모델이라고 판단해서는 안 됩니다. 학습에 사용하지 않은 Test 데이터에 모델을 적용하여 실제값과 예측값의 차이를 확인해야 합니다.
>
> 이때 Test 데이터에서 측정한 오차를 통해 모델이 새로운 데이터에서도 얼마나 잘 작동할지 추정할 수 있습니다. 이것이 일반화 오차를 확인하는 이유입니다.
>
> TMS 프로젝트에서는 과거 데이터로 학습한 모델이 미래의 NOx와 SO₂ 배출 패턴에서도 안정적으로 예측할 수 있는지를 확인하는 것이 핵심입니다.

**한 문장으로 정리하면 다음과 같습니다.**

일반화 오차는 모델이 학습하지 않은 새로운 데이터에서도 얼마나 정확하게 예측할 수 있는지를 나타내는 지표이며, 모델의 실제 활용 가능성을 판단하는 중요한 기준입니다.
