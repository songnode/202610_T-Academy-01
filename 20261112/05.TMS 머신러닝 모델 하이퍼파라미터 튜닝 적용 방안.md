# TMS 머신러닝 모델 하이퍼파라미터 튜닝 적용 방안

- 작성일: 2026.11.12
- 대상: 프로젝트 참여 교육생 및 모델 담당(C·E 파트)
- 적용 대상: XGBoost, Random Forest
- 관련 문서: 교차검증 적용 검토, 특성 스케일링 필요성 검토

---

## 1. 검토 배경 및 결론

현재 TMS 프로젝트에서는 XGBoost와 Random Forest를 활용하여 SO₂ 위험 진입 여부와 NOx·SO₂ 농도를 예측하고 있습니다.

모델의 성능을 개선하려면 어떤 Feature를 사용할지 결정하는 것뿐 아니라, 모델의 학습 방식과 복잡도를 조절하는 하이퍼파라미터(Hyperparameter)도 적절하게 설정해야 합니다.

하이퍼파라미터를 무작정 많이 변경하면 실험 시간이 늘어나고, 특정 검증 데이터에만 잘 맞는 설정을 선택할 위험도 있습니다.

따라서 현재 프로젝트에서는 **탐색 범위를 작게 정하고, 동일한 시간 순서 교차검증을 적용하여 모델을 비교하는 방식**을 권장합니다.

### 1.1 권장 적용 방법

| 구분 | 적용 방법 | 목적 |
|---|---|---|
| 탐색 방법 | Grid Search | 사전에 정한 후보 조합을 비교 |
| 교차검증 | 4-Fold Expanding Window | 서로 다른 기간의 성능 비교 |
| XGBoost 트리 수 | Early Stopping | 적절한 학습 반복 횟수 결정 |
| RF 트리 수 | 고정 후 안정성 확인 | 실험 비용과 성능 안정성 관리 |
| 분류 모델 선택 기준 | AP 중심 | 위험 이벤트를 구분하는 순위 성능 평가 |
| 회귀 모델 선택 기준 | MAE 중심 | 실제 농도 예측 오차 비교 |
| 운영 임계값 | 별도 Validation | 실제 경보 판단 기준 결정 |
| 최종 성능 평가 | Test | 선택된 모델의 최종 성능 확인 |

### 1.2 튜닝 시 지켜야 할 원칙

1. Baseline의 실제 학습 설정을 먼저 확인합니다.
2. Feature 세트를 먼저 확정한 후 하이퍼파라미터를 조정합니다.
3. 탐색 조합은 모델별로 약 6개 수준에서 시작합니다.
4. 분류 모델은 AP, 회귀 모델은 MAE를 중심으로 비교합니다.
5. 하이퍼파라미터 선택과 운영 임계값 결정은 별도로 수행합니다.
6. Test 및 국내 TMS 데이터는 튜닝에 사용하지 않습니다.
7. 성능이 비슷하다면 지나치게 복잡한 모델보다 단순한 모델을 우선 검토합니다.

이번 단계에서는 Optuna와 같은 자동 최적화 도구보다 실험 결과를 이해하고 설명하기 쉬운 Grid Search를 우선 적용하는 것이 적절합니다.

## 2. 하이퍼파라미터란?

하이퍼파라미터는 모델이 데이터를 학습하기 전에 사람이 설정하는 학습 조건입니다.

예를 들어 XGBoost에서 트리의 깊이를 설정하는 `max_depth`, 학습률을 설정하는 `learning_rate`, 생성할 트리 수를 설정하는 `n_estimators` 등이 있습니다.

같은 학습 데이터와 Feature를 사용하더라도 하이퍼파라미터 설정에 따라 예측 성능과 모델의 복잡도가 달라질 수 있습니다.

### 2.1 주요 개념

| 용어 | 설명 |
|---|---|
| Feature | 모델이 예측에 사용하는 입력 변수 |
| Hyperparameter | 모델 학습 전에 사람이 설정하는 조건 |
| Baseline | 성능 개선 여부를 비교하기 위한 기준 모델 |
| Grid Search | 미리 정한 후보값 조합을 모두 비교하는 방법 |
| Early Stopping | 검증 성능이 더 이상 개선되지 않으면 학습을 중단하는 방법 |
| Overfitting | 학습 데이터에는 잘 맞지만 새로운 데이터에는 성능이 떨어지는 현상 |

예를 들어 `max_depth`를 3, 5, 7로 설정하면 트리가 데이터를 얼마나 세부적으로 나누어 학습할지 비교할 수 있습니다.

- 깊이가 얕으면 모델이 단순해집니다.
- 깊이가 깊으면 복잡한 패턴을 학습할 수 있지만 과적합 위험도 커질 수 있습니다.

따라서 가장 깊은 트리가 항상 좋은 모델은 아닙니다.

## 3. 하이퍼파라미터 탐색 방법

대표적인 탐색 방법은 Grid Search, Random Search, Bayesian Optimization 등이 있습니다.

| 방법 | 설명 | 장점 | 단점 | 프로젝트 적용 |
|---|---|---|---|---|
| 수동 조정 | 사람이 값을 변경하며 실험 | 간단하고 빠름 | 재현성과 비교가 어려움 | 주 방법으로 사용하지 않음 |
| Grid Search | 정해진 후보 조합을 모두 실험 | 결과 비교가 쉽고 재현 가능 | 후보가 많으면 학습 비용 증가 | 우선 적용 |
| Random Search | 후보 범위에서 무작위로 조합 선택 | 다양한 조합 탐색 가능 | 실험 결과와 후보 관리 필요 | 탐색 범위 확대 시 검토 |
| Bayesian Optimization | 이전 실험 결과를 바탕으로 다음 후보 선택 | 탐색 효율을 높일 수 있음 | 설정과 결과 해석이 상대적으로 복잡 | 현재 단계에서는 보류 |

### 3.1 Grid Search를 우선 적용하는 이유

현재 프로젝트는 대만 CEMS 데이터가 수백만 행 규모이고, 시간 순서 교차검증을 적용할 예정입니다.

이때 파라미터 후보를 지나치게 많이 설정하면 학습 시간이 크게 늘어납니다.

예를 들어 파라미터 3개에 후보값을 각각 5개씩 설정하면 다음과 같이 125개 조합이 만들어집니다.

```text
5 × 5 × 5 = 125개 조합
```

여기에 4-Fold 교차검증을 적용하면 총 500회 학습이 필요합니다.

반면 파라미터 2개에 각각 3개와 2개의 후보값을 설정하면 다음과 같습니다.

```text
3 × 2 = 6개 조합

6개 조합 × 4-Fold = 24회 학습
```

따라서 현재는 **핵심 파라미터 2개를 선정하여 약 6개 조합으로 시작하는 방식**이 적절합니다.

단, 6개라는 숫자는 탐색 규모를 제한하기 위한 출발점이지, 모든 모델에 반드시 적용해야 하는 고정 규칙은 아닙니다.

## 4. 하이퍼파라미터 튜닝 전 데이터 구성

하이퍼파라미터 튜닝은 앞서 정리한 교차검증 데이터 구성을 그대로 사용합니다.

### 4.1 Fold 구성

| 구분 | 학습 데이터 | 검증 데이터 |
|---|---|---|
| Fold 1 | 2023.11 ~ 2024.10 | 2024.11 ~ 2025.01 |
| Fold 2 | 2023.11 ~ 2025.01 | 2025.02 ~ 2025.04 |
| Fold 3 | 2023.11 ~ 2025.04 | 2025.05 ~ 2025.07 |
| Fold 4 | 2023.11 ~ 2025.07 | 2025.08 ~ 2025.10 |

### 4.2 데이터별 역할

| 데이터 | 기간 | 사용 목적 |
|---|---|---|
| Train | 2023.11 ~ 2025.10 | 하이퍼파라미터 탐색 및 교차검증 |
| Validation | 2025.11 ~ 2026.04 | 최종 운영 임계값 및 운영 기준 결정 |
| Test | 2026.05 ~ 2026.10 | 최종 성능 평가 |
| 국내 TMS | 2026.10.31 ~ 2026.11.10 | 외부 데이터 일반화 성능 평가 |

**주의할 점**

- 하이퍼파라미터는 Train 내부의 4-Fold 결과로 선택합니다.
- 기존 Validation은 하이퍼파라미터 후보를 반복 비교하는 데 사용하지 않습니다.
- Test와 국내 TMS는 모델 선택 및 튜닝에 사용하지 않습니다.
- 모든 모델에 동일한 Fold 구성을 적용해야 공정하게 비교할 수 있습니다.

## 5. XGBoost 하이퍼파라미터 튜닝

XGBoost는 여러 개의 의사결정 트리를 순차적으로 생성하면서 이전 모델의 오차를 보완하는 방식으로 학습합니다.

따라서 트리의 복잡도, 학습률, 트리 개수 등이 주요 하이퍼파라미터입니다.

### 5.1 주요 파라미터와 역할

| 파라미터 | 역할 | 값이 커지거나 작아질 때 |
|---|---|---|
| `n_estimators` | 생성할 트리 개수 | 많을수록 학습 반복이 증가 |
| `learning_rate` | 각 트리의 학습 기여도 | 작을수록 일반적으로 더 많은 트리가 필요 |
| `max_depth` | 트리의 최대 깊이 | 깊을수록 복잡한 패턴 학습 가능 |
| `min_child_weight` | 자식 노드 분할에 필요한 최소 Hessian 합 | 커질수록 분할이 보수적으로 이루어짐 |
| `subsample` | 트리 학습에 사용할 행의 비율 | 작을수록 트리별 학습 데이터가 달라짐 |
| `colsample_bytree` | 트리별 사용할 Feature 비율 | 작을수록 Feature 사용이 제한됨 |
| `reg_lambda` | L2 규제 강도 | 커질수록 가중치에 대한 규제가 강해짐 |
| `tree_method` | 트리 생성 방식 | `hist`는 대규모 데이터 처리에 적합 |

`min_child_weight`는 단순히 노드에 들어가는 행의 개수를 의미하지 않습니다. 목적함수의 Hessian 합을 기준으로 분할을 제한하는 값이므로 데이터와 목적함수에 따라 실제 영향이 달라집니다.

### 5.2 XGBoost 탐색 후보

현재 프로젝트에서는 우선 `max_depth`와 `min_child_weight`를 주요 탐색 대상으로 선정하는 것을 제안합니다.

| 파라미터 | 처리 | 후보값 | 비고 |
|---|---|---|---|
| `max_depth` | 탐색 | 4, 6, 8 | 트리 복잡도 비교 |
| `min_child_weight` | 탐색 | 1, 20 | 노드 분할 제한 수준 비교 |
| `n_estimators` | Early Stopping | 상한 2,000 | 실제 트리 수는 조기 종료 결과로 결정 |
| `learning_rate` | 우선 고정 | 0.05 | 초기 실험에서 고정 |
| `subsample` | 우선 고정 | 0.8 | 초기 실험에서 고정 |
| `colsample_bytree` | 우선 고정 | 0.8 | 초기 실험에서 고정 |
| `tree_method` | 고정 | `hist` | 대규모 데이터 학습 |
| `random_state` | 고정 | 42 | 실험 재현성 확보 |

위 후보값은 탐색을 시작하기 위한 제안이며, 현재 데이터에서 검증된 최적값은 아닙니다.

### 5.3 Grid Search 조합

| 조합 | `max_depth` | `min_child_weight` |
|---|---:|---:|
| 1 | 4 | 1 |
| 2 | 4 | 20 |
| 3 | 6 | 1 |
| 4 | 6 | 20 |
| 5 | 8 | 1 |
| 6 | 8 | 20 |

각 조합에 대해 동일한 4-Fold를 적용하고 성능을 비교합니다.

### 5.4 Early Stopping 적용 방법

XGBoost는 `n_estimators`를 무조건 2,000으로 학습할 필요가 없습니다.

학습이 진행되면서 검증 성능이 더 이상 좋아지지 않으면 학습을 중단할 수 있습니다. 이 방법이 Early Stopping입니다.

다만 이번 프로젝트의 교차검증에서는 Fold의 최종 검증 구간을 Early Stopping에 사용하지 않는 것이 중요합니다.

Fold의 검증 구간을 조기 종료 판단과 최종 성능 측정에 모두 사용하면, 해당 구간에 맞춰 학습 반복 횟수가 결정되기 때문입니다.

따라서 다음과 같이 구성합니다.

```text
Fold 1 학습 데이터
│
├─ 내부 학습 구간: 2023.11 ~ 2024.08
│
└─ 내부 Early Stopping 구간: 2024.09 ~ 2024.10

Fold 1 최종 검증 구간
└─ 2024.11 ~ 2025.01
```

위 기간은 설명을 위한 예시입니다. 실제 내부 분할은 Fold별 학습 기간의 마지막 부분을 기준으로 정하고, 라벨 생성에 필요한 미래 구간도 고려해야 합니다.

실행 절차는 다음과 같습니다.

1. Fold 학습 데이터를 시간 순서에 따라 내부 학습 구간과 Early Stopping 구간으로 나눕니다.
2. 내부 학습 구간으로 모델을 학습합니다.
3. 내부 Early Stopping 구간의 성능이 더 이상 개선되지 않으면 학습을 중단합니다.
4. 가장 적절한 트리 개수를 기록합니다.
5. 선택한 트리 개수로 Fold의 전체 학습 데이터를 다시 학습합니다.
6. 해당 Fold의 최종 검증 구간에서 성능을 측정합니다.

이렇게 하면 Fold 검증 데이터는 조기 종료 판단에 사용되지 않고, 모델 성능을 평가하는 용도로만 사용할 수 있습니다.

실제 구현에서는 내부 학습 구간과 Early Stopping 구간 사이에서도 미래 60분 라벨이 경계를 넘어가지 않도록 해야 합니다.

### 5.5 XGBoost 회귀 손실 함수 검토

N1-R과 S1-R은 회귀 모델이므로 학습 손실 함수도 검토할 필요가 있습니다.

| Objective | 설명 | 특징 |
|---|---|---|
| `reg:squarederror` | 제곱 오차 기반 | 큰 오차에 민감 |
| `reg:absoluteerror` | 절대 오차 기반 | MAE 최소화 방향 |
| `reg:pseudohubererror` | Pseudo-Huber 손실 | 제곱 오차와 절대 오차의 특성을 절충 |

현재 회귀 모델은 MAE를 주요 평가 지표로 사용하고 있으므로, 학습 손실 함수와 최종 평가 지표가 반드시 같아야 하는 것은 아니지만 서로 다른 목적을 갖는다는 점을 이해해야 합니다.

권장 진행 순서는 다음과 같습니다.

1. 우선 현재 Baseline의 손실 함수를 확인합니다.
2. 기본 설정을 기준으로 회귀 모델의 성능을 측정합니다.
3. 필요하면 손실 함수 3종을 별도 실험으로 비교합니다.
4. 동일한 Fold에서 MAE와 RMSE를 비교합니다.
5. 실제 고농도 구간의 예측 성능도 함께 확인합니다.

특히 사전 경고 목적을 고려하여 실제 농도가 높은 구간에서의 MAE와 과소예측 비율을 별도 지표로 관리하는 것이 좋습니다.

단, 고농도 구간의 기준은 실험 전에 정의하고, 전체 MAE와 별도로 보고해야 합니다.

## 6. Random Forest 하이퍼파라미터 튜닝

Random Forest는 여러 개의 의사결정 트리를 독립적으로 학습한 뒤 예측 결과를 결합하는 방식입니다.

XGBoost와 달리 트리를 순차적으로 학습하지 않기 때문에 일반적으로 XGBoost와 같은 Early Stopping 방식을 사용하지 않습니다.

### 6.1 주요 파라미터

| 파라미터 | 역할 | 값의 영향 |
|---|---|---|
| `n_estimators` | 생성할 트리 개수 | 트리가 많아지면 예측 안정성이 높아질 수 있지만 학습 비용 증가 |
| `min_samples_leaf` | 리프 노드의 최소 샘플 수 | 커질수록 모델이 단순해짐 |
| `max_features` | 각 분할에서 고려할 Feature 수 | 작을수록 트리 간 다양성이 커질 수 있음 |
| `max_samples` | 각 트리 학습에 사용할 행의 비율 | 작을수록 트리별 학습 데이터가 달라짐 |
| `max_depth` | 트리의 최대 깊이 | 깊을수록 복잡한 패턴 학습 가능 |
| `class_weight` | 클래스별 가중치 | 분류 모델의 클래스 불균형 대응 |

### 6.2 RF 탐색 후보

현재 데이터 규모를 고려하면 트리의 복잡도를 조절하는 `min_samples_leaf`와 `max_features`를 우선 탐색하는 방법을 제안합니다.

| 파라미터 | 처리 | 후보값 | 비고 |
|---|---|---|---|
| `min_samples_leaf` | 탐색 | 50, 200, 1,000 | 리프 노드의 최소 샘플 수 |
| `max_features` | 탐색 | `"sqrt"`, 0.5 | Feature 선택 범위 |
| `n_estimators` | 우선 고정 | 300 | 트리 수 안정성 확인 필요 |
| `max_samples` | 우선 고정 | 0.2 | 트리별 학습 데이터 비율 |
| `max_depth` | 우선 고정 | `None` | 리프 크기를 중심으로 복잡도 조절 |
| `random_state` | 고정 | 42 | 재현성 확보 |
| `n_jobs` | 고정 | -1 | 사용 가능한 CPU 병렬 처리 |

위 값은 실험 출발점입니다. 특히 `min_samples_leaf` 50, 200, 1,000은 현재 데이터의 양성 건수와 Feature 특성을 고려해 실제 학습 전에 적절성을 확인해야 합니다.

데이터가 많다고 해서 리프 크기를 무조건 크게 설정하는 것이 좋은 것은 아닙니다. S1-C처럼 양성 비율이 낮은 분류 문제에서는 지나치게 큰 리프 크기가 소수 클래스의 패턴을 학습하지 못하게 할 수 있습니다.

또한 `max_samples=0.2`는 각 트리가 전체 학습 행의 20%를 사용한다는 의미입니다. 현재 데이터에서는 트리당 학습 행이 상당히 많을 수 있으므로, 학습 시간과 메모리 사용량을 먼저 확인하는 것이 좋습니다.

### 6.3 RF Grid Search 조합

| 조합 | `min_samples_leaf` | `max_features` |
|---|---:|---|
| 1 | 50 | `"sqrt"` |
| 2 | 50 | 0.5 |
| 3 | 200 | `"sqrt"` |
| 4 | 200 | 0.5 |
| 5 | 1,000 | `"sqrt"` |
| 6 | 1,000 | 0.5 |

각 조합에 대해 동일한 4-Fold를 적용합니다.

`n_estimators=300`은 우선 고정하되, 100개·300개·500개 트리에서 성능과 학습 시간이 얼마나 달라지는지 별도 확인할 수 있습니다.

Random Forest는 트리 수가 증가한다고 해서 일반적으로 XGBoost처럼 순차적으로 과적합이 진행되는 구조는 아닙니다. 다만 트리 수가 늘어나면 학습 및 추론 비용이 증가하므로, 충분히 안정적인 수준을 확인한 뒤 고정하는 것이 좋습니다.

## 7. 클래스 불균형 대응: scale_pos_weight 검토

S1-C는 SO₂ 위험 진입 여부를 예측하는 분류 모델입니다.

현재 프로젝트 데이터는 정상 데이터에 비해 위험 이벤트 데이터가 적은 불균형 구조입니다.

이러한 상황에서는 모델이 정상 데이터 위주로 학습되어 위험 이벤트를 제대로 찾아내지 못할 수 있습니다.

XGBoost에서는 `scale_pos_weight`를 사용하여 양성 클래스의 학습 가중치를 조정할 수 있습니다.

### 7.1 scale_pos_weight의 의미

일반적으로 다음과 같은 방식으로 계산할 수 있습니다.

```python
scale_pos_weight = negative_count / positive_count
```

예를 들어 정상 데이터가 100,000건이고 위험 데이터가 1,000건이라면 다음과 같습니다.

```text
scale_pos_weight = 100,000 / 1,000
                 = 100
```

이는 위험 데이터의 학습 손실에 더 큰 가중치를 부여하는 설정입니다.

다만 이 비율을 그대로 적용하는 것이 항상 좋은 것은 아닙니다.

가중치가 지나치게 커지면 오탐이 증가하거나 예측 성능이 오히려 나빠질 수 있습니다.

### 7.2 권장 실험 방법

`scale_pos_weight`는 처음부터 다른 하이퍼파라미터 격자에 모두 포함하기보다는, 기본 구조를 선택한 다음 별도 실험으로 비교하는 것을 권장합니다.

| 실험 | 설정 |
|---|---|
| 실험 A | `scale_pos_weight=1` |
| 실험 B | `scale_pos_weight=√(음성 건수 / 양성 건수)` |
| 실험 C | `scale_pos_weight=음성 건수 / 양성 건수` |

실험할 때는 Fold별 학습 데이터에서 음성 및 양성 건수를 계산해야 합니다. 검증 데이터나 Test 데이터의 클래스 분포를 이용해 가중치를 결정하면 안 됩니다.

### 7.3 평가 기준

각 설정을 다음 항목으로 비교합니다.

- AP
- 동일 Recall 수준에서의 Precision
- Recall
- 오경보 건수 및 비율
- 예측 점수 분포

`scale_pos_weight`를 변경하면 예측 점수의 분포뿐 아니라 트리의 분할 구조와 예측 순위도 달라질 수 있습니다.

따라서 AP가 크게 바뀌지 않을 것이라고 미리 가정하지 말고 실제 결과로 확인해야 합니다.

또한 모델이 출력하는 점수를 실제 발생 확률처럼 화면에 표시하려면 별도의 확률 보정이 필요할 수 있습니다.

가중치를 적용한 모델의 출력값을 곧바로 실제 발생 확률이라고 해석해서는 안 됩니다.

확률 보정이 필요하다면 별도의 보정 절차를 설계하고, 보정에 사용한 데이터와 평가에 사용한 데이터를 분리해야 합니다.

## 8. 모델별 성능 평가 및 선택 기준

하이퍼파라미터를 선택할 때는 모델 유형에 따라 기준을 구분해야 합니다.

### 8.1 S1-C 분류 모델

S1-C는 향후 60분 이내 SO₂ 위험 기준 진입 여부를 예측합니다.

따라서 위험 이벤트를 얼마나 잘 구분하는지 확인할 수 있는 AP를 주요 선택 지표로 사용합니다.

| 지표 | 의미 | 활용 |
|---|---|---|
| AP | Average Precision | 하이퍼파라미터 선택의 주요 기준 |
| Precision | 위험 판정 중 실제 위험 비율 | 오경보 수준 확인 |
| Recall | 실제 위험 중 찾아낸 비율 | 위험 이벤트 누락 수준 확인 |
| F1-score | Precision과 Recall의 조화 평균 | 운영 임계값 평가 |
| F2-score | Recall에 상대적으로 높은 가중치를 둔 조화 평균 | 사전 경고 목적의 운영 기준 평가 |

여기서 중요한 것은 AP와 F1·F2의 차이입니다.

- AP는 모델이 위험 데이터와 정상 데이터를 얼마나 잘 구분하는지, 즉 예측 점수의 순위 성능을 평가합니다.
- F1·F2는 예측 점수에 어떤 임계값을 적용하느냐에 따라 달라집니다.

따라서 하이퍼파라미터는 AP를 중심으로 선택하고, 운영 임계값은 별도 Validation에서 결정하는 것이 적절합니다.

단, AP만 높다고 운영에 적합한 모델이라고 단정할 수는 없습니다. 최종적으로는 Recall과 오경보 수준도 함께 확인해야 합니다.

### 8.2 임계값 결정 규칙은 먼저 확정해야 합니다

현재 프로젝트 문서에는 다음 두 가지 기준이 함께 존재합니다.

| 기준 | 내용 |
|---|---|
| 기준 A | Validation에서 F2-score가 최대가 되는 임계값 선택 |
| 기준 B | Recall 0.6 이상을 만족하는 임계값 중 F1-score가 최대가 되는 값 선택 |

두 기준은 서로 다른 임계값을 선택할 수 있습니다.

따라서 실험을 진행하기 전에 프로젝트의 운영 요구사항에 맞춰 하나의 기준을 확정해야 합니다.

사전 경고 시스템에서 위험 이벤트 누락을 중요하게 본다면 Recall 하한을 두는 방법을 검토할 수 있습니다. 반면 현재 모델의 기존 평가 결과와 연속성을 유지하려면 F2 기준을 유지할 수도 있습니다.

어느 기준을 선택하든 모든 모델에 동일하게 적용하고, 결정 근거를 기록해야 합니다.

**권장 원칙은 다음과 같습니다.**

1. 교차검증에서는 AP를 중심으로 하이퍼파라미터를 선택합니다.
2. 선택된 모델을 고정합니다.
3. 별도 Validation에서 사전에 확정한 임계값 규칙을 적용합니다.
4. Test에서는 선택된 모델과 임계값의 최종 성능을 한 번 평가합니다.

Fold별 최적 F2 임계값을 계산할 수는 있지만, 같은 Fold에서 그 임계값을 최적화하고 F2 성능까지 최종 성능으로 보고해서는 안 됩니다.

### 8.3 N1-R / S1-R 회귀 모델

회귀 모델은 실제 농도와 예측 농도의 차이를 기준으로 비교합니다.

| 지표 | 의미 | 활용 |
|---|---|---|
| MAE | 평균 절대 오차 | 주요 모델 선택 기준 |
| RMSE | 평균 제곱근 오차 | 큰 오차에 대한 민감도 확인 |
| 고농도 구간 MAE | 실제 고농도 구간에서의 평균 오차 | 사전 경고 목적의 예측 성능 확인 |
| 과소예측 비율 | 실제값보다 낮게 예측한 비율 | 위험 수준을 낮게 예측하는 문제 확인 |

현재 프로젝트는 MAE를 주요 평가 지표로 사용하되, RMSE와 고농도 구간의 예측 성능을 함께 확인하는 것을 권장합니다.

특히 사전 경고 시스템에서는 전체 평균 오차가 작더라도 고농도 구간에서 과소예측이 반복되면 운영상 문제가 될 수 있습니다.

따라서 전체 MAE만으로 모델을 선택하지 않도록 합니다.

### 8.4 Persistence Baseline과 비교

N1-R과 S1-R은 XGBoost의 성능만 확인해서는 안 됩니다.

현재 측정값이 60분 후에도 유지된다고 가정하는 Persistence Baseline과 비교해야 합니다.

```python
# Persistence Baseline
predicted_value_t_plus_60 = current_value_t
```

비교할 때는 XGBoost와 Persistence가 동일한 Stack, Item, timestamp 및 유효한 정답 데이터 행을 사용해야 합니다.

다음 지표를 활용할 수 있습니다.

```text
Skill Score = 1 - (XGBoost MAE / Persistence MAE)
```

| 결과 | 의미 |
|---|---|
| Skill Score > 0 | XGBoost가 Persistence보다 우수 |
| Skill Score = 0 | 두 모델의 MAE가 동일 |
| Skill Score < 0 | Persistence가 XGBoost보다 우수 |

이렇게 비교하면 머신러닝 모델이 단순히 현재 농도를 유지하는 예측보다 실제로 얼마나 개선되었는지 확인할 수 있습니다.

## 9. 최종 하이퍼파라미터 선택 방법

Grid Search를 수행한 뒤에는 평균 성능만 보고 가장 높은 조합을 선택하지 않는 것이 좋습니다.

Fold별 성능을 함께 확인해야 합니다.

### 9.1 Fold별 결과 비교

예를 들어 S1-C의 AP가 다음과 같이 측정되었다고 가정하겠습니다.

| 조합 | Fold 1 | Fold 2 | Fold 3 | Fold 4 | 평균 AP |
|---|---:|---:|---:|---:|---:|
| A | 0.82 | 0.81 | 0.83 | 0.82 | 0.82 |
| B | 0.90 | 0.75 | 0.80 | 0.83 | 0.82 |
| C | 0.84 | 0.83 | 0.84 | 0.83 | 0.835 |

C의 평균 AP가 가장 높지만, A와 C의 차이가 크지 않다면 Fold별 편차와 모델 복잡도까지 함께 고려할 수 있습니다.

### 9.2 선택 기준

다음 순서로 판단하는 것을 권장합니다.

1. 평균 AP 또는 평균 MAE를 기준으로 성능이 우수한 조합을 확인합니다.
2. Fold별 성능 편차와 최악의 Fold 성능을 확인합니다.
3. 성능 차이가 작다면 더 단순한 모델을 우선 검토합니다.
4. 특정 Fold에서만 성능이 급격히 떨어지는 조합은 원인을 확인합니다.
5. 최종 선택 근거를 실험 기록에 남깁니다.

성능 차이가 작은 모델을 선택할 때는 다음 기준을 실험 전에 정할 수 있습니다.

- AP 차이가 0.01 이내라면 단순한 모델을 우선 검토
- MAE 차이가 작다면 Fold별 편차와 고농도 구간 성능을 추가 비교
- 복잡도와 성능이 비슷하면 학습 시간과 운영 비용이 적은 모델을 우선 검토

여기서 AP 0.01은 프로젝트에서 사용할 수 있는 출발 기준이지, 통계적으로 검증된 보편적인 기준은 아닙니다.

또한 Fold가 4개이므로 표준편차와 평균만으로 성능 차이가 통계적으로 유의하다고 단정하지 않아야 합니다.

## 10. RF 회귀 모델의 역할과 불일치 기준값

현재 프로젝트에서 RF 회귀 모델은 XGBoost 회귀 모델과 비교하는 역할도 수행합니다.

두 모델의 예측값이 크게 다르면 불일치 신호를 발생시키는 구조를 검토하고 있습니다.

따라서 RF 회귀 모델을 XGBoost와 최대한 비슷하게 만들기 위해 지나치게 튜닝하는 것은 적절하지 않습니다.

두 모델의 예측값이 달라지는 현상 자체가 유용한 점검 신호가 될 수 있기 때문입니다.

다만 두 모델의 예측값이 다르다고 해서 반드시 어느 한 모델이 잘못된 것은 아닙니다. 실제 오차와 과거 검증 결과를 통해 불일치의 의미를 판단해야 합니다.

### 10.1 불일치 기준값 설정 순서

1. XGBoost 회귀 모델을 확정합니다.
2. RF 회귀 모델을 확정합니다.
3. 두 모델의 예측 차이를 Validation에서 측정합니다.
4. 기존 제안인 10%p를 출발점으로 기준값을 검토합니다.
5. 오경보와 실제 이상 징후 탐지 결과를 비교하여 최종 기준을 결정합니다.

불일치 기준값은 모델이 바뀌면 다시 검토해야 합니다.

따라서 두 회귀 모델을 확정하기 전에 불일치 기준값부터 결정하지 않도록 합니다.

## 11. 전체 튜닝 절차

이번 프로젝트의 권장 실험 순서는 다음과 같습니다.

```text
[0] Baseline 설정 확인
    └─ 실제 하이퍼파라미터, random_state, objective,
       scale_pos_weight, Early Stopping 여부 기록

          ↓

[1] Feature 세트 확정
    └─ 입력 Feature와 전처리 방식 확정
       학습 구간 기준 전처리 적용

          ↓

[2] Grid Search + 4-Fold 교차검증
    ├─ XGBoost: max_depth × min_child_weight
    ├─ RF: min_samples_leaf × max_features
    └─ XGBoost는 Fold 학습 데이터 내부에서 Early Stopping

          ↓

[3] 하이퍼파라미터 선택
    └─ 평균 성능, Fold별 편차, 최악의 Fold 확인
       성능 차이가 작으면 단순한 모델 우선

          ↓

[4] 클래스 불균형 별도 실험
    └─ S1-C scale_pos_weight 후보 비교
       AP, 동일 Recall에서의 Precision 등 확인

          ↓

[5] 최종 모델 재학습
    └─ 선택한 설정으로 대만 Train 전체 사용
       XGBoost 트리 수는 Fold별 최적값을 참고하여 결정

          ↓

[6] 운영 임계값 결정
    └─ 별도 Validation 사용
       사전에 확정한 F2 또는 Recall·F1 규칙 적용

          ↓

[7] 회귀 모델 및 불일치 기준 확정
    └─ XGBoost / RF 비교
       Validation에서 불일치 기준 결정

          ↓

[8] 모델 설정 고정 및 Test 평가
    └─ 모델, 임계값, 불일치 기준, 실험 기록 보관
       Test는 최종 평가에만 사용

          ↓

[9] 국내 TMS 외부 평가
    └─ 대만 데이터 기반 모델의 국내 일반화 성능 확인
```

### 11.1 Early Stopping 결과를 최종 학습에 적용하는 방법

4개 Fold에서 선택된 최적 트리 수가 다음과 같다고 가정하겠습니다.

| Fold | 최적 트리 수 |
|---|---:|
| Fold 1 | 420 |
| Fold 2 | 510 |
| Fold 3 | 480 |
| Fold 4 | 550 |

이 경우 최종 트리 수는 4개 Fold의 최적 트리 수 중앙값 등을 참고하여 결정할 수 있습니다.

위 예시의 중앙값은 495입니다.

이 값을 참고하여 Train 전체 데이터로 최종 모델을 학습합니다.

다만 Fold별 학습 데이터 크기가 서로 다르므로 중앙값을 기계적으로 적용하기보다는 Fold별 최적 트리 수의 변화와 성능을 함께 확인해야 합니다.

또한 최종 모델을 Train 전체로 다시 학습할 때는 기존 Validation을 Early Stopping에 사용하지 않습니다. Validation은 운영 임계값을 결정하는 역할로 남겨 둡니다.

## 14. 최종 정리

이번 프로젝트의 하이퍼파라미터 튜닝은 많은 후보를 무작정 실험하는 것이 목적이 아닙니다.

현재 Baseline보다 성능이 개선되는지, 특정 기간에만 좋은 결과가 나오는 것은 아닌지, 실제 운영 환경에서도 활용할 수 있는 모델인지 확인하는 것이 목적입니다.

멘티들이 기억해야 할 핵심은 다음과 같습니다.

1. **먼저 Baseline을 확인합니다.** 기존 모델의 실제 설정을 모르면 개선 여부를 판단할 수 없습니다.
2. **Feature를 먼저 확정합니다.** 입력 데이터가 바뀐 상태에서 하이퍼파라미터 효과를 비교하면 원인을 구분하기 어렵습니다.
3. **탐색 범위는 작게 시작합니다.** XGBoost와 RF 각각 핵심 파라미터 2개를 선정하여 약 6개 조합부터 비교합니다.
4. **시간 순서 교차검증을 적용합니다.** 동일한 4-Fold에서 모든 후보 모델을 비교합니다.
5. **분류와 회귀의 평가 기준을 구분합니다.** 분류는 AP 중심, 회귀는 MAE 중심으로 비교합니다.
6. **운영 임계값은 별도로 결정합니다.** 하이퍼파라미터 선택과 경보 기준 결정은 서로 다른 작업입니다.
7. **성능뿐 아니라 안정성을 확인합니다.** 평균 성능이 높더라도 특정 기간에서 성능이 크게 떨어진다면 원인을 확인해야 합니다.
8. **Test와 국내 TMS는 마지막에 사용합니다.** 최종 모델의 성능과 외부 일반화 가능성을 확인하는 용도로 유지합니다.

결국 좋은 모델은 특정 데이터에서 가장 높은 점수를 기록한 모델이 아니라, **서로 다른 기간에서도 안정적인 성능을 보이고 실제 TMS 사전 경고에 활용할 수 있는 모델**입니다.
