# TMS AI 이상 탐지 프로젝트 – 데이터 품질 및 모델 검증

## 1. 데이터 양의 충분성

**핵심 질문: 학습할 수 있는 데이터가 충분한가?**

데이터가 많다고 해서 반드시 충분한 학습 데이터라고 볼 수는 없습니다. 특히 이상 탐지나 조기 경보 모델은 정상 데이터뿐 아니라 실제 위험 상황을 나타내는 양성 데이터도 충분히 확보해야 합니다.

현재 TMS 프로젝트의 데이터 규모는 다음과 같습니다.

| 구분 | 데이터 건수 |
|---|---:|
| 전체 ML-ready 데이터 | 17,643,361건 |
| 분류 학습 가능 데이터 | 9,857,884건 |
| 분류 양성 데이터 | 133,716건 |
| 회귀 학습 가능 데이터 | 10,687,144건 |

분류 학습 데이터 중 양성 데이터는 약 1.36%이며, 정상 데이터와 양성 데이터의 비율은 약 73:1입니다.

**주요 확인 사항**
- 전체 데이터 건수보다 실제 양성 데이터가 충분한지 확인합니다.
- NOx와 SO₂별 양성 데이터 건수를 구분하여 확인합니다.
- 굴뚝별로 위험 사례가 충분히 분포하는지 확인합니다.
- 특정 기간에 양성 데이터가 집중되어 있지는 않은지 확인합니다.

**TMS 프로젝트 적용:** 양성 데이터가 적은 불균형 문제를 고려하여 Accuracy만으로 모델 성능을 판단하지 않고 Precision, Recall, F1, PR-AUC 등을 함께 평가해야 합니다.

## 2. 훈련 데이터의 대표성 부족

**핵심 질문: 학습 데이터가 실제 운영 환경을 충분히 반영하고 있는가?**

데이터가 충분하더라도 특정 굴뚝이나 특정 기간의 데이터에 편중되어 있다면 새로운 환경에서 예측 성능이 떨어질 수 있습니다.

예를 들어 여름철 데이터 위주로 학습한 모델은 겨울철의 배출 패턴을 제대로 예측하지 못할 수 있습니다.

**주요 확인 사항**
- 굴뚝별 데이터 분포
- NOx와 SO₂별 데이터 분포
- 계절별 및 월별 데이터 분포
- 시간대별 데이터 분포
- 정상 및 위험 수준별 데이터 분포

**TMS 프로젝트 적용:** 굴뚝별·계절별·시간대별 데이터 분포를 분석하여 특정 조건에 데이터가 편중되어 있지 않은지 확인해야 합니다.

---

## 3. 낮은 품질의 훈련 데이터

**핵심 질문: 학습 데이터에 잘못된 값이나 신뢰하기 어려운 데이터가 포함되어 있는가?**

데이터 품질이 낮으면 모델은 실제 패턴이 아닌 데이터 오류까지 학습할 수 있습니다.

TMS 데이터에서는 측정값 결측, 중복, 음수, 비정상적인 극단값, 기준치 변경 등의 문제를 확인해야 합니다.

**주요 확인 사항**

| 점검 항목 | 확인 내용 |
|---|---|
| 결측값 | 측정값 및 필수 Feature의 결측 여부 |
| 중복 데이터 | 동일 굴뚝·측정항목·측정시간의 중복 여부 |
| 음수 데이터 | NOx·SO₂ 측정값의 음수 발생 여부 |
| 극단값 | 비정상적으로 크거나 작은 값의 발생 여부 |
| 기준치 변경 | 허용기준 변경 시점과 변경 영향 구간 확인 |
| 시간 연속성 | 30분 단위 측정 데이터의 누락 여부 |

**TMS 프로젝트 적용:**
- Bronze에서는 원본 데이터를 보존합니다.
- Silver에서는 데이터 정제 및 표준화를 수행합니다.
- ML-ready 단계에서는 학습 적격성과 Feature·Label 생성 기준을 검증합니다.
- 음수나 극단값은 임의로 삭제하지 않고 원본 데이터와 발생 비율을 확인한 후 처리 기준을 결정합니다.

## 4. 관련 없는 특성(Feature) 및 데이터 누수

**핵심 질문: 모델이 예측에 필요한 정보만 학습하고 있는가?**

모델에 불필요한 Feature가 포함되면 학습 성능이 떨어지거나 특정 데이터에 과도하게 의존할 수 있습니다.

또한 미래의 결과를 알 수 있는 정보가 학습 데이터에 포함되면 실제 운영 환경에서는 얻을 수 없는 정보를 이용해 예측하는 데이터 누수(Data Leakage)가 발생합니다.

**주요 확인 사항**
- 각 Feature가 예측 목적과 관련이 있는지 확인합니다.
- Feature 중요도를 분석합니다.
- 서로 유사하거나 중복된 Feature가 있는지 확인합니다.
- 미래 측정값이나 미래 정보를 현재 시점의 Feature로 사용하지 않았는지 확인합니다.
- Label 생성에 사용한 미래 정보가 Feature에 포함되지 않았는지 확인합니다.

**TMS 프로젝트 적용:**

현재 24개 Feature를 대상으로 Feature 중요도와 상관관계를 분석하고, 데이터 누수 여부를 점검해야 합니다.

특히 T+30분 또는 T+60분의 미래 데이터를 활용해 Label을 생성하더라도 해당 미래 데이터가 학습 Feature에 포함되어서는 안 됩니다.

## 5. 훈련 데이터 과대적합(Overfitting)

**핵심 질문: 학습 데이터에서는 성능이 좋은데 새로운 데이터에서는 성능이 떨어지는가?**

과대적합은 모델이 일반적인 패턴을 학습하기보다 훈련 데이터의 세부적인 특징이나 잡음까지 학습한 상태입니다.

예를 들어 훈련 데이터에서는 정확도가 높지만 Validation이나 Test 데이터에서는 성능이 크게 떨어지는 경우입니다.

**주요 확인 사항**
- Train과 Validation 성능 차이
- 모델 복잡도
- 불필요한 Feature 및 잡음
- 특정 굴뚝이나 기간에 대한 과도한 의존성

**개선 방법**
- 모델 복잡도 조정
- 불필요한 Feature 검토
- Regularization 적용
- Early Stopping 적용
- 시간순 Validation을 통한 성능 확인

**TMS 프로젝트 적용:** Random Forest, XGBoost, LSTM 모델의 Train과 Validation 성능을 비교하여 과대적합 여부를 확인해야 합니다.

---

## 6. 훈련 데이터 과소적합(Underfitting)

**핵심 질문: 모델이 데이터의 주요 패턴을 충분히 학습하지 못하고 있는가?**

과소적합은 모델이 너무 단순하거나 학습에 필요한 Feature가 부족하여 데이터의 패턴을 제대로 학습하지 못하는 상태입니다.

훈련 데이터와 Validation 데이터 모두에서 성능이 낮게 나타나는 것이 대표적인 특징입니다.

**주요 확인 사항**
- Train과 Validation 모두 성능이 낮은지 확인합니다.
- Feature가 예측에 필요한 정보를 충분히 포함하는지 확인합니다.
- 모델의 복잡도가 지나치게 낮지 않은지 확인합니다.
- 학습 과정에서 충분히 최적화되었는지 확인합니다.

**개선 방법**
- Feature 추가 및 개선
- 모델 복잡도 조정
- 학습 파라미터 조정
- LSTM 등 시계열 패턴을 학습할 수 있는 모델 검토

**TMS 프로젝트 적용:** 단순 기준 모델인 Persistence를 먼저 평가하고, Random Forest, XGBoost, LSTM과 비교하여 모델의 학습 수준을 확인합니다.

## 7. Holdout 검증

**핵심 질문: 학습에 사용하지 않은 데이터에서도 모델의 성능이 좋은가?**

Holdout은 전체 데이터를 학습용, 검증용, 테스트용으로 분리하여 모델의 성능을 평가하는 방법입니다.

TMS 데이터는 시간의 흐름에 따라 측정되는 시계열 데이터이므로 무작위로 데이터를 분리하기보다는 시간순으로 분리하는 것이 적합합니다.

### 초기 데이터 분할 방안

| 구분 | 기간 | 목적 |
|---|---:|---|
| Train | 24개월 | 모델 학습 |
| Validation | 6개월 | 모델 성능 비교 및 파라미터 조정 |
| Test | 6개월 | 최종 성능 평가 |
| 합계 | 36개월 | 전체 데이터 |

> 위 기간은 초기 실험을 위한 제안이며, 실제 월별 데이터 분포와 양성 데이터 건수를 확인한 후 확정해야 합니다.

### 시간순 분할이 필요한 이유

예를 들어 과거 24개월의 데이터로 학습하고 이후 6개월의 데이터로 검증한 다음, 마지막 6개월의 데이터로 최종 평가합니다.

이렇게 해야 과거 데이터로 학습한 모델이 미래 데이터에서도 제대로 예측하는지 확인할 수 있습니다.

**주의 사항**
- Train, Validation, Test 데이터의 시간 범위가 겹치지 않도록 합니다.
- 미래 데이터가 과거 데이터의 Feature에 포함되지 않도록 합니다.
- Label 생성에 필요한 미래 관측 구간이 데이터 분할 경계를 넘어가는 경우 데이터 누수가 발생하지 않도록 적격성을 확인합니다.
- Test 데이터는 최종 평가 전까지 모델 개선에 반복적으로 사용하지 않습니다.
- 마지막 6개월에 양성 사례가 충분한지 확인합니다.

## 8. 샘플의 일반화 오차(Generalization Error)

**핵심 질문: 학습에 사용하지 않은 새로운 데이터에서도 예측 오차가 작은가?**

일반화 오차는 학습에 사용하지 않은 새로운 데이터에 모델을 적용했을 때 발생하는 예측 오차를 의미합니다.

훈련 데이터에서 성능이 좋더라도 실제 운영 환경에서 성능이 떨어진다면 좋은 모델이라고 할 수 없습니다.

**주요 확인 사항**
- Train과 Test의 성능 차이
- NOx와 SO₂별 예측 성능
- 굴뚝별 예측 성능
- 계절별 및 월별 성능 변화
- 실제 위험 상황에 대한 탐지 성능

**TMS 프로젝트 적용:**

마지막 6개월의 Test 데이터를 이용해 최종 성능을 평가하고, 실제 운영 데이터에서도 예측 성능이 유지되는지 확인해야 합니다.

---

## 9. TMS 프로젝트 모델 평가 지표

데이터 품질과 학습 상태를 확인하는 것뿐 아니라 모델이 실제 예측 목적을 달성하는지 평가해야 합니다.

### 9.1 분류 모델 평가

분류 모델은 향후 배출비율이 위험 수준에 도달할 가능성을 예측하는 데 사용합니다.

현재 프로젝트의 분류 Label 기준은 다음과 같습니다.

- 현재 배출비율이 90% 미만인 데이터 중에서 평가합니다.
- 향후 30분 또는 60분 시점 중 하나라도 90% 이상이면 Label=1입니다.
- 현재 배출비율이 90% 이상이거나 미래 관측이 불가능한 경우 분류 학습 대상에서 제외합니다.

| 평가 지표 | 의미 | TMS 프로젝트에서의 활용 |
|---|---|---|
| Precision | 위험으로 예측한 데이터 중 실제 위험 데이터의 비율 | 오경보 수준 확인 |
| Recall | 실제 위험 데이터 중 모델이 탐지한 비율 | 위험 상황 탐지 능력 확인 |
| F1-score | Precision과 Recall의 조화평균 | 두 지표의 균형 평가 |
| PR-AUC | Precision-Recall 곡선의 면적 | 양성 데이터가 적은 불균형 데이터 평가 |
| Confusion Matrix | 실제값과 예측값의 분포 | 정상·위험 예측 결과 분석 |

특히 양성 데이터 비율이 약 1.36%로 낮기 때문에 Accuracy만으로 모델을 평가하는 것은 적절하지 않습니다.

### 9.2 회귀 모델 평가

회귀 모델은 미래 시점의 배출비율을 예측하는 데 사용합니다.

현재 프로젝트에서는 60분 후 배출비율 예측을 목표로 합니다.

| 평가 지표 | 의미 |
|---|---|
| MAE | 실제값과 예측값 차이의 절대값 평균 |
| RMSE | 오차 제곱 평균의 제곱근으로 큰 오차에 더 큰 영향을 받음 |

회귀 모델은 전체 평균 오차뿐 아니라 실제 위험 수준에 가까운 데이터에서 얼마나 정확하게 예측하는지도 확인해야 합니다.

### 9.3 모델별 비교

초기 모델은 다음과 같이 구성할 수 있습니다.

| 모델 | 목적 및 특징 |
|---|---|
| Persistence | 현재 값이 미래에도 유지된다고 가정하는 기준 모델 |
| Random Forest | 여러 결정 트리를 활용하는 머신러닝 모델 |
| XGBoost | 부스팅 기반 머신러닝 모델 |
| LSTM | 시간에 따른 데이터 패턴을 학습하는 시계열 모델 |

동일한 Train, Validation, Test 데이터와 평가 기준을 적용하여 모델별 성능을 비교해야 합니다.

| 일반화 오차 | 새로운 미래 데이터에서도 오차가 작은가? | 마지막 6개월 Test 및 운영 데이터 평가 |

**특히 다음 세 가지를 중요하게 강조하면 좋겠습니다.**

1. **데이터 양보다 데이터의 다양성과 대표성이 중요합니다.** 전체 데이터가 약 1,764만 행이라고 해서 충분한 학습 데이터라고 단정할 수 없습니다. 실제 위험 사례의 다양성과 굴뚝별·계절별 분포를 확인해야 합니다.

2. **시계열 데이터는 무작위 분할보다 시간순 Holdout이 적합합니다.** 과거 데이터로 학습하고 이후 데이터로 검증해야 실제 미래 예측 성능을 평가할 수 있습니다.

3. **Test 데이터는 최종 성능 평가를 위해 별도로 보존해야 합니다.** Validation 성능을 개선하는 데 반복적으로 사용하면 Test 데이터의 독립성이 훼손됩니다.

현재 제안한 24개월·6개월·6개월 분할은 초기 실험 설계안입니다. 실제 적용 전에는 월별 양성 건수와 계절별 분포를 확인해야 합니다. 특히 마지막 6개월에 양성 사례가 충분하지 않다면 Test 평가의 신뢰성이 낮아질 수 있습니다.

이러한 검증 과정을 통해 단순히 모델을 학습시키는 데 그치지 않고, **실제 TMS 운영 환경에서도 신뢰할 수 있는 예측 모델인지 확인하는 것**이 중요합니다.
