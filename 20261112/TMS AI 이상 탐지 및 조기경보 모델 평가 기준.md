# TMS AI 이상 탐지 및 조기경보 모델 평가 기준

## 1. 평가 목적

TMS 프로젝트의 모델 평가는 학습 데이터에 대한 예측 정확도만 확인하는 것이 아니라, 학습에 사용하지 않은 새로운 데이터에서도 실제 위험 상황을 안정적으로 탐지하고 예측할 수 있는지를 확인하는 데 목적이 있다.

특히 NOx와 SO₂ 배출비율이 기준에 도달하기 전에 위험 상황을 사전에 탐지하는 것이 중요하므로 다음 항목을 종합적으로 평가한다.

1. 실제 위험 상황을 얼마나 놓치지 않고 탐지하는가?
2. 위험 상황이 아닌데 위험하다고 판단하는 오경보는 얼마나 발생하는가?
3. 학습하지 않은 미래 데이터에서도 안정적인 성능을 유지하는가?
4. 60분 후 배출비율을 얼마나 정확하게 예측하는가?
5. 실제 운영 환경에서 경보를 발생시킬 수 있을 만큼 안정적이고 신속하게 동작하는가?

평가는 크게 분류 모델 평가와 회귀 모델 평가로 구분한다.

| 평가 구분 | 평가 목적 | 주요 평가 지표 |
|---|---|---|
| 분류 모델 | 미래 위험 상황 발생 여부 탐지 | Precision, Recall, F1, F2, PR-AUC |
| 회귀 모델 | 미래 배출비율 예측 | MAE, RMSE |
| 운영 성능 | 실제 서비스 적용 가능성 확인 | 처리 시간, 데이터 누락률, 경보 발생 건수 등 |

## 2. 평가 데이터 구성

### 2.1 Train / Validation / Test 데이터 분리

모델 평가를 위해 전체 데이터를 학습용, 검증용, 테스트용으로 분리한다.

| 구분 | 비율(예시) | 용도 |
|---|---:|---|
| Train | 70% | 모델 학습 |
| Validation | 15% | 모델 및 하이퍼파라미터 선택 |
| Test | 15% | 최종 모델의 독립적인 성능 평가 |

TMS 데이터는 시간에 따라 수집되는 시계열 데이터이므로 무작위 분할(Random Split)이 아닌 시간순 분할(Time-based Split)을 적용한다.

예를 들어 전체 36개월 데이터가 있다면 다음과 같이 구성할 수 있다.

- Train: 초기 24개월
- Validation: 다음 6개월
- Test: 마지막 6개월

이 방식은 과거 데이터로 학습한 모델이 이후 기간의 데이터를 얼마나 잘 예측하는지 확인할 수 있다는 장점이 있다.

### 2.2 데이터 분리 시 주의사항

- 미래 데이터를 학습 데이터에 포함하지 않는다.
- Test 데이터는 모델 선택 및 파라미터 조정에 사용하지 않는다.
- Scaler와 같은 전처리 기준은 Train 데이터로만 학습하고 Validation 및 Test에 동일하게 적용한다.
- 미래 T+30분 또는 T+60분 데이터를 활용해 Label을 생성하므로 데이터 분할 경계에서 미래 정보가 다른 구간으로 넘어가지 않도록 주의한다.
- 동일한 굴뚝의 연속 시계열 데이터가 시간순으로 유지되는지 확인한다.

특히 TMS 프로젝트에서는 미래 배출비율을 이용해 분류 Label을 생성하므로 미래 정보가 학습 과정에 유입되는 데이터 누수(Data Leakage)를 방지하는 것이 중요하다.

## 3. 분류 모델 평가

### 3.1 분류 모델의 평가 대상

분류 모델은 현재 배출비율이 90% 미만인 데이터 중 미래 T+30분 또는 T+60분에 배출비율이 90% 이상에 도달하는 위험 상황을 탐지하는 것을 목표로 한다.

| Label | 의미 |
|---|---|
| 1 | 미래 30분 또는 60분 이내에 배출비율이 90% 이상 도달 |
| 0 | 관측 가능한 미래 구간에서 배출비율이 90% 미만 유지 |
| NULL | 현재 배출비율이 90% 이상이거나 미래 관측 데이터가 부족하여 분류 학습 대상에서 제외 |

분류 모델은 실제 위험 상황(Label=1)을 얼마나 잘 탐지하는지, 위험하지 않은 상황(Label=0)을 얼마나 정확하게 구분하는지를 평가한다.

### 3.2 Confusion Matrix(혼동 행렬)

분류 모델의 성능을 이해하기 위해 가장 먼저 확인해야 하는 지표가 Confusion Matrix이다.

Confusion Matrix는 실제 정답과 모델 예측 결과를 비교하여 네 가지 유형으로 구분한다.

| 구분 | 예측 결과 | 실제 의미 | TMS 관점 |
|---|---|---|---|
| TP(True Positive) | 위험 | 실제 위험 | 위험 상황을 정상적으로 탐지 |
| FP(False Positive) | 위험 | 실제 정상 | 위험하지 않은데 경보 발생 |
| FN(False Negative) | 정상 | 실제 위험 | 실제 위험 상황을 놓침 |
| TN(True Negative) | 정상 | 실제 정상 | 정상 상황을 정상으로 판단 |

TMS 프로젝트에서는 특히 FN과 FP를 구분해서 살펴봐야 한다.

- FN(미탐): 실제 위험 상황인데 모델이 탐지하지 못한 경우이다. 조기경보 목적에 비추어 중요한 문제다.
- FP(오탐): 실제로는 위험하지 않은데 경보를 발생시킨 경우이다. 오경보가 많아지면 운영자가 경보를 신뢰하지 않게 될 수 있다.

따라서 미탐을 줄이는 것과 오경보를 관리하는 것 사이의 균형이 중요하다.

### 3.3 Precision(정밀도)

Precision은 모델이 위험하다고 예측한 데이터 중 실제로 위험했던 데이터의 비율이다.

**공식**

Precision = TP / (TP + FP)

**예시**

모델이 위험 경보를 100건 발생시켰고, 그중 실제 위험 상황이 80건이었다면 Precision은 80%이다.

**TMS 관점**

- Precision이 높으면 발생한 경보의 신뢰도가 높다는 의미이다.
- Precision이 낮으면 실제 위험하지 않은 상황에서도 경보가 많이 발생한다는 의미이다.
- 불필요한 경보를 줄이고 운영자가 신뢰할 수 있는 경보를 제공하는 데 중요하다.

### 3.4 Recall(재현율)

Recall은 실제 위험 데이터 중 모델이 위험하다고 정확하게 탐지한 비율이다.

**공식**

Recall = TP / (TP + FN)

**예시**

실제 위험 상황이 100건 발생했고, 모델이 이 중 90건을 탐지했다면 Recall은 90%이다.

**TMS 관점**

- Recall이 높으면 실제 위험 상황을 놓치지 않고 탐지하는 능력이 높다는 의미이다.
- Recall이 낮으면 실제 위험 상황인데도 정상으로 판단하는 미탐이 많다는 의미이다.
- 사전 경보 시스템에서는 특히 중요하게 관리해야 하는 지표이다.

### 3.5 F1-Score

F1-Score는 Precision과 Recall의 조화평균이다.

두 지표를 동일한 비중으로 평가하기 때문에 오탐과 미탐을 균형 있게 고려할 수 있다.

**공식**

F1 = 2 × (Precision × Recall) / (Precision + Recall)

**평가 의미**

- Precision이 높더라도 Recall이 낮으면 F1-Score가 낮아진다.
- Recall이 높더라도 Precision이 낮으면 F1-Score가 낮아진다.
- 두 지표가 모두 높은 모델일수록 F1-Score가 높아진다.

**TMS 관점**

위험 상황을 탐지하면서 불필요한 경보도 적절하게 관리하는 모델을 선택하는 데 활용한다.

### 3.6 F2-Score

F2-Score는 F1-Score와 마찬가지로 Precision과 Recall을 함께 평가하지만, Recall에 더 높은 가중치를 부여한다.

**공식**

F2 = 5 × (Precision × Recall) / (4 × Precision + Recall)

F-beta 공식에서 β=2를 적용한 지표이며, Recall의 중요도가 Precision보다 4배 높은 가중치로 반영된다.

**평가 의미**

- 실제 위험 상황을 놓치지 않는 능력을 더 중요하게 평가한다.
- 오탐이 일부 증가하더라도 미탐을 줄이는 방향의 모델에 상대적으로 유리하다.
- 위험 상황을 사전에 탐지하는 목적에 적합하다.

**TMS 관점**

실제 배출비율이 위험 수준에 도달할 가능성이 있는 상황을 최대한 놓치지 않도록 모델을 평가하는 데 활용한다.

다만 F2-Score가 높다는 이유만으로 모델을 선택해서는 안 된다. 오경보가 지나치게 많으면 운영상 부담이 커질 수 있으므로 Precision도 함께 확인해야 한다.

### 3.7 F1-Score와 F2-Score 비교

| 구분 | F1-Score | F2-Score |
|---|---|---|
| 평가 목적 | Precision과 Recall의 균형 | Recall을 더 중요하게 평가 |
| Precision | 동일한 비중으로 고려 | 상대적으로 낮은 비중 |
| Recall | 동일한 비중으로 고려 | 상대적으로 높은 비중 |
| 미탐 관리 | 중요 | 더 중요하게 반영 |
| 오탐 관리 | 중요 | 상대적으로 덜 중요하게 반영 |
| TMS 활용 | 전체적인 분류 성능 비교 | 위험 상황 미탐 방지 중심 평가 |

### 3.8 PR-AUC(Precision-Recall AUC)

PR-AUC는 Precision-Recall Curve 아래의 면적을 의미한다.

분류 모델은 위험 여부를 판단할 때 예측 확률과 임계값(Threshold)을 사용한다.

예를 들어 위험 확률이 0.5 이상이면 위험으로 판단하도록 설정할 수 있다. 하지만 임계값을 0.3이나 0.7로 변경하면 Precision과 Recall도 달라진다.

PR-AUC는 여러 임계값에서 Precision과 Recall이 어떻게 변화하는지 종합적으로 평가한다.

**TMS 관점**

현재 TMS 분류 데이터는 양성 데이터 비율이 약 1.36%로 낮은 불균형 데이터이다.

이런 환경에서는 정상 데이터를 잘 맞히는 것만으로는 모델의 위험 탐지 성능을 제대로 판단하기 어렵다.

PR-AUC를 활용하면 실제 위험 데이터에 대한 탐지 성능과 경보의 신뢰도를 함께 고려할 수 있다.

- PR-AUC가 높을수록 전반적인 Precision-Recall 성능이 우수하다.
- 양성 데이터가 적은 환경에서 모델 간 성능을 비교하는 데 유용하다.
- 특정 임계값 하나에 종속되지 않고 모델의 전반적인 분류 성능을 비교할 수 있다.

단, PR-AUC가 높다고 실제 운영에 적합한 임계값까지 자동으로 결정되는 것은 아니다.

### 3.9 Accuracy(정확도)를 주요 평가 지표로 사용하지 않는 이유

Accuracy는 전체 예측 데이터 중 정답을 맞힌 비율이다.

Accuracy = (TP + TN) / (TP + TN + FP + FN)

예를 들어 실제 위험 데이터가 1.36%이고 나머지 98.64%가 정상 데이터인 경우, 모든 데이터를 정상이라고 예측해도 Accuracy는 약 98.64%가 된다.

그러나 이 모델은 위험 상황을 하나도 탐지하지 못한다.

따라서 TMS 프로젝트에서는 Accuracy를 참고 지표로 확인할 수 있지만, 주요 모델 선택 기준으로 사용하지 않는 것이 적절하다.

## 4. 분류 모델의 최종 평가 및 선택 기준

### 4.1 평가 지표별 역할

각 평가 지표는 서로 다른 관점에서 모델 성능을 설명한다.

| 평가 지표 | 평가 목적 | 활용 방법 |
|---|---|---|
| Precision | 경보의 신뢰도 | 오경보 수준 확인 |
| Recall | 위험 상황 탐지율 | 미탐 수준 확인 |
| F1-Score | 정밀도와 재현율의 균형 | 일반적인 모델 성능 비교 |
| F2-Score | 위험 상황 탐지 능력 강조 | 미탐을 줄이는 모델 비교 |
| PR-AUC | 여러 임계값에서의 분류 성능 | 불균형 데이터의 모델 비교 |
| Confusion Matrix | 실제 예측 결과의 구성 | TP, FP, FN, TN 분석 |

### 4.2 권장 평가 순서

**1단계: 기본 분류 성능 확인**

모든 후보 모델에 대해 동일한 Test 데이터를 사용하여 Precision, Recall, F1-Score, F2-Score, PR-AUC를 산출한다.

이때 Confusion Matrix도 함께 생성하여 TP, FP, FN, TN의 실제 건수를 확인한다.

**2단계: 미탐과 오탐 수준 비교**

Recall과 FN을 통해 실제 위험 상황을 얼마나 놓쳤는지 확인한다.

Precision과 FP를 통해 불필요한 경보가 얼마나 발생했는지 확인한다.

F2-Score가 높은 모델이라도 FP가 과도하게 발생한다면 운영 적합성이 떨어질 수 있다.

**3단계: 임계값(Threshold) 조정**

모델의 예측 확률을 위험 여부로 변환하는 기준값을 조정한다.

예를 들어 다음과 같이 비교할 수 있다.

| Threshold | Precision | Recall | F1-Score | F2-Score |
|---:|---:|---:|---:|---:|
| 0.3 | 측정값 | 측정값 | 측정값 | 측정값 |
| 0.4 | 측정값 | 측정값 | 측정값 | 측정값 |
| 0.5 | 측정값 | 측정값 | 측정값 | 측정값 |
| 0.6 | 측정값 | 측정값 | 측정값 | 측정값 |
| 0.7 | 측정값 | 측정값 | 측정값 | 측정값 |

위 표는 평가를 위한 예시이며 실제 수치는 모델 예측 결과로 산출한다.

임계값이 낮아지면 일반적으로 위험 경보가 증가하여 Recall이 높아지고 Precision이 낮아질 수 있다. 반대로 임계값이 높아지면 경보가 줄어들고 Precision이 높아지는 대신 Recall이 낮아질 수 있다.

따라서 F2-Score만 가장 높은 임계값을 선택하기보다는 운영상 허용할 수 있는 최소 Precision을 먼저 정하고, 해당 조건을 만족하는 임계값 중 Recall 또는 F2-Score가 높은 지점을 선택하는 방식을 권장한다.

임계값 조정은 Validation 데이터에서 수행하고, 최종 선택된 임계값을 고정한 후 Test 데이터에서 최종 성능을 확인한다.

**4단계: 최종 모델 선정**

다음 조건을 종합하여 최종 모델을 선정한다.

- Recall이 충분히 확보되어 실제 위험 상황을 놓치는 비율이 낮은가?
- Precision이 운영상 허용할 수 있는 수준인가?
- F2-Score가 우수한가?
- PR-AUC를 기준으로 전체적인 분류 성능이 우수한가?
- Test 데이터에서도 성능이 안정적으로 유지되는가?

F2-Score 하나만으로 최종 모델을 결정하지 않고, Recall과 Precision을 함께 확인하는 것이 중요하다.

---

## 5. 회귀 모델 평가

### 5.1 회귀 모델의 평가 대상

회귀 모델은 미래 배출비율을 수치로 예측하는 모델이다.

TMS 프로젝트에서는 현재 시점의 Feature를 이용해 60분 후 NOx 및 SO₂ 배출비율을 예측하는 것을 목표로 한다.

분류 모델이 위험 여부를 판단한다면, 회귀 모델은 미래 배출비율이 어느 정도까지 상승할지를 예측한다.

### 5.2 MAE(Mean Absolute Error)

MAE는 실제값과 예측값의 차이를 절댓값으로 계산한 후 평균을 구한 지표이다.

MAE = 실제값과 예측값 차이의 절댓값 평균

**예시**

실제 배출비율과 예측 배출비율의 평균적인 차이가 3%p라면 MAE는 3%p이다.

**평가 의미**

- MAE가 낮을수록 예측값이 실제값에 가깝다.
- 이상치의 영향을 RMSE보다 상대적으로 적게 받는다.
- 평균적으로 얼마나 오차가 발생하는지 직관적으로 이해하기 쉽다.

### 5.3 RMSE(Root Mean Squared Error)

RMSE는 실제값과 예측값의 차이를 제곱한 후 평균을 구하고, 다시 제곱근을 적용한 지표이다.

RMSE = 실제값과 예측값 차이 제곱의 평균에 제곱근 적용

**평가 의미**

- RMSE가 낮을수록 예측 성능이 좋다.
- 오차가 큰 예측에 더 큰 페널티를 부여한다.
- 특정 시점에 배출비율을 크게 잘못 예측하는 경우를 확인하는 데 유용하다.

### 5.4 MAE와 RMSE 비교

| 구분 | MAE | RMSE |
|---|---|---|
| 평가 방식 | 절대 오차 평균 | 제곱 오차 평균의 제곱근 |
| 큰 오차의 영향 | 상대적으로 작음 | 상대적으로 큼 |
| 주요 목적 | 평균적인 예측 오차 확인 | 큰 예측 오차 확인 |
| 해석 | 평균적으로 얼마나 차이가 나는가? | 큰 오차까지 고려하면 얼마나 차이가 나는가? |

두 지표를 함께 확인하면 평균적인 예측 정확도와 큰 오차 발생 여부를 모두 평가할 수 있다.

### 5.5 회귀 모델 평가 시 주의사항

- Test 데이터에서 실제값과 예측값을 비교한다.
- NOx와 SO₂를 구분하여 평가한다.
- 굴뚝별로 예측 오차의 차이가 있는지 확인한다.
- 배출비율이 낮은 구간과 90%에 근접한 구간의 예측 성능을 구분한다.
- Persistence Baseline과 비교하여 복잡한 모델이 실제로 예측 성능을 개선했는지 확인한다.

특히 Persistence는 미래 배출비율이 현재 배출비율과 동일하다고 가정하는 기준 모델이다.

복잡한 ML 모델이 Persistence보다 MAE와 RMSE를 개선하지 못한다면 모델의 실질적인 활용 가치가 있는지 다시 검토해야 한다.

---

## 6. 모델별 성능 비교

동일한 데이터 분할과 평가 기준을 적용하여 후보 모델의 성능을 비교한다.

### 6.1 분류 모델 비교

| 모델 | Precision | Recall | F1-Score | F2-Score | PR-AUC |
|---|---:|---:|---:|---:|---:|
| Random Forest | 측정값 | 측정값 | 측정값 | 측정값 | 측정값 |
| XGBoost | 측정값 | 측정값 | 측정값 | 측정값 | 측정값 |
| LSTM | 측정값 | 측정값 | 측정값 | 측정값 | 측정값 |

모든 지표는 Validation 데이터에서 모델과 임계값을 선택할 때 활용하고, 최종 Test 성능은 별도로 기록한다.

### 6.2 회귀 모델 비교

| 모델 | MAE | RMSE |
|---|---:|---:|
| Persistence | 측정값 | 측정값 |
| Random Forest | 측정값 | 측정값 |
| XGBoost | 측정값 | 측정값 |
| LSTM | 측정값 | 측정값 |

회귀 모델은 Persistence를 기준으로 다른 모델이 얼마나 오차를 줄였는지 확인한다.

### 6.3 모델 비교 시 공통 조건

공정한 비교를 위해 다음 조건을 동일하게 유지한다.

- 동일한 Train / Validation / Test 분할
- 동일한 Feature 및 Label 기준
- 동일한 평가 대상 데이터
- 동일한 평가 지표 산출 방식
- 동일한 분류 임계값 선정 절차
- 동일한 데이터 전처리 기준

단, 모델별로 필요한 입력 형태와 학습 방식은 다를 수 있으므로 각 모델의 특성에 맞게 학습하되 평가 데이터와 평가 기준은 동일하게 유지한다.

## 7. 일반화 성능 평가

모델이 학습 데이터에만 잘 맞고 새로운 데이터에서는 성능이 떨어지는 현상을 과대적합(Overfitting)이라고 한다.

따라서 Train 성능과 Test 성능을 비교하여 모델의 일반화 성능을 확인해야 한다.

### 7.1 Train과 Test 성능 비교

| 구분 | 확인 목적 |
|---|---|
| Train 성능 | 학습 데이터에 대한 모델의 적합도 확인 |
| Validation 성능 | 모델 및 파라미터 선택 |
| Test 성능 | 학습하지 않은 데이터에 대한 최종 성능 확인 |

### 7.2 일반화 성능 확인 방법

- Train과 Test의 F1-Score, F2-Score, PR-AUC를 비교한다.
- Train과 Test의 MAE, RMSE를 비교한다.
- Train 성능은 높은데 Test 성능이 크게 떨어지는지 확인한다.
- 특정 월이나 계절에만 성능이 떨어지는지 확인한다.
- NOx와 SO₂의 성능 차이를 확인한다.

Train 성능과 Test 성능의 차이가 크다면 과대적합 가능성을 검토한다.

다만 두 성능의 차이가 작더라도 Test 성능 자체가 낮다면 좋은 모델이라고 판단할 수 없다.

궁극적으로는 학습에 사용하지 않은 미래 데이터에서도 충분히 낮은 예측 오차와 안정적인 위험 탐지 성능을 유지해야 한다.

---

## 8. 운영 관점의 추가 평가

모델의 통계적 성능이 우수하더라도 실제 운영 환경에서 사용할 수 없다면 실질적인 활용 가치가 낮다.

따라서 다음 항목도 함께 확인한다.

| 평가 항목 | 확인 내용 |
|---|---|
| 데이터 처리 시간 | 30분 단위 데이터 처리 및 예측이 정해진 시간 내 완료되는가? |
| 데이터 누락률 | 입력 데이터가 누락되거나 비정상적으로 수집되는 비율은 얼마인가? |
| 경보 발생 건수 | 시간별·일별 경보 발생 건수는 적절한가? |
| 경보 중복 | 동일한 위험 상황에 경보가 반복 발생하지 않는가? |
| 경보 선행 시간 | 실제 위험 수준 도달 전에 얼마나 일찍 탐지하는가? |
| 운영 안정성 | 데이터 오류나 모델 실행 실패 시에도 안정적으로 동작하는가? |

특히 TMS 조기경보 시스템에서는 일반적인 분류 성능 외에 **경보 선행 시간**을 별도로 평가하는 것이 중요하다.

예를 들어 실제 배출비율이 90%에 도달하기 30분 전에 탐지했는지, 60분 전에 탐지했는지를 확인하면 모델의 조기경보 활용 가치를 더 구체적으로 판단할 수 있다.

단, 경보 선행 시간은 단순한 분류 지표와 별도로 정의해야 하며, 실제 위험 발생 시점과 최초 경보 시점을 기준으로 산출한다.

---

## 9. 최종 평가 체계 및 권장 방향

TMS 프로젝트에서는 다음과 같은 평가 체계를 권장한다.

| 평가 영역 | 주요 지표 | 평가 목적 | 중요도 |
|---|---|---|---|
| 위험 탐지 능력 | Recall | 실제 위험 상황을 놓치지 않는가? | 매우 중요 |
| 경보 신뢰도 | Precision | 발생한 경보가 실제 위험과 일치하는가? | 매우 중요 |
| 종합 분류 성능 | F1-Score | Precision과 Recall의 균형이 좋은가? | 중요 |
| 위험 탐지 중심 성능 | F2-Score | 미탐을 줄이는 데 유리한가? | 매우 중요 |
| 전체 분류 성능 | PR-AUC | 불균형 데이터에서 전반적인 분류 성능이 좋은가? | 중요 |
| 미래 예측 정확도 | MAE, RMSE | 미래 배출비율을 정확하게 예측하는가? | 중요 |
| 운영 성능 | 처리 시간, 경보 선행 시간 등 | 실제 운영에 적용할 수 있는가? | 중요 |

### 9.1 권장 모델 선정 절차

1. Random Forest, XGBoost, LSTM 등 후보 모델을 학습한다.
2. Validation 데이터에서 Precision, Recall, F1-Score, F2-Score, PR-AUC를 산출한다.
3. Confusion Matrix를 통해 FP와 FN 발생 건수를 확인한다.
4. Validation 데이터에서 임계값을 조정한다.
5. 운영상 허용할 수 있는 Precision 수준을 만족하는 후보 중 Recall과 F2-Score가 우수한 모델을 선정한다.
6. 선정된 모델과 임계값을 고정한다.
7. Test 데이터에서 최종 분류 성능을 평가한다.
8. 회귀 모델은 MAE와 RMSE를 Persistence Baseline과 비교한다.
9. Test 결과를 NOx/SO₂, 굴뚝별, 기간별로 나누어 성능 편차를 확인한다.
10. 처리 시간과 경보 선행 시간 등 운영 관점의 성능을 확인한다.

### 9.2 최종 평가 결과 작성 예시

최종 보고서에는 단순히 모델별 점수만 나열하지 않고 다음 내용을 포함하는 것이 좋다.

- 어떤 모델의 Recall이 가장 높았는가?
- 실제 위험 상황을 놓친 FN은 몇 건인가?
- 오경보 FP는 몇 건인가?
- F1-Score와 F2-Score 중 어떤 지표에서 강점을 보였는가?
- 임계값 변경에 따라 Precision과 Recall은 어떻게 변화했는가?
- Test 데이터에서도 Validation과 유사한 성능을 유지했는가?
- Persistence보다 미래 배출비율 예측 성능이 개선되었는가?
- 실제 위험 수준에 도달하기 전에 충분한 경보 선행 시간을 확보했는가?

## 10. 교육생에게 강조할 내용

모델 평가에서 가장 중요한 것은 높은 점수 하나를 만드는 것이 아니라, **모델이 어떤 상황에서 잘 작동하고 어떤 상황에서 실패하는지 정확하게 파악하는 것**이다.

특히 TMS 프로젝트에서는 다음 사항을 기억해야 한다.

1. Accuracy가 높다고 좋은 모델은 아니다. 양성 데이터가 적기 때문에 실제 위험 상황을 놓치고도 높은 Accuracy가 나올 수 있다.
2. Precision은 경보의 신뢰도를 나타내고, Recall은 실제 위험 상황을 얼마나 놓치지 않았는지를 나타낸다.
3. F1-Score는 Precision과 Recall의 균형을 평가하고, F2-Score는 Recall을 더 중요하게 평가한다.
4. PR-AUC는 불균형 데이터에서 여러 임계값에 걸친 분류 성능을 비교하는 데 유용하다.
5. F2-Score가 높더라도 오경보가 지나치게 많으면 실제 운영에 적합하지 않을 수 있다.
6. Test 데이터는 최종 성능 평가를 위한 독립적인 데이터이므로 모델 선택이나 임계값 조정에 반복적으로 사용하면 안 된다.
7. 회귀 모델은 MAE와 RMSE를 통해 실제 배출비율과 예측 배출비율의 차이를 확인해야 한다.
8. 최종적으로는 새로운 미래 데이터에서도 위험 상황을 안정적으로 탐지하고, 운영자가 활용할 수 있는 수준의 경보를 제공하는지가 중요하다.

**핵심 정리**

> TMS AI 모델의 평가는 위험 상황을 얼마나 잘 탐지하는지(Recall), 발생한 경보를 얼마나 신뢰할 수 있는지(Precision), 두 성능의 균형이 적절한지(F1-Score), 위험 상황을 놓치지 않는 데 얼마나 유리한지(F2-Score)를 함께 확인해야 한다. 여기에 PR-AUC와 회귀 오차(MAE, RMSE), 실제 운영 성능까지 종합적으로 검토하여 최종 모델을 선정해야 한다.
