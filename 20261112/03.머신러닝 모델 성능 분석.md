# 머신러닝 모델 성능 분석 및 보완 멘토링

## 1. 멘토링 목적

이번 멘토링에서는 교육생이 개발한 3개 머신러닝 모델의 성능을 점검하고, 실제 운영에 활용할 수 있는 수준인지 확인합니다.

단순히 성능 지표가 높고 낮은지를 보는 것보다 다음 세 가지를 중점적으로 확인하려고 합니다.

1. **기준 성능 비교:** 머신러닝 모델이 Persistence보다 실제로 예측을 잘하는가?
2. **위험 구간 예측:** 배출 비율이 높은 구간에서 위험을 놓치지 않고 예측하는가?
3. **결과의 신뢰성:** 모델, 학습 데이터, Feature, 설정 정보를 추적하고 동일한 결과를 재현할 수 있는가?

현재 제출된 성능 보고서 기준입니다.

| 모델 | 예측 대상 | Test 주요 성능 | 핵심 점검 사항 |
|---|---|---|---|

## 3. 모델별 성능 점검

### 3.1 S1-C: SO₂ 위험 구간 분류 모델

**예측 목적**

현재 측정값을 바탕으로 향후 60분 이내에 SO₂ 배출 비율이 위험 기준인 90%에 도달하는지를 예측합니다.

**Test 성능**

| 평가 지표 | 결과 | 의미 |
|---|---:|---|
| Precision | 15.43% | 위험으로 예측한 건 중 실제 위험인 비율 |
| Recall | 46.23% | 실제 위험 사례 중 모델이 찾아낸 비율 |
| F2 | 0.3304 | Precision보다 Recall에 더 비중을 둔 종합 지표 |
| AP | 0.1611 | 여러 판정 기준에서의 Precision-Recall 성능 |

**핵심 해석**

- 실제 위험 사례의 약 46%를 찾아냈지만, 약 54%는 놓쳤습니다.
- 위험으로 예측한 사례 중 실제 위험이 아닌 비율은 약 84.57%입니다.
- 따라서 현재 성능만으로는 운영에 적합하다고 판단하기 어렵습니다.
- 위험 기준에 도달하는 사례 자체가 Test 데이터의 약 0.86%로 적기 때문에, 불균형 데이터 특성을 고려해야 합니다.

**멘토링 질문**

1. Precision이 15.43%로 낮은데, 오경보를 줄이기 위한 개선 방법은 무엇인가요?
2. Recall이 46.23%라는 것은 실제 위험 사례의 절반 이상을 놓친다는 의미인데, 이를 어떻게 개선할 수 있을까요?
3. 현재 적용한 임계값 0.0424는 어떤 기준으로 결정했나요?

**추가 확인**

0.0424는 모델의 예측 점수에 적용한 판정 임계값입니다. 반드시 보정된 위험 확률을 의미하는 것은 아니므로, 보고서에 '확률'이라고 표현하지 않도록 주의해야 합니다.

Validation의 혼동행렬과 실제 위험 비율도 추가로 산출해 Test 결과와 함께 비교할 필요가 있습니다.

현재 수치만으로 예측 성능이 좋다고 단정할 수는 없습니다. 현재 측정값을 그대로 사용하는 Persistence 기준선과 비교해야 실제 개선 여부를 판단할 수 있습니다.

2. XGBoost가 Persistence보다 오차를 얼마나 줄였나요?
3. 예측 오차가 큰 상위 사례에서는 어떤 특징이 나타나나요?

## 4. 회귀 모델의 핵심 평가: Persistence 기준선 비교

이번 회귀 모델 평가에서 가장 중요한 보완 사항입니다.

현재 N1-R과 S1-R은 MAE와 RMSE를 산출했지만, Persistence 기준선과 비교한 결과가 없습니다.

따라서 현재 성능 수치만으로 머신러닝 모델이 실제로 예측 성능을 개선했다고 결론 내리기는 어렵습니다.

### 4.1 Persistence란?

Persistence는 **현재 측정값이 미래에도 그대로 유지된다고 가정하는 가장 단순한 기준 예측 방법**입니다.

예를 들어 현재 NOx 배출 비율이 65%라면, 60분 후에도 65%일 것으로 예측합니다.

수식은 다음과 같습니다.

\[
\hat{y}_{t+60}=y_t
\]

- \(y_t\): 현재 시점의 실제 측정값
- \(\hat{y}_{t+60}\): 60분 후 예측값

별도의 머신러닝 학습 없이 현재 측정값을 그대로 미래 예측값으로 사용하는 방식입니다.

### 4.2 TMS 데이터에서 산출하는 방법

이번 프로젝트는 30분 단위 데이터이므로 60분 후 값은 현재 시점에서 두 행 뒤의 값에 해당합니다.

예를 들어 다음과 같습니다.

| 측정 시각 | 현재 측정값 | 60분 후 실제값 | Persistence 예측값 |
|---|---:|---:|---:|
| 10:00 | 65 | 68 | 65 |
| 10:30 | 70 | 75 | 70 |
| 11:00 | 68 | 72 | 68 |
| 11:30 | 75 | 80 | 75 |
| 12:00 | 72 | 70 | 72 |

10:00의 현재 측정값은 65%입니다. 따라서 Persistence는 60분 후에도 65%라고 예측합니다. 실제 60분 후 값이 68%라면 예측 오차는 3%p입니다.

실제 데이터에서는 반드시 설비 또는 굴뚝과 측정 항목별로 정렬한 후 60분 후 값을 연결해야 합니다. 단순히 전체 데이터를 정렬해 두 행 뒤의 값을 가져오면 다른 설비나 측정 항목의 데이터가 섞일 수 있습니다.

### 4.3 Persistence 성능 산출

Persistence 예측값과 60분 후 실제값을 이용해 MAE와 RMSE를 계산합니다.

**MAE**

\[
MAE=\frac{1}{N}\sum_{i=1}^{N}|y_i-\hat{y}_i|
\]

실제값과 예측값의 절대 오차 평균입니다.

**RMSE**

\[
RMSE=\sqrt{\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat{y}_i)^2}
\]

오차를 제곱하기 때문에 큰 오차에 더 큰 영향을 받습니다.

두 지표 모두 Persistence와 XGBoost에 동일한 평가 행을 적용해야 합니다.

### 4.4 머신러닝 모델과 비교

| 평가 대상 | Persistence | XGBoost |
|---|---:|---:|
| NOx MAE | 산출 필요 | 4.2547 |
| NOx RMSE | 산출 필요 | 7.3464 |
| SO₂ MAE | 산출 필요 | 3.2406 |
| SO₂ RMSE | 산출 필요 | 7.5055 |

Persistence 기준선보다 XGBoost의 MAE와 RMSE가 모두 낮다면, 평균적인 오차와 큰 오차 측면에서 개선되었다고 볼 수 있습니다.

반대로 XGBoost의 성능이 Persistence보다 낮다면, 복잡한 머신러닝 모델을 사용했음에도 단순히 현재값을 유지한다고 예측하는 것보다 성능이 좋지 않다는 의미입니다.

### 4.5 Persistence 대비 개선율(Skill Score)

MAE 기준으로 개선율을 계산할 수 있습니다.

\[
Skill\ Score=1-\frac{MAE_{Model}}{MAE_{Persistence}}
\]

예를 들어 다음과 같습니다.

- Persistence MAE: 5.0
- XGBoost MAE: 4.0

\[
1-\frac{4.0}{5.0}=0.2
\]

즉, Persistence 대비 MAE가 20% 감소한 것입니다.

Skill Score가 양수이면 Persistence보다 개선된 것이고, 0이면 동일하며, 음수이면 Persistence보다 성능이 낮은 것입니다.

**중요한 것은 Persistence와 XGBoost가 동일한 Test 데이터, 동일한 예측 시점, 동일한 실제 목표값으로 평가되어야 한다는 점입니다.**

## 5. 세 모델 공통 보완 사항

### 5.1 위험 구간에서의 성능 확인

전체 데이터의 평균 성능만으로는 실제 운영에 필요한 예측 능력을 판단하기 어렵습니다.

특히 TMS에서는 배출 비율이 높은 구간에서 얼마나 정확하게 예측하는지가 중요합니다.

회귀 모델은 실제 60분 후 배출 비율을 기준으로 다음 구간별 MAE와 과소 예측 비율을 산출하도록 합니다.

| 실제 배출 비율 구간 | 확인할 내용 |
|---|---|
| 50% 미만 | 일반 구간 예측 성능 |
| 50~70% | 중간 구간 예측 성능 |
| 70~85% | 위험 접근 구간 예측 성능 |
| 85~90% | 위험 임계값 직전 예측 성능 |
| 90% 이상 | 실제 위험 구간 예측 성능 |

특히 실제값보다 예측값이 낮은 과소 예측이 얼마나 발생하는지 확인해야 합니다.

### 5.2 큰 오차 사례 분석

MAE와 RMSE만으로는 어떤 데이터에서 예측이 실패했는지 알기 어렵습니다.

다음 항목을 추가로 확인하도록 합니다.

- 오차 상위 1% 데이터 추출
- 오차 P50, P90, P95, P99 산출
- 월별 또는 설비별 MAE, RMSE 비교
- 위험 구간에서의 과소 예측 비율 확인

특히 S1-R은 RMSE가 MAE에 비해 상대적으로 높으므로 큰 오차 사례를 우선 분석하는 것이 좋겠습니다.

### 5.3 모델 및 데이터 추적성 확인

현재 성능 보고서만으로는 모델과 학습 데이터의 연결 관계를 충분히 확인하기 어렵습니다.

다음 정보를 확인해야 합니다.

- 모델 ID 및 모델 버전
- 학습 데이터 기간과 데이터 출처
- 사용한 Feature 목록
- 학습 설정 및 하이퍼파라미터
- 학습 Job ID 및 모델 저장 S3 경로
- `metadata.json`과 `metrics.json`의 연결 관계

특히 N1-R과 S1-R은 원본 예측 결과 행이 제공되지 않아 MAE와 RMSE를 독립적으로 재계산하기 어렵습니다. 예측값과 실제값이 포함된 평가 결과도 확보할 필요가 있습니다.

## 8. 멘토링 마무리

이번 모델 개발에서 중요한 것은 모델을 학습하고 성능 지표를 산출했다는 사실 자체가 아닙니다.

**기존의 단순한 기준 예측보다 얼마나 개선되었는지, 실제 위험 구간에서도 신뢰할 수 있는 결과를 제공하는지를 확인하는 것이 중요합니다.**

특히 회귀 모델은 Persistence와의 비교가 먼저 이루어져야 합니다. 그 결과를 바탕으로 XGBoost가 실제로 필요한 모델인지 판단할 수 있습니다.

교육생들에게는 다음과 같이 전달하면 좋겠습니다.

> 모델을 만들고 성능 지표를 산출한 것까지는 잘 진행했습니다. 이제는 한 단계 더 나아가서, 현재 측정값을 그대로 사용하는 Persistence보다 얼마나 잘 예측하는지 확인해 봅시다. 그리고 평균적인 성능뿐 아니라 실제 위험 구간에서도 제대로 예측하는지 살펴보면 좋겠습니다. 이런 검증이 이루어져야 실제 현장에서 활용할 수 있는 모델이라고 이야기할 수 있습니다.
