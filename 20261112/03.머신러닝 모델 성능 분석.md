# 머신러닝 모델 성능 분석

## 1. 멘토링 목적

이번 멘토링은 교육생이 개발한 머신러닝 모델 3종의 성능을 객관적으로 점검하고, 실제 TMS 사전 경고 시스템에 활용하기 위해 무엇을 보완해야 하는지 이해하는 데 목적이 있습니다.

현재 모델은 학습과 기본 성능 평가까지 진행되었습니다. 이제는 단순히 성능 지표를 산출하는 단계에서 벗어나, **모델이 기존 예측 방법보다 실제로 나은지, 위험 상황을 제대로 예측하는지, 결과를 신뢰하고 재현할 수 있는지** 확인해야 합니다.

이번 멘토링에서는 다음 네 가지를 중점적으로 다룹니다.

1. 모델별 성능을 정확하게 해석하고 현재 수준을 판단합니다.
2. Persistence 기준선과 비교하여 머신러닝의 실제 성능 개선 여부를 확인합니다.
3. 위험 구간 예측과 큰 오차 사례를 분석하여 운영상 한계를 파악합니다.
4. 모델·데이터·Feature·학습 설정을 연결하여 결과의 신뢰성과 재현성을 확보합니다.

## 2. 개발 모델 및 성능 요약

현재 검토 대상은 SO₂ 분류 모델 S1-C와 NOx·SO₂ 회귀 모델 N1-R, S1-R입니다.

| 모델 | 예측 유형 | 예측 목적 | Test 주요 성능 |
|---|---|---|---|
| S1-C | 분류(Classification) | 향후 60분 이내 SO₂ 위험 기준(90%) 진입 여부 | Precision 15.43%, Recall 46.23%, F2 0.3304, AP 0.1611 |
| N1-R | 회귀(Regression) | 정확히 60분 후 NOx 배출 비율 예측 | MAE 4.2547, RMSE 7.3464 |
| S1-R | 회귀(Regression) | 정확히 60분 후 SO₂ 배출 비율 예측 | MAE 3.2406, RMSE 7.5055 |

**공통 조건**

- 알고리즘: XGBoost V1.0 Baseline
- 데이터: 대만 CEMS
- 데이터 단위: 30분 간격
- 분류: 향후 60분 이내 위험 기준 진입 여부 예측
- 회귀: 정확히 60분 후 배출 비율 예측

※ 분류 모델과 회귀 모델은 예측 목적과 평가 지표가 다르므로 성능 숫자를 직접 비교하면 안 됩니다. 회귀의 MAE와 RMSE는 배출 비율의 오차(%p)입니다.

## 3. 모델별 성능 진단

### 3.1 S1-C: SO₂ 위험 구간 분류 모델

**① 모델의 역할**

현재 측정 데이터와 Feature를 이용하여 향후 60분 이내에 SO₂ 배출 비율이 위험 기준인 90%에 도달하는지를 예측합니다.

즉, 미래의 위험 발생 가능성을 사전에 찾아내는 모델입니다.

**② Test 성능**

| 평가 지표 | 결과 | 해석 |
|---|---:|---|
| Precision | 15.43% | 위험으로 예측한 건 중 실제 위험인 비율 |
| Recall | 46.23% | 실제 위험 사례 중 찾아낸 비율 |
| F2 | 0.3304 | Recall에 더 큰 비중을 둔 종합 지표 |
| AP | 0.1611 | 여러 판정 임계값에서의 Precision-Recall 성능 |

**③ 핵심 진단**

- 실제 위험 사례의 약 46.23%를 찾아냈습니다.
- 반대로 실제 위험 사례의 약 53.77%는 놓쳤습니다.
- 위험으로 예측한 사례 중 실제 위험이 아닌 비율은 84.57%입니다.
- Test 데이터의 실제 양성 비율은 약 0.86%로, 위험 사례가 매우 적은 불균형 데이터입니다.

현재 모델은 위험 사례를 일부 찾아내고 있지만, 오경보가 많고 실제 위험을 놓치는 비율도 높습니다. 따라서 현재 결과만으로 운영에 적합하다고 판단하기는 어렵습니다.

**④ 교육생에게 설명할 핵심**

Precision과 Recall은 서로 다른 관점의 지표입니다.

- Precision이 낮다는 것은 위험이라고 예측한 결과 중 실제 위험이 아닌 사례가 많다는 의미입니다.
- Recall이 낮다는 것은 실제 위험이 발생했는데도 모델이 찾아내지 못한 사례가 많다는 의미입니다.

사전 경고 시스템에서는 위험을 놓치지 않는 것도 중요하지만, 오경보가 지나치게 많으면 운영자가 경고를 신뢰하지 않게 됩니다.

따라서 두 지표 사이의 균형을 고려해야 합니다.

**⑤ 멘토링 질문**

1. Precision이 15.43%로 낮은데, 오경보를 줄이기 위한 방법은 무엇인가요?
2. Recall이 46.23%라는 것은 실제 위험의 절반 이상을 놓친다는 의미인데, 이를 개선할 방법은 무엇인가요?
3. 현재 사용한 임계값 0.0424는 어떤 기준으로 결정했나요?
4. 임계값을 변경하면 Precision과 Recall은 어떻게 달라지나요?

**추가 확인 사항**

- 0.0424는 모델 예측 점수에 적용한 판정 임계값입니다. 보정된 위험 확률이라고 단정하면 안 됩니다.
- Validation 혼동행렬과 양성 비율이 누락되어 있으므로 추가 산출이 필요합니다.
- 현재값 기준 규칙과의 비교도 필요합니다.

### 3.2 N1-R: NOx 회귀 모델

**① 모델의 역할**

현재 NOx 측정값과 관련 Feature를 이용하여 정확히 60분 후의 NOx 배출 비율을 예측합니다.

분류 모델이 위험 여부를 판단한다면, 회귀 모델은 미래의 실제 배출 수준을 수치로 예측합니다.

**② Test 성능**

| 평가 지표 | 결과 | 해석 |
|---|---:|---|
| MAE | 4.2547%p | 실제값과 예측값의 평균 절대 오차 |
| RMSE | 7.3464%p | 큰 오차에 더 큰 영향을 받는 오차 지표 |

Validation 결과는 MAE 4.2702, RMSE 7.6284입니다.

**③ 핵심 진단**

- Test MAE는 약 4.25%p입니다.
- Test RMSE는 약 7.35%p입니다.
- Validation과 Test의 지표 차이는 크지 않습니다.
- 하지만 현재 결과만으로 예측 성능이 좋은지 판단할 수는 없습니다.

가장 중요한 이유는 비교 기준선이 없기 때문입니다.

현재 측정값을 그대로 60분 후 값이라고 예측하는 Persistence보다 XGBoost가 더 정확한지 확인해야 합니다.

**④ 교육생에게 설명할 핵심**

MAE가 작다는 것은 평균적으로 예측 오차가 작다는 의미입니다.

반면 RMSE는 큰 오차에 더 민감합니다.

따라서 MAE와 RMSE를 함께 살펴봐야 평균적인 오차와 큰 오차의 영향을 모두 이해할 수 있습니다.

**⑤ 멘토링 질문**

1. 현재 NOx 측정값을 그대로 60분 후 값으로 예측하면 MAE와 RMSE는 얼마인가요?
2. XGBoost는 Persistence보다 오차를 얼마나 줄였나요?
3. 예측 오차가 큰 상위 1% 데이터에는 어떤 특징이 있나요?
4. 실제 배출 비율이 높은 구간에서도 정확하게 예측하고 있나요?

### 3.3 S1-R: SO₂ 회귀 모델

**① 모델의 역할**

현재 SO₂ 측정값과 관련 Feature를 이용하여 정확히 60분 후의 SO₂ 배출 비율을 예측합니다.

**② Test 성능**

| 평가 지표 | 결과 | 해석 |
|---|---:|---|
| MAE | 3.2406%p | 실제값과 예측값의 평균 절대 오차 |
| RMSE | 7.5055%p | 큰 오차에 더 큰 영향을 받는 오차 지표 |

Validation 결과는 MAE 3.0935, RMSE 8.8250입니다.

**③ 핵심 진단**

- Test MAE는 약 3.24%p입니다.
- Test RMSE는 약 7.51%p입니다.
- MAE에 비해 RMSE가 상대적으로 높습니다.
- 이는 평균적인 오차에 비해 큰 오차가 상대적으로 두드러질 가능성을 보여 줍니다.

특히 RMSE/MAE 비율을 비교하면 다음과 같습니다.

| 모델 | Validation | Test |
|---|---:|---:|
| N1-R | 1.79 | 1.73 |
| S1-R | 2.85 | 2.32 |

S1-R은 N1-R보다 RMSE/MAE 비율이 높습니다. 따라서 S1-R은 평균 오차만 보는 것보다 큰 오차 사례를 별도로 분석하는 것이 중요합니다.

단, 이 비율만으로 큰 오차가 발생한 횟수나 원인을 확정할 수는 없습니다.

**④ Validation과 Test 해석 시 주의점**

S1-R은 Validation에서 Test로 넘어가면서 다음과 같이 변화했습니다.

- MAE: 3.0935 → 3.2406
- RMSE: 8.8250 → 7.5055

이것을 두고 Test에서 모델이 개선되었다고 표현하면 안 됩니다.

동일한 모델을 서로 다른 데이터 기간에 평가한 것이므로, 기간별 성능 차이로 해석해야 합니다.

**⑤ 멘토링 질문**

1. MAE는 낮은데 RMSE가 상대적으로 높은 이유를 실제 데이터로 설명할 수 있나요?
2. 오차가 큰 상위 1% 데이터는 어떤 특징을 가지고 있나요?
3. 실제 배출 비율이 85~90% 또는 90% 이상인 구간에서 예측 오차는 얼마인가요?
4. 실제값보다 낮게 예측하는 사례는 얼마나 발생하나요?

## 4. 회귀 모델의 필수 검증: Persistence 기준선 비교

이번 회귀 모델 성능 진단에서 가장 중요한 보완 사항입니다.

현재 N1-R과 S1-R은 MAE와 RMSE를 산출했지만, Persistence 기준선과 비교한 결과가 없습니다.

따라서 현재 성능 수치만으로 머신러닝 모델이 기존의 단순 예측 방법보다 우수하다고 결론 내릴 수 없습니다.

### 4.1 Persistence란?

Persistence는 현재 측정값이 미래에도 그대로 유지된다고 가정하는 예측 방식입니다.

예를 들어 현재 NOx 배출 비율이 65%라면 60분 후에도 65%일 것이라고 예측합니다.

\[
\hat{y}_{t+60}=y_t
\]

- \(y_t\): 현재 시점의 실제 측정값
- \(\hat{y}_{t+60}\): 60분 후 예측값

별도의 머신러닝 학습 없이 현재값을 그대로 미래 예측값으로 사용하는 방식입니다.

### 4.2 TMS 데이터에서 산출하는 방법

이번 프로젝트는 30분 단위 데이터이므로 정확히 60분 후의 값은 두 행 뒤의 실제값에 해당합니다.

예를 들어 다음과 같습니다.

| 측정 시각 | 현재 측정값 | 60분 후 실제값 | Persistence 예측값 |
|---|---:|---:|---:|
| 10:00 | 65 | 68 | 65 |
| 10:30 | 70 | 75 | 70 |
| 11:00 | 68 | 72 | 68 |
| 11:30 | 75 | 80 | 75 |
| 12:00 | 72 | 70 | 72 |

10:00의 현재 측정값이 65%라면 Persistence는 11:00에도 65%일 것으로 예측합니다.

실제값이 68%라면 오차는 3%p입니다.

실제 데이터에서는 다음 사항을 반드시 지켜야 합니다.

- 굴뚝 또는 설비별로 데이터를 분리합니다.
- NOx와 SO₂ 측정 항목을 구분합니다.
- 시간순으로 정렬합니다.
- 정확히 60분 후의 실제값을 연결합니다.
- 중간 측정 누락이나 시간 간격 불일치가 있는 행은 별도로 처리합니다.

전체 데이터를 단순히 두 행씩 이동시키면 서로 다른 굴뚝이나 측정 항목의 값이 연결될 수 있으므로 주의해야 합니다.

### 4.3 MAE와 RMSE 산출

Persistence 예측값과 실제값을 이용하여 XGBoost와 동일한 방식으로 평가합니다.

**MAE**

\[
MAE=\frac{1}{N}\sum_{i=1}^{N}|y_i-\hat{y}_i|
\]

실제값과 예측값의 절대 오차 평균입니다.

**RMSE**

\[
RMSE=\sqrt{\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat{y}_i)^2}
\]

오차를 제곱하기 때문에 큰 오차에 더 큰 영향을 받습니다.

### 4.4 Persistence와 XGBoost 비교

| 평가 항목 | Persistence | XGBoost |
|---|---:|---:|
| NOx MAE | 산출 필요 | 4.2547 |
| NOx RMSE | 산출 필요 | 7.3464 |
| SO₂ MAE | 산출 필요 | 3.2406 |
| SO₂ RMSE | 산출 필요 | 7.5055 |

두 모델의 평가 대상 행을 동일하게 맞춰야 공정한 비교가 가능합니다.

- XGBoost의 MAE와 RMSE가 모두 낮다면 평균 오차와 큰 오차 측면에서 개선된 것입니다.
- XGBoost의 MAE만 낮고 RMSE가 높다면 평균적인 예측은 나아졌지만 큰 오차 문제가 남아 있을 수 있습니다.
- 두 지표 모두 Persistence보다 높다면 현재 모델은 단순한 기준 예측보다 성능이 낮은 것입니다.

### 4.5 Persistence 대비 개선율(Skill Score)

MAE 기준 개선율은 다음과 같이 계산할 수 있습니다.

\[
Skill\ Score=1-\frac{MAE_{Model}}{MAE_{Persistence}}
\]

예를 들어 다음과 같습니다.

- Persistence MAE: 5.0
- XGBoost MAE: 4.0

\[
1-\frac{4.0}{5.0}=0.2
\]

즉, Persistence 대비 MAE가 20% 감소한 것입니다.

- Skill Score > 0: Persistence보다 개선
- Skill Score = 0: Persistence와 동일
- Skill Score < 0: Persistence보다 성능이 낮음

**교육생에게 강조할 점**

모델을 개발했다는 사실보다 중요한 것은 기존의 간단한 예측 방법보다 얼마나 더 정확하게 예측하는지를 증명하는 것입니다.

Persistence 비교는 머신러닝 모델의 필요성과 효과를 판단하기 위한 가장 기본적인 검증입니다.

## 5. 분류와 회귀 모델을 함께 보는 방법

현재 프로젝트에는 위험 여부를 판단하는 분류 모델과 미래 배출 비율을 예측하는 회귀 모델이 있습니다.

두 모델은 역할이 다르므로 결과를 어떻게 결합할 것인지도 검토해야 합니다.

| 구분 | 분류 모델 | 회귀 모델 |
|---|---|---|
| 예측 결과 | 위험 여부 | 미래 배출 비율 |
| 주요 역할 | 위험 발생 가능성 탐지 | 미래 배출 수준 예측 |
| 주요 지표 | Precision, Recall, F2, AP | MAE, RMSE |
| 활용 관점 | 사전 경고 | 위험 수준 및 변화량 판단 |

예를 들어 회귀 모델이 60분 후 배출 비율을 92%로 예측했다면, 이를 위험 경고에 활용할 수 있습니다.

다만 분류 모델은 '향후 60분 이내 위험 기준 진입'을 예측하고, 회귀 모델은 '정확히 60분 후 값'을 예측하므로 Label의 시간적 의미가 다릅니다.

따라서 두 모델의 결과를 바로 같은 기준으로 결합해서는 안 됩니다.

**추가로 확인할 사항**

- 분류 모델과 회귀 모델이 동일한 위험 상황을 놓치는지 확인합니다.
- 회귀 예측값이 90% 이상일 때 Precision과 Recall을 산출합니다.
- 두 모델의 결과를 최종 경보에 어떻게 반영할지 결정합니다.

S1-C의 미탐 행과 S1-R의 큰 오차 행이 겹치는지는 아직 확인되지 않은 가설입니다. 실제 행을 연결해 겹침 비율을 계산한 후 판단해야 합니다.

## 6. 프로젝트 공통 문제: 모델 결과를 신뢰할 수 있는가?

성능 지표가 정확하더라도 어떤 모델과 데이터로 산출했는지 확인할 수 없다면 결과를 신뢰하기 어렵습니다.

현재 진단에서 확인된 주요 문제는 다음과 같습니다.

### 6.1 모델 식별 및 추적성

현재 `metrics.json` 파일과 모델 ID의 연결 관계가 충분히 명확하지 않습니다.

특히 파일명에 포함된 번호는 다운로드 순서일 수 있으므로 모델 식별 근거로 사용하면 안 됩니다.

다음 정보를 연결해야 합니다.

- 모델 ID 및 버전
- 대상 물질과 예측 과제
- 학습 Job ID
- 모델 저장 S3 경로
- `metadata.json`
- 학습 데이터 테이블과 스냅샷 ID
- Feature 목록 및 출처
- 하이퍼파라미터와 학습 설정

**교육 포인트**

모델의 성능 수치만 저장하지 말고, 어떤 데이터와 설정으로 만들어진 모델인지 함께 관리해야 합니다.

### 6.2 Train / Validation / Test 평가

현재 보고서에는 Train 성능이 없습니다.

따라서 과적합 여부를 판단할 근거가 부족합니다.

세 데이터 구간의 결과를 함께 관리해야 합니다.

| 구분 | 평가 목적 |
|---|---|
| Train | 학습 데이터에 대한 모델 성능 확인 |
| Validation | 모델 및 임계값 선택, 설정 조정 |
| Test | 최종 성능을 독립적으로 평가 |

Validation과 Test는 동일 모델을 서로 다른 기간에 평가한 결과입니다.

따라서 두 결과의 차이는 기간별 성능 차이로 해석해야 하며, 모델 버전이 바뀌지 않았다면 '개선'이라고 표현하지 않도록 합니다.

### 6.3 공통 평가 결과 관리

모델마다 평가 항목과 보고서 형식이 다르면 결과를 일관되게 비교하기 어렵습니다.

공통 평가 결과에 다음 항목을 포함하도록 합니다.

- 모델 ID, 버전, 알고리즘
- Train / Validation / Test 기간과 행 수
- 학습 데이터 및 Feature 출처
- 목표값 또는 Label 정의
- 분류: 혼동행렬, 양성 비율, Precision, Recall, F2, AP
- 회귀: MAE, RMSE, 오차 분위수
- 기준선 대비 성능
- 위험 구간별 성능
- 확인된 사실, 추정, 가설의 구분

## 7. 실제 TMS 운영 관점에서 추가해야 할 평가

이번 프로젝트의 목적은 단순히 배출 비율을 예측하는 것이 아니라 사전에 위험을 경고하는 것입니다.

따라서 행 단위 성능 지표만으로 운영 가능성을 판단해서는 안 됩니다.

### 7.1 위험 구간별 회귀 성능

실제 60분 후 배출 비율을 기준으로 구간을 나누어 MAE와 과소 예측 비율을 산출합니다.

| 실제 배출 비율 구간 | 평가 목적 |
|---|---|
| 50% 미만 | 일반 구간 성능 |
| 50~70% | 중간 구간 성능 |
| 70~85% | 위험 접근 구간 성능 |
| 85~90% | 위험 임계값 직전 성능 |
| 90% 이상 | 실제 위험 구간 성능 |

특히 실제값보다 낮게 예측하는 과소 예측이 얼마나 발생하는지 확인해야 합니다.

### 7.2 큰 오차 사례 분석

회귀 모델은 평균적인 오차뿐 아니라 큰 오차가 발생한 사례를 분석해야 합니다.

다음 항목을 추가합니다.

- 오차 P50, P90, P95, P99, 최대값
- 오차 상위 1% 데이터 추출
- 월별·굴뚝별 MAE와 RMSE
- 위험 구간의 과소 예측 비율

특히 S1-R은 RMSE/MAE 비율이 상대적으로 높으므로 큰 오차 사례 분석을 우선 진행하는 것이 좋겠습니다.

### 7.3 사건 단위 분류 성능

현재 S1-C의 FP 25,148건은 행 단위 오탐 결과입니다.

연속해서 발생한 여러 오탐 행이 하나의 경보 사건일 수 있으므로, 이를 그대로 경보 건수로 환산해서는 안 됩니다.

실제 운영에서는 다음 항목이 필요합니다.

- 연속 경보를 하나의 사건으로 묶는 기준
- 사건 단위 위험 탐지율
- 하루·굴뚝당 오경보 건수
- 위험 발생 전 경보 리드타임

## 8. 오늘 멘토링에서 반드시 확인할 핵심 질문

오늘은 모든 분석을 한 번에 진행하기보다 다음 다섯 가지를 중심으로 교육생과 논의하는 것이 좋겠습니다.

### 질문 1. 머신러닝 모델이 Persistence보다 성능이 좋은가요?

- NOx와 SO₂ 각각 Persistence MAE, RMSE를 산출했나요?
- XGBoost와 동일한 Test 데이터로 비교했나요?
- Persistence 대비 개선율을 계산했나요?

### 질문 2. 위험 구간에서도 제대로 예측하고 있나요?

- 실제 배출 비율 85~90%, 90% 이상 구간의 예측 오차는 얼마인가요?
- 실제값보다 낮게 예측하는 사례는 얼마나 되나요?
- 위험 구간의 성능을 전체 MAE만으로 설명할 수 있을까요?

### 질문 3. 큰 오차는 어떤 데이터에서 발생하나요?

- 오차 상위 1% 데이터의 공통적인 특징은 무엇인가요?
- 특정 월이나 굴뚝에 오차가 집중되나요?
- S1-C가 놓친 위험 사례와 S1-R의 큰 오차 사례가 겹치나요?

### 질문 4. 모델 결과를 재현할 수 있나요?

- 모델 ID와 `metrics.json`이 정확히 연결되어 있나요?
- 학습 데이터와 Feature 목록을 확인할 수 있나요?
- 하이퍼파라미터와 학습 설정을 재현할 수 있나요?

### 질문 5. 실제 운영에 적용할 수 있는 기준이 있나요?

- 어느 정도의 Recall을 확보해야 하나요?
- 하루 또는 굴뚝당 오경보를 어느 수준까지 허용할 수 있나요?
- 분류와 회귀 모델의 결과를 최종 경보에 어떻게 반영할 것인가요?

※ 목표 Precision이나 Recall 수치는 근거 없이 임의로 정하지 말고, 운영 요구사항과 경보 처리 가능량을 바탕으로 팀에서 합의해야 합니다.

## 9. 교육생 후속 작업 및 우선순위

모든 작업을 동시에 진행하기보다는 모델 결과의 신뢰성을 확보한 뒤 평가를 보강하는 순서로 진행합니다.

### P0. 먼저 확인할 사항: 모델과 데이터의 근거 확보

| 작업 | 대상 | 완료 기준 |
|---|---|---|
| 모델 ID와 metrics 파일 연결 | S1-C, N1-R, S1-R, N1-C | 모델 ID·metrics·S3 경로 대응표 작성 |
| 전체 6개 모델 목록 정리 | 전체 | 모델 ID, 대상 물질, 과제, 알고리즘, 버전 정의 |
| 학습 설정 및 Feature 확인 | 전체 | 하이퍼파라미터, Feature 목록, 데이터 출처 확보 |
| 보고서 오류 및 표현 수정 | 3개 보고서 | 확인된 사실과 가설을 구분하고 부정확한 표현 수정 |

### P1. 추가 학습 없이 우선 수행할 평가 보강

| 작업 | 대상 | 완료 기준 |
|---|---|---|
| Persistence 기준선 산출 | N1-R, S1-R | MAE, RMSE, Skill Score 비교 |
| 분류 규칙 기준선 비교 | S1-C, N1-C | 현재값 기준 규칙과 Precision, Recall 비교 |
| 회귀 오차 분위수 분석 | S1-R 우선, N1-R | P50, P90, P95, P99, 최대값 산출 |
| 위험 구간별 성능 분석 | N1-R, S1-R | 구간별 MAE, 과소 예측 비율 산출 |
| S1-C 미탐과 S1-R 큰 오차 비교 | S1-C, S1-R | 동일 사례 겹침 여부와 비율 확인 |
| Train 성능 및 Validation 혼동행렬 보완 | 전체, 특히 S1-C | 과적합 및 기간별 성능 차이 판단 근거 확보 |

### P2. 운영 적합성과 일반화 검증

| 작업 | 대상 | 완료 기준 |
|---|---|---|
| 사건 단위 평가 | 분류 모델 | 사건 탐지율, 하루·굴뚝당 오경보, 리드타임 산출 |
| 국내 TMS 외부 평가 | S1-C, N1-R, S1-R | 국내 데이터 평가 결과 확보 |
| 신뢰구간 산출 | 전체 | 굴뚝 또는 시간 구간 단위 부트스트랩 적용 |
| S1-C V1.1 실험 | S1-C | 가중치, 임계값, 확률 보정 등 실험 결과 비교 |
| SO₂ 관련 추가 Feature 검토 | S1-C, S1-R | 탈황설비 운전 상태, 연료 황 함량 등 데이터 확보 가능성 확인 |

※ 국내 데이터 평가는 모델의 일반화 성능을 확인하기 위한 외부 검증으로 활용하고, 국내 Test 데이터를 모델 튜닝에 사용하지 않도록 합니다.

### P3. 최종 운영 체계 정립

- 모델 산출물과 Iceberg 데이터 스냅샷 연결
- 공통 성능진단 보고서 및 평가 스크립트 표준화

## 10. 멘토링 마무리

이번 모델 개발을 통해 분류와 회귀 모델을 각각 구현하고 기본 성능 지표를 산출한 점은 잘 진행했습니다.

이제부터는 모델을 만들었다는 사실보다 **모델이 실제로 얼마나 유용한지 증명하는 과정**이 중요합니다.

특히 다음 세 가지를 꼭 기억하면 좋겠습니다.

1. **기준선 비교:** 머신러닝 모델이 Persistence보다 실제로 더 정확한지 확인해야 합니다.
2. **위험 구간 검증:** 전체 평균 성능뿐 아니라 위험 구간에서 얼마나 정확하게 예측하는지 확인해야 합니다.
3. **결과의 신뢰성:** 모델 ID, 데이터, Feature, 학습 설정을 추적할 수 있어야 동일한 결과를 재현하고 운영에 적용할 수 있습니다.

교육생들에게는 다음과 같이 전달하면 좋겠습니다.

> 지금까지 모델을 개발하고 성능 지표를 산출한 것까지는 잘 진행했습니다. 이제 한 단계 더 나아가 봅시다.
>
> 현재 측정값을 그대로 사용하는 Persistence보다 얼마나 잘 예측하는지 확인하고, 실제 위험 구간에서도 제대로 예측하는지 살펴봅시다.
>
> 그리고 성능이 좋다는 결과를 다른 사람이 확인하고 다시 재현할 수 있도록 데이터와 모델 정보도 함께 정리해야 합니다.
>
> 이런 검증까지 이루어져야 단순히 학습이 완료된 모델이 아니라 실제 현장에서 활용할 수 있는 모델이라고 이야기할 수 있습니다.
