# 11/16~11/20 주간 작업 계획
## TMS 데이터 파이프라인 및 Hybrid AI 사전 경고 시스템 구축 — 모델 채택과 Gold 완성

- **작업 기간:** 2026-11-16(월) ~ 2026-11-20(금)
- **이번 주 목표:** Validation으로 **분류 모델**(60분 안 경고 진입 확률)과 **회귀 모델**(60분 뒤 기준대비율)을 고르고, 판정 흐름에 연결해 11/20에 **Gold를 완성·고정**한다.
- **기준 문서:** [프로젝트 정본](<(정본)굴뚝 TMS 데이터 파이프라인 및 Hybrid AI 사전 경고 시스템_20261101_01.md>)("정본 3.3"처럼 적은 곳은 프로젝트 정본의 절)
- **작업 방식:** 이 문서는 큰 흐름만 알려 준다. 방법·도구·분담은 팀이 정하고 이유를 멘토링 때 설명한다.

> **성능 숫자를 올리는 것보다, 데이터 → 모델 예측 → 최종 판정 → 경고 이력이 한 줄로 이어지게 하는 것이 이번 주의 핵심이다.**

> ## 이번 주 핵심 목표
>
> 1. 실험 재료를 고정하고, 시작 전에 게이트로 다시 점검한다.
> 2. 분류는 B Feature 세트를 정한 뒤 XGBoost·RF 두 사슬에서 각각 B → B+E → +S 순서로 비교하고, 두 결승 후보를 최종 비교해 고른다. B+EP는 Could·참고 실험이다.
> 3. 회귀는 국내 실측만으로 학습해 분류 결과에 맞춰 고른다. RF 회귀를 비교 모델로 함께 학습하고 불일치 기준값을 정한다.
> 4. 승인 모델을 판정 흐름에 잇고, 현재 판정 + 사전 경고를 완성한다.
> 5. 11/20에 모델·규칙·코드 버전을 고정한다.

# 3. Task별 큰 흐름

## Task 1. Feature 데이터셋 확정

- **왜:** 실험 도중 데이터가 바뀌면 결과를 비교할 수 없다.
- **어떤 방식으로:** Train·Validation 특성과 라벨을 최종 계산하고, 실험에 쓸 판본을 고정해 기록한다.
- **결과물:** Feature 최종 스냅샷, 데이터셋 문서

## Task 2. 국내 P99·EPA 점수 계산

- **왜:** 공통 특성(`common-v1`, 정본 부록 C)과 EPA 점수가 있어야 B+E 실험을 할 수 있다.
- **어떤 방식으로**
  1. 국내 기준 통계(P99)는 Train 구간 값만으로 구해 버전과 함께 저장하고, Validation·Test·운영에서도 그 값을 쓴다.
  2. EPA 점수는 고정된 `epa-surge-v1`로 계산만 한다(다시 학습하지 않음). 대상은 국내 **NOx·SOx**뿐이고, 그 밖 항목은 빈 값으로 둔다.
  3. `rel_p99`가 빈 값이면(P99 없음·0·현재 값 없음) 점수도 빈 값으로 둔다. 0이나 직전 값으로 채우지 않는다.
  4. 합성 행은 참조 실측 배출구(`ref_stack_code`)의 Train P99로 계산한다(정본 부록 C.4).
  5. 점수 빈 값 비율을 항목별·`data_origin`별로 기록한다.
- **결과물:** 국내 공통 특성, EPA 점수, P99 표(버전), 빈 값 비율 기록
- **고민할 점:** Validation 값까지 써서 통계를 구하면 무엇이 문제인가?

## Task 3. (Could) B+EP 합동 데이터셋

- **왜:** EPA 행을 직접 학습에 섞었을 때의 효과를 참고로 보기 위해서다. 채택 후보는 아니다(정본 5.2).
- **어떤 방식으로:** 11/17까지 실행 여부를 정한다. 실행하면 EPA 행이 국내를 압도하지 않도록 비중과 양을 제한하고(기준은 실행을 정할 때 멘토와 함께 정한다), 출처를 표시한다.
- **결과물:** 실행 여부 결정 기록. 실행하면 합동 학습 데이터와 출처·비중 기록

## Task 4. 본 실험 전 게이트

- **왜:** 한 번 실험한 뒤에 누수를 발견하면 되돌리기 어렵다.
- **어떤 방식으로:** 구간 분리, 미래 정보 누수, 출처 분리를 점검하고, 통과해야만 본 실험을 시작한다.
- **결과물:** 게이트 결과

## Task 5. 분류 본 실험

- **왜:** 무엇을 더했을 때 좋아지는지 하나씩 확인해야 근거 있는 선택을 할 수 있다.
- **어떤 방식으로**
  0. B의 Feature 세트를 먼저 정한다. B 기본(기존 국내 Feature 14개(정본 4.1) + 채택된 국내 특성 후보)과 B 확장(+ `ratio_diff_60m`·`ratio_diff_120m`·`ratio_slope_3h`)을 Validation으로 비교하고, 확장이 나을 때만 세 개를 한 묶음으로 넣는다. 0단계는 XGBoost로 하고, 정한 세트를 두 사슬의 모든 실험에 쓴다.
  1. XGBoost 사슬과 RF 사슬을 따로 돌린다. 사슬마다 B(국내만)를 기준으로 삼는다.
  2. 같은 사슬에서 B+E가 Validation으로 B보다 나은지 본다.
  3. 같은 사슬에서 거기까지 채택된 쪽에 +S(합성 Train)를 더해 보고, 사슬별 결승 후보를 정한다.
  3-1. 두 결승 후보의 Validation F1 차이를 배출구 단위 부트스트랩 구간으로 본다. 구간이 0을 포함하면 XGBoost를 채택한다. 이 구조와 동점 규칙은 11/17까지 고정한다.
  3-2. RF는 scikit-learn 1.4 이상으로 고정해 빈 값을 채우지 않는다. RF 탐색 범위도 XGBoost처럼 작게(6조합 정도) 잡는다.
  4. (Could) B+EP를 실행했다면 참고 행으로만 적는다.
  5. 하나를 더할 때마다 나아질 때만 채택하고, 차이가 작으면 더 단순한 쪽을 고른다.
  6. 여섯 실험(B·B+E·+S × XGBoost·RF)은 같은 조건으로 돌린다. 같은 Feature 세트·데이터 스냅샷·코드 버전·탐색 범위·임계값 규칙을 쓰고, Persistence와 Rule Engine만 쓴 경우를 기준선으로 함께 적는다(정본 5.2 "결과표").
  7. 채택은 Validation의 행 단위 F1·재현율·오경보 건수로 한다. 사건 단위 지표, 선행 시간, PR-AUC, Persistence 대비 개선율은 보고용이다. 합성 비중의 영향도 Test가 아니라 Validation으로 판단한다.
- **결과물:** Validation 실험 비교표(6개), 최종 비교의 부트스트랩 구간, 실험 기록
- **고민할 점:** 사건 수가 적을 때 작은 차이를 믿어도 되는가?

## Task 6. 채택·임계값·승인 모델 등록

- **왜:** 운영에 쓰는 모델과 임계값은 근거와 함께 하나로 묶여야 한다.
- **어떤 방식으로**
  1. 재현율 기준(0.6 이상)을 넘는 후보 중에서 고른다.
  2. 임계값은 Validation으로만 정한다.
  3. 분류(`clf-v1`)·XGBoost 회귀(`reg-v1`)·RF 회귀(`rf-reg-v1`)와 불일치 기준값을 한 묶음으로 등록하고 채택 근거를 남긴다. 나중에 다시 학습하면 `v2`로 올린다.
- **결과물:** 승인 모델 묶음, 채택 근거, 모델 카드

## Task 7. 회귀 모델 학습

- **왜:** 확률만으로는 "얼마나 올라갈지" 알 수 없다. 60분 뒤 기준대비율을 직접 예측한다.
- **어떤 방식으로**
  1. 국내 실측 Train만으로(합성·EPA 행 없이) XGBoost 회귀의 B판과 B+E판을 학습하고, 분류에서 채택한 쪽에 맞춰 고른다.
  2. RF 회귀를 같은 데이터·같은 판(B 또는 B+E)으로 학습한다. RF는 사전 경고를 정하지 않고, XGBoost 회귀와 예측 차이를 재는 비교 모델이다(정본 5.1·7장).
  3. Validation에서 두 회귀 예측의 차이 D = |RF − XGBoost| 분포를 보고, 불일치 기준값을 10%p에서 출발해 JEV 호출 대상이 전체 예측의 약 5% 안팎이 되도록 정한다.
  4. Persistence 대비 MAE 개선을 두 회귀 모델 모두 기록한다.
- **결과물:** XGBoost·RF 회귀 모델, Validation 오차 결과, 불일치 기준값과 근거

## Task 8. 판정 흐름에 모델 연결

- **왜:** 모델이 실제 판정 흐름 안에서 돌아야 사전 경고를 낼 수 있다.
- **어떤 방식으로**
  1. 배치와 스트리밍이 같은 방식으로 승인 모델(분류·XGBoost 회귀·RF 회귀)을 호출한다.
  2. 예측값을 `tms_gold.judgement`에 정본 3.6의 열대로 남긴다. 키 여섯 개로 MERGE하고 이미 있으면 쓰지 않는다(재시도해도 중복 없음).
  3. 호출이 실패하거나 특성이 모자라면 빈 값과 `hold_reason`을 남긴다.
  4. 추론에 쓴 Feature 값을 `tms_feature.online_features`에 같은 키로 저장한다.
  5. 늦게 들어온 값으로 지난 기준 시각을 다시 판정하지 않는다.
- **결과물:** 예측값이 기록된 Gold, 추론 Feature 기록, 같은 입력을 두 번 넣어도 행이 하나인지 확인하는 테스트
- **고민할 점:** 모델 호출이 실패해도 현재 판정은 계속 나와야 하는가?

## Task 9. Final Decision·사전 경고

- **왜:** 현재 판정과 미래 예측을 하나의 최종 단계로 합쳐야 사람이 행동할 수 있다.
- **어떤 방식으로**
  1. 현재 판정을 먼저 둔다(ML은 현재 단계를 낮추지 못한다).
  2. 분류 확률이나 XGBoost 회귀 예측이 조건을 넘으면 사전 경고를 더하고, 그 이유를 남긴다.
  3. 두 회귀 예측의 차이가 기준값 이상이면 "모델 불일치"를 표시한다. 불일치일 때 RF만 90% 이상을 예측해도 사전 경고를 유지하고 사유를 `rf_only_disagreement`로 따로 남긴다(정본 9.2).
  4. 같은 사전 경고가 짧은 간격으로 반복되지 않게 한다.
  5. 경고·초과·사전 경고 행만 `ops.warning_history`(운영 테이블)에 옮긴다. 숫자는 Gold 행에서 그대로 복사한다.
  6. 실측 전용 뷰(`gold.v_judgement_observed`)와 일간 집계 뷰(`gold.v_daily_summary`)를 만들고, 새 Gold 행을 Elasticsearch에 키 기준으로 색인한다.
  7. JEV 호출은 이 흐름에 넣지 않는다. 11/30 주에 판정 흐름 밖의 별도 작업으로 붙인다.
- **결과물:** 최종 판정 로직, 사전 경고 이력

## Task 10. Gold 통합 확인·고정

- **왜:** Test 기간 동안 바뀌지 않는 기준점이 있어야 공정하게 평가할 수 있다.
- **어떤 방식으로:** 배치·스트리밍 전체 흐름을 확인한 뒤, 11/20에 모델(분류·회귀·RF)·특성·규칙·임계값·불일치 기준값·코드 버전을 함께 고정하고 기록한다.
- **결과물:** 고정 기록, **Gold 완성**

## Task 11. 합성 시나리오 1차 평가

- **왜:** 실측에 드문 상황에서도 시스템이 설계대로 반응하는지 본다.
- **어떤 방식으로:** 합성 시나리오를 운영과 같은 경로로 흘리고, 기대 결과와 실제 반응을 비교한다.
- **결과물:** 시나리오 반응 1차 결과

## Task 12. Test 계획·평가 코드

- **왜:** Test를 본 뒤에 평가 코드나 판단 기준을 고치는 일이 없도록 미리 완성해 둔다. Test는 11/23~12/4이고 11/27(Test-1 중간)과 12/7(Test 전체 최종)에 같은 코드로 평가한다.
- **어떤 방식으로**
  1. Test 기간(~12/4)에 하는 일과 하지 않는 일을 운영 규칙으로 정한다. Test-1 결과를 본 뒤에도 바꾸지 않는다는 규칙을 넣는다.
  2. 분류·회귀 평가 코드를 만들고 Validation으로 미리 돌려 본다. 사건 단위 집계와 배출구 단위 신뢰 구간을 넣는다.
  3. 규칙만 쓸 때와 ML을 더했을 때를 비교하는 항목도 넣는다.
  4. Validation의 하루 사건 수로 Test 12일의 예상 사건 수를 어림하고, **Test 적정성 기준값**(정본 4.5, 부록 B.2의 사건 세는 법)을 `docs/evaluation/test_adequacy.md`에 11/22까지 적는다.
- **결과물:** Test 운영 규칙, 평가 코드, Test 적정성 기준

# 6. 팀에서 결정할 사항

**이미 정해진 것:** 데이터 구간, 실험 순서(B Feature 세트 확정 → XGBoost·RF 사슬별 B → B+E → +S → 최종 비교, B+EP는 Could·참고), 재현율 0.6 이상, 현재 판정 우선, Test는 선택에 쓰지 않음, 사전 경고 조건(분류 확률 ≥ 운영 임계값 또는 XGBoost 회귀 ≥ 90% — 정본 9.2).

| # | 팀이 정할 것 | 판단 근거 |
|---|---|---|
| 1 | 사전 경고 반복 방지 간격 | 같은 배출구·항목에서의 반복 빈도 |
| 2 | 모델 저장·등록 방식 | 재현성, 배치·스트리밍 공통 사용 |
| 3 | 판정 실행 환경의 자원 | 실행 시간·메모리 |

정본과 다른 결정을 하려면 멘토와 먼저 협의한다.
