## 1. 추진 목적

### 1.1 무엇을 예측하나

우리 모델이 맞히려는 것은 **"지금 기준대비율 90% 미만인 배출구 × 항목이, 다음 60분 안(t+30 또는 t+60)에 한 번이라도 90% 이상에 들어가는가"** 다(분류, 주 모델). 60분 뒤 기준대비율 수치는 회귀 모델이 보조로 예측한다.

### 1.2 왜 EPA 활용 방식을 나눠서 실험하나

| 차이 | EPA CAMPD(부 데이터) | 한국환경공단 굴뚝 TMS(주 데이터) |
|---|---|---|
| 값 | NOx 배출률(lbs/mmBtu) | NOx 농도(ppm) |
| 간격 | 60분 | 30분 |
| 기준 | 법적 기준 없음 → 대리 기준(`proxy-v0`, 2023년 P99) | 법적 허용기준이 응답에 들어 있음 |
| 기간 | 텍사스 여러 해(14개 분기) | 10/30부터 수집(과거 조회 불가) |

국내 데이터는 기간이 짧아 사건이 적고, EPA는 사건이 많지만 값의 뜻이 다르다. 그래서 두 데이터를 무조건 합치지 않고, **EPA를 쓰는 방법을 실험으로 나눠** 국내 사전 경고에 도움이 되는지 비교한다.

이 프로젝트는 현장에 바로 쓸 완성형 제품이 아니라, 교육생이 데이터 엔지니어링과 ML을 직접 구현·검증하는 것이 목적이다. 성능이 반드시 좋아져야 성공인 것은 아니다.

### 1.3 실험 목표

1. 국내 데이터만 쓴 기준 모델(B)을 만든다.
2. EPA에서 배운 급등 패턴을 **점수 하나로** 국내 모델에 전달한다(B+E).
3. 합성 데이터를 학습에 더했을 때의 효과를 본다(+S).
4. (Could) EPA 행을 국내 학습에 직접 섞었을 때를 **참고로** 본다(B+EP).

## 2. 전체 실험 구성

| 실험 | 학습 데이터 | Feature | 확인하는 질문 | 지위 |
|---|---|---|---|---|
| **B** | 국내 실측 Train | 국내 Feature | 국내만으로 얼마나 되나 | 기준 모델 |
| **B+E** | 국내 실측 Train | B + `epa_surge_score` | EPA 급등 점수가 도움이 되나 | 채택 후보 |
| **+S** | 그 사슬에서 채택된 쪽 + 합성(학습용) | 채택된 쪽과 같음 | 합성을 더하면 나아지나 | 채택 후보 |
| B+EP | 국내 실측 Train + EPA 행 | 공통 특성 | EPA 행을 직접 섞으면 어떤가 | **(Could) 참고만** |

### 2.1 B → B+E → +S는 이어지는 사슬이다

하나를 더할 때마다 Validation에서 나아지는지 보고, **나아질 때만 채택**해 다음 단계를 그 위에 쌓는다(정본 5.2). 이 사슬을 XGBoost와 RF에서 같은 조건으로 따로 돌린다.

```text
0단계  B Feature 세트 확정(XGBoost로)
          │
   ┌──────┴───────┐
XGBoost 사슬    RF 사슬
B → B+E → +S    B → B+E → +S
   │               │
XGB 결승 후보   RF 결승 후보
   └──────┬───────┘
     최종 비교 1회 → 승인 분류 모델 clf-v1
```

- 예: XGBoost 사슬에서 B+E가 B보다 나아지면 +S는 "B+E + 합성"으로, 나아지지 않으면 "B + 합성"으로 시험한다.
- B+EP는 이 사슬에 들어가지 않는다. 실행 여부는 **11/17까지 미리** 정하고, 결과를 본 뒤 추가하지 않는다.

## 3. 실험 ① B: 국내 데이터 기준 모델

### 목적

국내 환경공단 데이터만으로 기준 모델을 만든다. 이후 모든 실험은 이 모델과 비교한다.

### 진행 방법

1. 국내 데이터의 단위·간격·결측·상태 문구를 확인하고, 항목별 진입 사건 수를 센다(11/9 주 Task 1 EDA).
2. 라벨 `label-v1`을 만들고 11/12까지 고정한다(정본 4.4·부록 B).
3. 공통 Feature Library로 국내 Feature를 계산한다(정본 4.1).
4. **0단계:** B 기본(기존 국내 Feature 14개 + 채택된 국내 특성 후보)과 B 확장(+ 추가 후보 3개)을 Validation으로 비교해 Feature 세트를 정한다(11/18, XGBoost로).
5. 국내 실측 Train만으로 학습하고 Validation으로 평가한다.

### 국내 Feature (일부, 정본 4.1)

| Feature | 뜻 |
|---|---|
| `ratio_pct` | 현재 기준대비율 |
| `ratio_lag_30m` · `ratio_lag_60m` | 30분 전 · 60분 전 기준대비율 |
| `ratio_rolling_mean_1h` · `ratio_rolling_mean_3h` | 최근 1시간 · 3시간 평균 |
| `ratio_diff_30m` | 직전 구간 대비 변화량 |
| `ratio_pct_change_30m` | 직전 구간 대비 변화율(직전 값이 0이면 빈 값) |
| `hour` · `dayofweek` | 시간대 · 요일 |
| (추가 후보) `ratio_diff_60m` · `ratio_diff_120m` · `ratio_slope_3h` | 60분·120분 변화량, 3시간 기울기 |

- 시차와 창은 행 순서가 아니라 `measured_at` 기준 **시간**으로 찾는다.
- 창에 값이 모자라면(3시간 6개 중 4개 미만, 1시간 2개 미만) 빈 값으로 둔다. 0으로 나누는 경우도 빈 값이다.
- Train이 2주라 같은 요일이 두 번씩만 들어 있어 `dayofweek`에 과적합되기 쉽다. 특성 중요도가 이 변수에 몰리면 멘토와 상의한다.

### 결과물

- 국내 Feature 데이터셋(`tms_feature.keco_features`) 스냅샷
- B Feature 세트 결정 근거(B 기본 vs B 확장)
- XGBoost·RF의 B 모델과 Validation 결과

## 4. 실험 ② B+E: EPA 급등 점수를 국내 모델에 전달

### 목적

EPA로만 학습한 **급등 점수 모델**이 국내 행에 매긴 점수를 국내 모델의 Feature 하나로 더한다. EPA 행을 국내 학습 데이터에 넣지 않는다. **EPA 모델의 결과를 점수 형태로 전달하는 방식**이다.

### 진행 방법

#### 1단계. 공통 특성 `common-v1`과 EPA 점수 모델 (11/9 주)

- EPA에 가동 재개·변동성 증가·동시 상승 같은 급등 직전 현상이 실제로 있는지 확인한다(Task 7).
- 두 원천에서 같은 식으로 계산하는 **단위 없는 특성 5개**를 쓴다(정본 부록 C.3): `rel_p99`(자기 P99 대비 %), `rel_diff_60m`, `rel_roll_mean_3h`, `rel_roll_std_3h`, `hour`.
- EPA 라벨은 **"자기 P99 대비 90%에 60분 안 진입"** 이다. 국내 라벨(법적 허용기준 대비 90%)과 같은 정답이 아니다.
- EPA 데이터만으로 XGBoost 점수 모델 **`epa-surge-v1`** 을 학습하고 고정한다. EPA 안에서도 시간 순서로 나눠 검증한다.

#### 2단계. 국내 행에 점수 붙이기 (11/16 주)

- 국내 P99는 배출구 × 항목별 **Train 구간 유효 값**으로만 구한다(유효 값 200개 미만이면 빈 값).
- 국내 **NOx·SOx** 행에 같은 공통 Feature Library로 `common-v1`을 계산하고, `epa-surge-v1`에 넣어 **계산만** 한다.
- 결과를 `epa_surge_score`(0~1)로 저장한다. 그 밖 항목과 `rel_p99`가 빈 행은 점수도 빈 값이다.
- 합성 행은 참조 실측 배출구(`ref_stack_code`)의 Train P99로 계산한다.

#### 3단계. 국내 모델을 다시 학습 (11/18)

| 구분 | Feature | 학습 행 |
|---|---|---|
| B | 국내 Feature(0단계에서 정한 세트) | 국내 실측 Train |
| B+E | 국내 Feature + `epa_surge_score` | 국내 실측 Train |

B의 학습 결과에 점수만 덧붙이는 것이 아니다. **점수가 들어간 국내 데이터로 처음부터 다시 학습**한다. 같은 사슬의 B와 같은 알고리즘·탐색 범위·데이터 스냅샷을 쓴다.

### 데이터 흐름

```text
EPA Silver ──▶ common-v1(proxy-v0 분모) + EPA 라벨 ──▶ epa-surge-v1 학습·고정
                                                            │
국내 Silver(NOx·SOx) ──▶ common-v1(Train P99 분모) ─────────┴─▶ epa_surge_score
                                                                      │
국내 Feature + epa_surge_score ──▶ 국내 라벨(label-v1)로 학습 ──▶ B+E 모델
```

### 주의사항

- EPA 점수 모델은 EPA 데이터만으로 학습한다. 국내 라벨을 쓰지 않는다.
- `common-v1` 5개는 B+E 모델에 **직접 들어가지 않는다.** 그 결과인 점수 하나만 들어간다.
- 점수의 입력도 예측 시점까지 확보한 값만 쓴다(`ingested_at` 조건). 미래 값이 들어가면 누수다.
- 두 원천의 `common-v1` 분포를 나란히 그려 차이를 기록한다. 3시간 창에 EPA는 3개, 국내는 6개가 들어가 표준편차의 성질이 조금 다르다.
- 점수의 뜻은 "법적 기준에 가까운가"가 아니라 **"자기 평소보다 60분 안에 급등할 가능성"** 이다.
- 이 방식은 모델 가중치를 넘겨받는 전이학습과 다르다. EPA에서 배운 지식을 점수로 옮긴다.

### 결과물

- `common-v1` 정의(`config/features.yaml`)와 고정 사례 테스트
- `epa-surge-v1`과 학습 기록
- 국내 `epa_surge_score`, 빈 값 비율 기록
- 사슬별 B vs B+E Validation 비교

## 5. 실험 ③ +S: 합성 데이터를 학습에 더하기

### 목적

실측에서 드문 상황(급등·지속 상승 등)을 담은 합성 데이터를 학습에 더하면 나아지는지 본다.

### 진행 방법

- 그 사슬에서 거기까지 채택된 쪽(B 또는 B+E)에 **학습용 합성 시나리오**를 더한다.
- 합성 행은 **Train 행의 30% 이내, 가중치 0.5**로 고정한다.
- 합성 행도 같은 라벨 함수(`label-v1`)를 쓴다. 미래 값은 Silver에 **실제로 들어온** 합성 값을 쓰고, 생성기가 계획한 궤적은 쓰지 않는다.
- 학습용 시나리오와 평가·시연용 시나리오가 겹치지 않게 `scenario_id`로 나눈다.
- Validation·Test에는 합성을 넣지 않는다(실측만).

## 6. (Could) 참고 실험 B+EP: EPA 행 직접 통합

### 목적

EPA 행과 국내 행을 공통 특성으로 맞춘 뒤 하나의 학습 데이터로 합쳤을 때 어떤지 **참고로** 본다. **채택 후보가 아니며**, B+E가 나쁘게 나왔다고 추가로 돌리는 실험도 아니다. 실행 여부는 11/17까지 정한다(11/16 주 Task 3).

### 진행 방법

1. 두 원천에서 같은 뜻으로 계산할 수 있는 공통 특성으로 행을 구성한다(`common-v1`을 출발점으로).
2. 출처를 구분하는 열(예: `is_epa`)을 둔다.
3. EPA 행이 국내를 압도하지 않도록 비중과 양을 제한한다.
4. 통합 모델을 학습하고 같은 국내 Validation으로 평가해 **참고 행**으로 적는다.

### 비중·양의 초기값

| 항목 | 초기값 | 비고 |
|---|---|---|
| EPA 행 가중치 | 0.2 | 필요할 때만 0.1·0.5·1.0 비교 |
| EPA 행 수 | 국내 Train 행의 2배 이내 | |

초기값은 최적값이 아니다. 실행을 정할 때 멘토와 함께 확정하고 기록한다. 비교 범위를 넓게 늘리지 않는다.

### 데이터 구성 예시 (설명용 가상 수치)

| 출처 | 시각 | `rel_p99` | `rel_diff_60m` | `rel_roll_std_3h` | `is_epa` | 60분 안 진입 |
|---|---|---:|---:|---:|---:|---:|
| 국내 | 09:00 | 62 | 4 | 3.1 | 0 | 0 |
| 국내 | 09:30 | 71 | 13 | 5.8 | 0 | 0 |
| 국내 | 10:00 | 84 | 22 | 9.4 | 0 | 1 |
| EPA | 09:00 | 58 | 3 | 2.7 | 1 | 0 |
| EPA | 10:00 | 81 | 23 | 9.0 | 1 | 1 |

### 주의사항

- `is_epa` 열 하나로 두 데이터의 차이가 해결되지 않는다.
- 국내 행의 정답은 법적 허용기준 대비, EPA 행의 정답은 자기 P99 대비다. **두 정답이 같은 현상을 뜻하는지가 B+EP의 가장 큰 한계**이며, 결과와 함께 반드시 적는다.
- 농도와 배출률처럼 다른 물리량을 단순 변환해 같은 특성으로 쓰지 않는다.
- 시간 순서로 나누고, Validation·Test에는 국내 실측만 쓴다.

## 7. B+E와 B+EP의 핵심 차이

| 비교 항목 | B+E | B+EP (참고) |
|---|---|---|
| EPA 활용 방식 | EPA 모델의 **결과(점수)** | EPA **행** 자체 |
| EPA 별도 모델 | 필요(`epa-surge-v1`) | 필요 없음 |
| 국내 모델 입력 | 국내 Feature + `epa_surge_score` | 공통 특성 |
| 국내 모델 학습 행 | 국내만 | 국내 + EPA |
| EPA 가중치 | 해당 없음 | 적용(초기 0.2) |
| 지위 | **채택 후보** | **참고 실험** |
| 핵심 질문 | EPA가 매긴 급등 점수가 국내 예측에 도움이 되나 | EPA 행을 직접 섞으면 어떤가 |

### 쉽게 이해하기

- **B:** 국내 데이터만으로 학습한다.
- **B+E:** EPA를 공부한 별도 모델이 국내 행마다 "급등할 것 같은 정도"를 점수로 매기고, 국내 모델은 그 점수를 참고 자료 하나로 쓴다.
- **+S:** 실측에서 드문 상황을 합성으로 만들어 학습 사례에 조금 보탠다.
- **B+EP:** EPA 사례를 국내 사례와 한 교재에 섞어 공부한다(참고로만).

## 8. 공통 평가 방법

**Validation으로 고르고, Test로 한 번 보고한다.**

| 구분 | 지표 | 쓰임 |
|---|---|---|
| 채택 | Validation의 **행 단위 F1·재현율·오경보 건수** | 재현율 0.6 이상 중 F1이 높은 쪽. 오경보가 크게 늘면 고르지 않음. 차이 0.01 미만이면 단순한 쪽 |
| 보고 | PR-AUC, 사건 단위 Recall·Precision·F1, Lead Time(60분 전 / 30분 전 / 놓침), Persistence·Rule Engine만 쓴 경우 대비 | 결과표 |
| 보조 | FPR | 정상 행이 많아 작게 나오므로 보조로만 |
| 편중 | 배출구 단위 신뢰 구간, 항목별 사건 수 | 특정 배출구에 성능이 몰리는지 |

- Accuracy만으로 평가하지 않는다. 정상 행이 압도적으로 많아 거의 항상 높게 나온다.
- 모든 실험은 같은 구간(Train 10/30~11/12, Validation 11/13~11/17), 같은 라벨(`label-v1`), 같은 데이터 스냅샷, 같은 예측 대상을 쓴다.
- Test(11/23~12/4)는 승인 모델을 평가하는 데 쓰고, 나머지 실험은 12/7에 **비교 행으로만** 적는다. Test 결과를 보고 채택을 바꾸지 않는다.

## 10. 최종 정리 — 답해야 할 질문

| 실험 | 질문 |
|---|---|
| **B** | 국내 데이터만으로 60분 안 진입을 어느 정도 미리 잡는가? |
| **B+E** | EPA에서 배운 급등 점수가 국내 예측에 도움이 되는가? |
| **+S** | 합성 데이터를 조금 더하면 나아지는가? |
| B+EP(참고) | EPA 행을 직접 섞으면 어떤가? 정답의 뜻이 다른 문제는 얼마나 큰가? |

성능이 나빠졌거나 차이가 없었다면 그것도 결과다. 점수 분포, 두 원천의 특성 분포 차이, 사건이 일부 배출구에 몰린 정도 같은 **원인을 분석해 설명하는 것**이 중요한 학습 결과다.

**핵심은 EPA를 쓰는 방식에 따라 무엇이 달라지는지 직접 구현하고, 같은 국내 Validation으로 공정하게 고른 뒤, Test로 한 번 정직하게 보고하는 것이다.**
