# Hybrid Retrieval(하이브리드 검색) 이해 및 TMS 프로젝트 적용

## 1. Hybrid Retrieval이란?

**Hybrid Retrieval(하이브리드 검색)**은 서로 다른 검색 방식을 결합하여 검색 정확도와 검색 품질을 높이는 기술이다.

일반적으로 RAG(Retrieval-Augmented Generation)에서는 다음 두 가지 검색 방식을 결합한다.

- **Sparse Retrieval**: 키워드 기반 검색
- **Dense Retrieval**: 의미 기반 검색

두 검색 방식의 장점을 결합하면 정확한 키워드 검색과 문맥 및 의미 중심 검색을 동시에 수행할 수 있다.

## 2. Hybrid Retrieval의 구성

### 전체 처리 흐름

```text
[사용자 질문]
      |
      v
[Query Processing]
      |
      +--------------------------+
      |                          |
      v                          v
[Sparse Retrieval]       [Dense Retrieval]
      |                          |
      v                          v
[BM25 + Kiwi]            [Embedding + Vector DB]
      |                          |
      v                          v
[키워드 검색 결과]        [의미 기반 검색 결과]
      |                          |
      +------------+-------------+
                   |
                   v
             [Result Fusion]
                   |
                   v
              [RRF 적용]
                   |
                   v
              [Reranking]
                   |
                   v
             [최종 검색 결과]
                   |
                   v
              [LLM Answer]
                   |
                   v
                [답변]
```

### 2.1 Sparse Retrieval (희소 검색)

키워드가 문서에 얼마나 정확하게 포함되어 있는지를 기준으로 검색하는 방식이다.

대표 기술은 다음과 같다.

- **BM25**: 검색어와 문서 사이의 키워드 관련성을 계산하는 알고리즘
- **Kiwi**: 한국어 형태소 분석기로, 문장을 형태소 단위로 분석하여 검색 품질을 개선

주요 특징:
- 설비 코드, 측정 항목, 특정 용어 검색에 유리하다.
- 정확한 키워드가 포함된 문서를 찾는 데 효과적이다.
- 동의어나 유사한 표현으로 작성된 문서를 찾는 데는 한계가 있다.

### 2.2 Dense Retrieval (밀집 검색)

문장을 Embedding 모델을 이용해 벡터로 변환한 다음, 벡터 간 의미적 유사도를 기준으로 검색하는 방식이다.

대표 기술은 다음과 같다.

- **Embedding Model**: 텍스트를 벡터로 변환
- **Vector DB**: 변환된 벡터를 저장하고 유사도 검색 수행
- **Qdrant**: 대표적인 벡터 데이터베이스

주요 특징:
- 질문과 문서의 표현이 달라도 의미가 유사하면 검색할 수 있다.
- 동의어나 문맥이 다른 표현을 처리하는 데 유리하다.
- 정확한 설비 코드나 특정 수치 등의 검색에서는 키워드 검색보다 불리할 수 있다.

## 3. Sparse Retrieval과 Dense Retrieval 비교

| 구분 | Sparse Retrieval | Dense Retrieval |
|---|---|---|
| 검색 기준 | 키워드 일치 및 관련성 | 의미적 유사도 |
| 대표 기술 | BM25 | Embedding |
| 데이터 표현 | 희소 벡터 | 밀집 벡터 |
| 검색 특징 | 정확한 단어 중심 | 문맥과 의미 중심 |
| 장점 | 설비 코드, 고유 용어 검색에 유리 | 동의어 및 유사 문장 검색에 유리 |
| 단점 | 표현이 달라지면 검색 누락 가능 | 정확한 코드 및 수치 검색에 한계 |
| 활용 | 특정 설비 및 측정 항목 검색 | 유사 장애 사례 및 기술 문서 검색 |

## 4. Hybrid Retrieval의 핵심 기술

### 4.1 BM25

BM25(Best Matching 25)는 키워드 기반 검색 알고리즘이다.

검색어가 문서에 얼마나 자주 등장하는지, 다른 문서에 비해 얼마나 중요한 단어인지 등을 고려하여 검색 점수를 계산한다.

예를 들어 다음과 같은 검색을 수행한다.

```text
검색어: NOx 배출량 증가

검색 결과:
1. NOx 배출량 증가 원인 분석
2. NOx 측정 장비 점검 이력
3. 배출가스 관리 및 운영 기준
```

### 4.2 Embedding

Embedding은 텍스트를 숫자로 구성된 벡터로 변환하는 기술이다.

예를 들어 다음과 같은 문장은 서로 다른 단어를 사용하지만 의미적으로 유사하다.

```text
질문:
NOx 배출량이 증가한 원인은?

문서:
질소산화물 농도가 상승한 주요 원인은 연소 온도 증가이다.
```

Embedding을 사용하면 단어가 정확하게 일치하지 않더라도 의미적 유사성을 기반으로 관련 문서를 검색할 수 있다.

### 4.3 RRF (Reciprocal Rank Fusion)

RRF는 서로 다른 검색 방식에서 나온 결과를 하나의 순위로 통합하는 기법이다.

예를 들어 BM25와 Dense Retrieval이 각각 검색 결과를 반환하면 RRF가 두 결과의 순위를 종합하여 최종 검색 순위를 결정한다.

```text
BM25 검색 결과
1위: 문서 A
2위: 문서 B
3위: 문서 C

Dense 검색 결과
1위: 문서 B
2위: 문서 D
3위: 문서 A

          |
          v

       RRF 적용

최종 검색 결과
1위: 문서 B
2위: 문서 A
3위: 문서 D
4위: 문서 C
```

RRF는 일반적으로 다음 공식을 사용한다.

\[
RRF(d) = \sum_{r \in R}
\frac{1}{k + rank_r(d)}
\]

- `d`: 검색 대상 문서
- `R`: 검색 시스템별 검색 결과 집합
- `rank_r(d)`: 특정 검색 시스템에서 해당 문서의 순위
- `k`: 순위 점수의 영향을 조절하는 상수

RRF는 서로 다른 검색 시스템의 점수 체계가 달라도 순위를 기반으로 결과를 통합할 수 있다는 장점이 있다.

### 4.4 Reranker

Reranker는 1차 검색 결과를 질문과 문서 사이의 관련성을 기준으로 다시 평가하여 순위를 조정하는 기술이다.

일반적인 검색 흐름은 다음과 같다.

1. BM25와 Dense Retrieval로 후보 문서를 검색한다.
2. RRF로 검색 결과를 통합한다.
3. Reranker가 질문과 각 문서의 관련성을 재평가한다.
4. 관련성이 높은 문서를 최종 선택한다.
5. 선택된 문서를 LLM에 전달한다.

RRF가 여러 검색 결과의 순위를 통합하는 역할이라면, Reranker는 질문과 문서의 실제 관련성을 다시 평가하는 역할이다.

## 5. TMS 프로젝트 적용 방안

TMS 프로젝트에서는 운영 문서, 설비 매뉴얼, 장애 이력, 과거 이상 발생 사례 등을 검색하는 RAG 기능에 Hybrid Retrieval을 적용할 수 있다.

### 5.1 적용 대상

| 검색 대상 | 권장 검색 방식 | 적용 목적 |
|---|---|---|
| 설비 코드 검색 | BM25 | 정확한 설비 식별 |
| NOx, SO2 관련 기술 문서 | Hybrid Retrieval | 키워드 및 의미 기반 검색 |
| 장애 조치 이력 | Hybrid Retrieval | 유사 장애 및 조치 사례 검색 |
| 유사한 이상 발생 사례 | Dense Retrieval | 의미적으로 유사한 사례 검색 |
| 특정 설비의 장애 이력 | Hybrid Retrieval | 설비 정보와 장애 문맥을 함께 검색 |
| 운영 및 점검 매뉴얼 | Hybrid Retrieval | 자연어 질문 기반 문서 검색 |

### 5.2 TMS 적용 예시

**사용자 질문**

```text
지난달 A공장의 NOx 농도가 급격히 상승했던 사례와
당시 조치 방법을 알려줘.
```

**① Sparse Retrieval**

BM25와 Kiwi를 이용하여 다음 키워드를 중심으로 검색한다.

- A공장
- NOx
- 농도 상승
- 장애 조치

**② Dense Retrieval**

Embedding과 Vector DB를 이용하여 의미적으로 유사한 사례를 검색한다.

- 질소산화물 농도 급증
- 배출가스 이상 발생
- 연소 조건 변화
- 과거 유사 장애 사례

**③ Result Fusion**

RRF를 적용하여 BM25와 Dense Retrieval의 검색 결과를 통합한다.

**④ Reranking**

질문과 검색 문서의 관련성을 재평가하여 가장 적합한 문서를 선별한다.

**⑤ LLM Answer**

최종 검색 문서를 기반으로 LLM이 다음 내용을 생성한다.

- 과거 NOx 농도 상승 사례
- 이상 발생 시점
- 당시 측정 데이터
- 확인된 원인 및 조치 이력
- 유사 사례와 비교 분석

단, 실제 원인이 확인되지 않은 경우 LLM이 임의로 원인을 추정하지 않도록 해야 한다.

## 6. TMS Hybrid Retrieval 권장 아키텍처

```text
[사용자 질문]
       |
       v
[Query Processing]
       |
       +----------------------------+
       |                            |
       v                            v
[Sparse Retrieval]          [Dense Retrieval]
       |                            |
       v                            v
[Kiwi + BM25]               [Embedding Model]
       |                            |
       v                            v
[OpenSearch / BM25]         [Qdrant Vector DB]
       |                            |
       +-------------+--------------+
                     |
                     v
              [RRF Fusion]
                     |
                     v
                [Reranker]
                     |
                     v
              [Context Builder]
                     |
                     v
                 [LLM]
                     |
                     v
                [최종 답변]
```

### 권장 기술 스택

| 구분 | 기술 | 역할 |
|---|---|---|
| 한국어 형태소 분석 | Kiwi | 검색어 형태소 분석 |
| 키워드 검색 | BM25 | 정확한 키워드 검색 |
| 검색 엔진 | OpenSearch | 문서 및 키워드 검색 |
| 임베딩 | Embedding Model | 문장 벡터 변환 |
| 벡터 데이터베이스 | Qdrant | 벡터 저장 및 유사도 검색 |
| 검색 결과 통합 | RRF | 검색 결과 순위 통합 |
| 재순위화 | Reranker | 문서 관련성 재평가 |
| 답변 생성 | LLM | 검색 결과 기반 답변 생성 |
| RAG 오케스트레이션 | LangGraph | 검색 및 답변 생성 흐름 제어 |

※ OpenSearch는 BM25 검색 엔진으로 활용할 수 있으며, 별도의 검색 인프라를 최소화하려면 Qdrant의 Sparse Vector 기능을 활용하는 방안도 검토할 수 있다.

## 7. Hybrid Retrieval의 기대 효과

1. **검색 정확도 향상**: 키워드 검색과 의미 기반 검색의 장점을 결합한다.
2. **검색 누락 감소**: 표현이 다른 유사 문서도 검색할 수 있다.
3. **설비 정보 검색 강화**: 설비 코드, 측정 항목, 기술 용어를 정확하게 검색할 수 있다.
4. **유사 장애 사례 검색**: 과거 장애 이력과 현재 상황을 의미적으로 비교할 수 있다.
5. **RAG 답변 품질 향상**: 관련성이 높은 문서를 LLM에 제공하여 답변의 근거를 강화한다.

## 8. 핵심 정리

Hybrid Retrieval은 하나의 검색 방식에 의존하지 않고 여러 검색 방식을 결합하여 검색 품질을 높이는 전략이다.

| 기술 | 핵심 역할 |
|---|---|
| BM25 | 키워드 기반 검색 |
| Kiwi | 한국어 형태소 분석 |
| Embedding | 텍스트의 의미를 벡터로 표현 |
| Vector DB | 벡터 저장 및 유사도 검색 |
| RRF | 여러 검색 결과의 순위 통합 |
| Reranker | 검색 결과의 관련성 재평가 |

**TMS 프로젝트 적용 권장 조합**

`Kiwi + BM25 + Embedding + Qdrant + RRF + Reranker`

특히 운영 문서, 설비 매뉴얼, 장애 조치 이력, 과거 이상 발생 사례를 검색하는 RAG 기능에 적용하는 것을 권장한다.

핵심은 **정확한 키워드 검색과 문맥 중심 검색을 결합하여, TMS 운영자가 원하는 정보를 더 정확하게 찾을 수 있도록 만드는 것**이다.
